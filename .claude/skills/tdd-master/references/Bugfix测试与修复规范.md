# Bugfix 精简验收规范

Bugfix 仍使用同一份 `output/tests/TDD验收契约.md`，不恢复多层测试文档。

## 必须覆盖

1. **复现**：从 REPRO/CUR 形成一条能稳定观察原缺陷的验收。若适合自动化，先运行并确认 RED；环境错误不算复现。
2. **修复结果**：从 EXP 形成最小可观察验收，修复后必须 GREEN。
3. **关键不变行为**：每个 UNCH 至少映射一次，证明修复没有破坏原有核心行为。
4. **约束**：CON 中与数据、安全、兼容、性能或不可逆后果相关的约束必须进入 required。

CUR 可以和对应 REPRO 同行，EXP 可以和修复结果同行；不要为了 ID 一对一重复场景。一条回归旅程也可以覆盖多个 UNCH。

## 用例 ID

- `BUG-REPRO-01`：稳定复现。
- `BUG-FIX-01`：修复结果。
- `BUG-REG-01`：不变行为/回归。
- `BUG-RULE-01`：关键约束（确有需要才生成）。

## 执行纪律

- Bugfix 优先严格 RED→GREEN：先证明测试能抓到原缺陷，再修改实现。
- 不要求每条用例都删除/回退实现做四遍验证；只有怀疑测试假绿时才做针对性破坏验证。
- 每次修复后重跑相关测试、冒烟和受影响的核心旅程。
- 不得通过改弱期望、跳过测试或扩大无关功能来制造通过。
- 所有 required Bugfix 验收与回归通过后才能结束。
