# 提问收敛闸门（目标驱动 · 不按次数 · 不机械问清单）

## 唯一目标：问到你（AI）真心相信"这东西能解决他的问题"

提问的**唯一目的**，是让你对一件事建立**真实的信心**：**照现在掌握的信息做出来的东西，确实能解决用户的问题。**

- **信了 → 停。没信 → 继续问。就这一个标准。**
- 不为问而问（凑清单、凑轮数都不算数），也绝不没问清就草草开工。
- **没有轮数上限，也没有轮数下限**——简单需求可能两三轮就信了，复杂需求问到信为止。

## 这个"信"不是你自己拍的，是和人讨论出来的

你**不能**替用户默默假设答案、然后自我说服。每个影响"能不能解决问题"的关键判断，都要**摊开来和人讨论**：先讲你的判断和依据，让用户确认或推翻，由**用户拍板**。信心必须建立在**用户确认过的事实**上，不是你的猜测上。

## 开问前：先复述，对齐"到底要解决什么问题"

深挖前，先用你自己的话**复述一遍**你听到的业务目标（不照抄原文，讲你对"要解决什么、给谁、为什么值得做"的理解），用当前环境的结构化提问能力让用户确认"我理解对吗、要补充/纠正什么"。问题都没对齐，后面问得再多也白问。

## 提问中：整体考虑，针对性问，不逐条念清单

- **通读上下文、全局判断**："要让我相信这东西能解决他的问题，现在最缺、最不放心的是哪几块？"——针对这个**具体项目**的真实缺口去问。
- 各 skill 给的"必问清单"是**防漏检查器，不是问卷脚本**：用它自检"有没有漏掉某个会致命的维度"，但**问什么、先问什么、怎么问，由你结合上下文判断**。已经清楚的（PRD 写了 / 用户讲了）就别再问，一句复述确认即可。**绝不把清单从头到尾机械念一遍。**
- 每轮最多 1-2 个，问完等答复再问下一轮，不要问卷轰炸。
- 每个问题优先用当前环境的结构化提问能力（选择题 + 推荐项 + 理由），不可用时按主 Skill 的「运行环境适配」改用纯文本；**先讲判断再问**：每题前先说"我从 X 读到 / 判断 Y"，让用户在你的判断上确认或推翻。
- 用户对某题答"用推荐 / 你定"——是用户在**这一题上拍板**（有效作答），采用推荐项继续；不是跳过澄清。

## 什么时候停（闸门）

**当且仅当你能诚实地说出下面这句话时，才进入下一阶段：**

> "凭现在和用户确认过的信息，我相信照这个做出来的东西能解决他的问题；没有会让方案跑偏或返工的关键未知了。"

- 还说不出这句 → 说明还有关键缺口或没澄清的歧义 → **继续问**，并明说"我现在还不放心的是 X"。
- 把还没敲死的列进可见的"待确认事项"，不藏。

## 严格不停

没到"我相信能解决问题"这一步，**绝不**因为"问了好几轮 / 用户好像差不多了"就收尾，也绝不把没问清的塞进 _TBD_ / 假设一扔了事。
（边界：用户单题可以说"你定"来拍板**某一项**；但你**不主动**提供"剩下别问了、直接开始"这种全局跳过出口。）
