# 提示词 · 08 PPT HTML 开发师

> ## ⚠️ 执行方式（最高优先级 · 必须遵守）
>
> **本提示词为「单页」生成逻辑。优先每页调用一个子代理：**
>
> 1. 主代理先读取 `output/ppt.md` 获取总页数 N，并基于 PRD 生成一次共享视觉契约（统一的 `:root` 变量块 + 简短排版基调）
> 2. **按系统支持的最大并发数并发派发**（不要一次性派发全部 N 个——并发过多会超出系统上限失败）：维持满并发，每完成一个立即补派下一个，直到 N 页全部完成；第 i 个子代理收到「当前页码：i，总页数：N」和同一份共享视觉契约
> 3. 各页面之间无数据依赖，各子代理独立完成「读取 → 生成 → 自校验 → 保存」；并发额度不足时分批，没有子代理能力时由主代理逐页执行同一套自校验
> 4. N 个子代理全部完成后，主代理再做一次全局自校验（`:root` 外 hex / 导航链完整 / 全屏适配 `.stage`）
>
> **有可用子代理时不要无故串行，也不要一次性派发超过系统并发上限；能力降级不得省略页面或自校验。**

> **使用方法**：阶段 6.2 由 Controller 完整读取并派发，不要求用户复制粘贴。
>
> **前置依赖**：
> - `output/ppt.md` 已存在（由阶段 6.1 产出）
> - 主代理已生成共享视觉契约；PPT 不依赖 `DESIGN.md` 或 `tokens.css`
>
> **产出**：`output/ppt/p{i:02d}.html`（如 p01.html, p02.html，两位数页码）
>
> **⚠️ 使用前修改**：请把下面"执行指令"中的 `{i}`（当前页码）和 `{N}`（总页数）替换成具体数字。如：生成第 3 页，就改成 "当前页码：3，总页数：10"。PPT 每一页都要单独运行一次本提示词。

# 1. 最高铁律（必须全部遵守）

## 1.1 不改变任何事实与结论（零篡改）

* ❌ 不篡改数据
* ❌ 不引入新观点
* ❌ 不改变逻辑结论
* ✅ 允许且鼓励：删除冗余/重复/空洞表述、重组结构、提炼结论表达、重建视觉层级、润色语言、增强可读性与叙事张力
* ⚠️ 零篡改 = 不改变数据真值与结论方向，**不是不许删字**。ppt.md 里同一观点换说法重复、空话套话、与本页判断无关的内容，**必须删**，只保留核心判断 + 不可替代的证据  

## 1.2 PPT 是观点输出，不是文档堆砌

* 每一页必须有**明确结论句**（观众应当记住的一句话）

  * ❌ 功能介绍 / 市场分析 / 用户画像式堆叠

# 2. 审美与叙事标准（你的"判断系统"）

## 2.1 美 = 秩序感

* 信息必须被放在"它该在的位置"
* 留白不是空，而是为重点让路
* 每个元素都必须回答：

  > "它是在帮助理解，还是在制造噪音？"

* **密度靠结构不靠字数**：同信息量下，字越少设计感越强。用图表/数据/对比承载密度，不用文字堆砌。

## 2.2 美 = 克制

* 每页只允许**一个视觉重心**
* 渐变/阴影/发光/卡片是调味料：过量即失败
* 追求稳、准、狠，不追求炫技  

## 2.3 美 = 可读性第一

* 3 秒抓重点、远距离也能读懂
* 正文 **≥ 22px（硬下限）**
* 需要读两遍才懂的句子 = 设计失败  

## 2.4 你是导演，不是排版员

* 控制节奏（快/慢/停/炸点）
* 页面变化来自"语义差异"，不是装饰花活
* 千篇一律是原罪：不同信息 → 必须选择不同版式

# 3. 页面硬规格（截图范式）

## 3.1 尺寸与视口自适应（最高宪法）

**画布基准锁 1920px，但浏览器打开必须宽度铺满全屏**（通过 §3.3 的等比缩放实现，不能让 1920px 固定画布在窗口里溢出 / 横向滚动）：

* **画布宽度 X：锁定 1920px**（所有页面一致 → 保证各页宽度统一、视觉等宽）
* **画布高度 Y：`min-height: 1080px`** 作为基准；优先一屏讲清，仅在确属不可压缩的核心证据时向下延展
* ✅ **全屏铺满（强制）**：1920px 画布外层用标准适配方案按视口宽度等比缩放 —— 详见 §3.3，必须照做
* ❌ 严禁卡片内局部滚动条（`overflow-y: scroll` 是死罪）
* ❌ 严禁截断核心信息（禁止省略号糊掉主要信息）
* ❌ 严禁为了塞进一屏而缩小字号；优先一屏讲清，超长是**例外不是常态**。**每页可见正文 ≤ 300 字**（叙述文字，不含表格数据/图表标签），超出即注水信号，必须删到线内或转图表

## 3.2 静态高保真

* CSS 禁止 `transition / animation / hover`
* 你交付的是"最终截图态"，不是网页体验态 
* 例外：§3.3 的全屏适配脚本（resize 时改变 transform）是布局适配，不是视觉动效，允许；但**禁止给 `transform` 加 `transition`**（避免缩放时拖影）

## 3.3 视口自适应·全屏铺满（强制，每页必须照做）

浏览器打开必须**宽度铺满全屏**。1920px 绝对像素画布在多数浏览器窗口（CSS 宽 < 1920）里会溢出，必须用等比缩放解决。实现方式固定如下，**禁止自由改写**：

### 强制 HTML 骨架
```html
<body>
  <div class="stage">
    <!-- 原 1920px 的全部页面内容（含导航）都放这里 -->
  </div>
  <script>
    function fit() {
      var s = innerWidth / 1920;                 // 按视口宽度等比缩放
      var stage = document.querySelector('.stage');
      stage.style.transform = 'scale(' + s + ')';
      document.body.style.height = (stage.offsetHeight * s) + 'px';  // 修正滚动高度，避免留白 / 错位
    }
    addEventListener('resize', fit); fit();
  </script>
</body>
```

### 强制 CSS（粘贴到 `<style>`）
```css
html, body { margin: 0; padding: 0; }
.stage { width: 1920px; transform-origin: top left; }
```

### 规则
* `scale = innerWidth / 1920`：宽度永远铺满视口，字号 / 间距等比缩放；同一屏幕下各页缩放比例一致 → 视觉等宽。
* `transform-origin: top left`：从左上角缩放，对齐视口左边。
* 超长页：高度超出视口时，整页纵向滚动（已由 `body.height` 修正保证滚动条准确）；**禁止卡片内滚动**。
* 16:9 屏幕 scale 后刚好铺满；非 16:9 按宽度铺满、高度自适应。
* **导航栏禁止用 `position: fixed`**：`.stage` 有 `transform`，会使 `fixed` 的包含块变成 `.stage` 而非视口，导致导航定位错乱。用普通文档流或 `absolute` 定位。

### 截图注意
本页带 scale 适配。要原始 1920px 高清截图：截图工具应截 `.stage` 元素本体（截图前可临时移除 `transform`）；若截浏览器视口，得到的是按当前窗口缩放后的画面。

# 4. 字体与排版系统（1920px 基准字号体系）

你需要像设计杂志一样处理文字，行距与字距是质感来源。推荐字号体系如下（可微调但不可违反下限）：

* Slide Title（H1）：64–72px，line-height≈1.1
* Hero / Headline：36–48px
* Sub-header：30–36px
* Body：22–24px，line-height≈1.6（**严禁低于 22px**）
* Meta / Label：14–16px，全大写/宽字距，用于标注
  并且控制单行长度，避免过长导致阅读困难。

## 输出后自校验（每页生成后必须执行）

生成 HTML 并保存后，**立即**对自己刚写的文件执行以下检查：

1. **Grep 搜索 `:root {`**：确认 `<style>` 中包含共享视觉契约的 `:root {}` 块
2. **Grep 搜索 `#[0-9a-fA-F]{3,6}`**：检查硬编码 hex 颜色。hex 值只允许出现在 `:root {}` 块内部，组件 CSS 中出现任何 hex 值即为违规
3. **如果检查不通过**：自行修复（将硬编码颜色替换为 `var(--xxx)`），修复后重新保存，禁止交付不合规的 HTML
4. **Grep 搜索 `.stage` 与 `function fit`**：确认已按 §3.3 包入 `.stage` 容器并粘贴全屏适配脚本（`scale = innerWidth / 1920`）；导航未使用 `position: fixed`。缺失即违规，补齐后重新保存。
5. **反注水检查**（通读本页 HTML 文字）：
   - 同一观点是否有换说法重复？（有 = 注水，保留首次，删重复）
   - 是否有"赋能/闭环/矩阵/引擎/抓手/底座"等空话套话？（有 = 删或改具体表述）
   - 文字区域是否超过页面 50%？（超过 = 视觉空洞风险，补图表/数据/留白，不是补字）
   - 有任一项不通过：修复后重新保存，禁止交付注水页面。
6. **字数检查**：统计本页可见正文（叙述文字，不含表格数据/图表标签）。
   - 超过 300 字 = 注水，删到线内或转图表后重新保存。
   - 并自问：每句话能不能砍成一个词/一句话？能 = 砍。
