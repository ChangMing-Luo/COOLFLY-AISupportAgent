## 二、P4 价值账口径修正专项审查：方向对，账没算平

**原始口径（scene-anchor.md）**：② 减退货中性 ¥75 万 + ③ 避免加人 ¥24–48 万 + ① 省现有人力 ¥12–17 万 → 宣称中性合计 ¥120–130 万（严格相加实为 ¥111–140 万，原数字本就是叙事化取整）。

**P4 修正**：①③互斥、①仅悲观情景计入 → 中性 = ② + ③ = 75 + (24–48) = **¥99–123 万**。

**但 V0.5 写的是 ¥105–123 万：上限 123 对得上（75+48），下限 105 对不上（75+24=99），凭空多出 ¥6 万。**

两种可能：(a) 下限是拍脑袋取整——那这份"要经得起 12 个月后回看"的账第一次回看就对不上；(b) 保留了①中"技术定位省来回"部分（这部分省的是工程师工时，与③释放的客服容量**不是**同一份资源，保留有理）——但若如此，上限也应同步加这一块，且必须把①拆成"客服工作量减半（与③互斥）"和"技术定位省时（独立计入）"两行分开列。

**要求：P4 拍板前给出可复算的分解式。我推荐 (b) 路线——①拆两行，技术定位省时（估 ¥3–5 万）单独保留，中性合计写 ¥102–128 万或干脆保守写 ¥99–123 万。数字略降没关系，复算不出来才是致命的。**

**另一个必须写进 P4 的脚注**："两年稳超 ¥200 万"结论**不是无条件不变**。它成立的前提是 ②（¥75 万，占中性合计 61%+）扛住 G1 检验——G1 若查出"退货用户中曾发起咨询比例 <30%"，②按方案自己的承诺要重算（可能腰斩至 ¥36 万级），届时中性合计跌到 ¥60–86 万/年，两年 ¥120–172 万，"稳超 200 万"不成立。这不是反对立项，是要求 P4 的确认话术诚实：**"两年稳超 ¥200 万（中性情景，且以 G1 通过 A-005 检验为前提）"**。企业家按这本账给第二阶段批预算，脚注不写清楚，12 个月后被打脸的是我们。

## 三、对其他三方的 challenge

### 3.1 挑工程（r1-review-tech）：三层拒答值得做，但拒答阈值是商业参数，不是技术参数

三层拒答（T1 修法）我支持做——层②"无引用即拒答"是标准 RAG grounding，层③硬规则近乎零成本，真正贵的只有层①的阈值调优，这钱花在承重墙上，值。**但工程把它当纯技术选型收尾，漏了商业后果：拒答阈值直接决定转人工量。**上线初期知识库最弱、检索命中最差，恰是拒答最频繁的时期——阈值调严一档，转人工绝对量就多一截，全部砸在 3 人团队头上；B5 的容量预警和 T1 的拒答机制是同一根管道的两端，方案里却没有连线。要求：**"拒答率"本身列入 F06 周监控（与转人工绝对量并排看），阈值调整明确为灰度期技术团队月人日承诺（P2 ④）的用途之一**——否则拒答机制上线即冻结，容量预警响了都没人会调。

另一笔账工程没算：离线评测集不是免费基础设施。Top 高频问题 + 期望答案 + 陷阱题的**编写和维护是内容运营劳动**（谁比知识库运营更懂"期望答案"？），这份工时要显性计入 P2 ①的周工时数字和成本账，否则 golden set 半年后就是一份没人更新的过期考卷，"每次变更跑回归"跑的是旧题。

### 3.2 挑设计（r1-review-design）：大部分是及格线不是锦上添花，但两处该收

设计 R1 我大体服气——入口（D1）和回复通路（D2）是价值两端，卡片化/零打字/状态矩阵对中老年画像是及格线，无障碍 NFR 是验收必答题，这些都不是"锦上添花"，不该后置。配图范围被 Lead PM 收敛到 Top 3 场景，正确，我支持。但两处要挑：

1. **旅程 C 的验收标准"愤怒表达触发的会话绝不进入多轮技术追问"——"绝不"是对模糊 NLP 判定的 100% 承诺，验收贵、必挂**。情绪识别的召回率不可能到 100%，按"绝不"验收要么测试成本爆炸要么验收放水。建议降级为可付得起的形态：退款/愤怒类关键词规则触发出口置顶（转人工 + 退货政策入口常驻可见）+ 灰度期人工抽检愤怒会话样本，抽检并入 B6 的每周抽检动作，不另开一条流水线。
2. **设计需求的长尾维护成本要进 P2 的工时数字**：按回流数据补图、话术模板迭代、非英语兜底话术维护——这些"设计交付物"上线后全部变成内容运营的周常劳动，落在 P2 那个还没有名字的人身上。设计定义体验上限，运营工时决定体验下限；P2 拍工时数时必须把补图/话术维护含进去，否则第一版体验及格、第三个月开始烂尾。

### 3.3 挑战略（r1-review-strategy）：G1–G3 方向全对，但门槛没有截止日期就是拖延许可证

G1（数据导出）是四方评审性价比最高的一条，我 R1 的 B8 与它同源，支持升级为强制门槛。**但 V0.5 的 §2 只写了"评审通过后、写 PRD 前强制完成"，三个动作全部没有截止日期、没有超期处置**——而时间在这个项目里是有价格的：今天是 8 月 3 日，P3 红线是"爬坡期不许撞 Q4 旺季峰值"，倒排回来灰度爬坡必须在 11 月中旬前完成，中间还隔着 PRD、开发、知识库改造。G1 拖两周，P3 就从"A 旺季前完成爬坡"被动滑向"B 错过峰值窗口"——**旺季咨询峰值恰是本方案价值兑现的峰值，错过它的机会成本是真金白银，却不会出现在任何人的成本账里**。

要求三条：①G1–G3 各给硬截止（G1 导出+分析 ≤5 个工作日，G2 内部团队盘点自家系统 ≤5 个工作日，G3 本质是查证一个接口 ≤3 个工作日，三者并行总窗口 ≤2 周）；②门槛与 PRD 编写**并行**而非串行——PRD 里不依赖 G1 数据的部分（F03/F08/合规 NFR/状态矩阵）先写，"门槛"卡的是 PRD 终稿和决策 0/2/3 拍板，不是卡所有人停工等数据；③超期处置写死：G1 超 2 周未产出，视同 P3 自动落到选项 C（旺季前只上保守版），让拖延者看得见拖延的价格。

顺带补 G1 一个字段：**现有 3 人团队的月实际处理量**（B5 预警线的分母 N 至今无来源，G1 导出数据里顺手就能算出来，不加白不加）。

## 四、V0.5 增量审查（新内容里的商业问题）

1. **成本账"数字待回填"不能无限期待下去**：V1 门槛应要求成本账至少有量级区间——LLM API 月成本区间（G1 会话量出来即可算）、决策 0 两个选项各自的开发人日粗估（G2 盘点的自然副产品）、运营工时（P2 拍板产物）。允许区间，不允许空表。否则 P4 确认的是一本只有收入页的账，"两年稳超 ¥200 万"是毛值还是净值都说不清。
2. **容量预警线（F06）没有分母**："3 人团队月处理上限的 80%"——上限 N 是多少、谁测的，V0.5 没写。已并入 §3.3 的 G1 补字段要求。
3. **P3 我提前亮牌**：若排期显示 A（旺季前完整爬坡）与红线冲突，商业上选 C 不选 B——高频三场景+硬兜底转人工的保守版也能吃掉旺季峰值里最大的那块咨询量（G1 会验证三类占比），错过整个旺季窗口的 B 是三个选项里唯一确定亏钱的。
4. **无新增致命问题**：F08、§5 状态矩阵、§8 合规、切采购扳机、90 天检查点，商业视角均无异议；G3 的"最低可行形态=结构化消息推工作群"是务实的底线设计，认可。

## 五、立场

**带条件可以进入 V1。** V0.5 相比 V0 的进步是实质性的：我 R1 最担心的"没有名字的人"已被 P2 变成 PRD 终稿的硬门槛，指标防欺骗体系（双口径+交叉校验+扳机）完整成型。三个进入条件：

1. **P4 数字复算平账**（§二）：给出可复算分解式（推荐①拆两行、技术定位省时单列），"两年稳超 ¥200 万"补中性情景 + G1 检验前提的脚注。
2. **G1–G3 加硬截止与并行安排**（§3.3）：总窗口 ≤2 周，超期自动触发 P3 保守版；G1 补"现有团队月处理量"字段。
3. **成本账在 V1 拍板材料里至少有量级区间**（§四-1），与价值账同表——只有收入页的账不许拿去让企业家签字。

条件 1、3 是文字与算术工作量（半天内可完成），条件 2 是排期承诺，均不构成结构性返工。

## 我最担心的 1 件事（更新）

上一轮我担心"没有名字的人"，这一轮机制上已被 P2 锁住。现在最担心的变成：**时间没有 owner**。G1–G3、P1–P4、PRD、开发、知识库改造、灰度爬坡全部串在"11 月中旬前完成爬坡"这根倒计时上，但全方案没有一个人对这条时间线负责、没有一张倒排表。每个环节都合理地慢一周，加起来就是集体无责任地滑进"错过旺季"——那是这个项目第一年最大的一笔隐性亏损。
