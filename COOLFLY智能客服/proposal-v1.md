## 1. 解决思路（用户视角）

用户在 COOLFLY App 里遇到装不上、连不上、配不了对、会员疑问时，**不用在"迷宫 App"里找客服**——设备掉线、配对失败、扫码失败的错误提示旁边就有"Get help"，一键进入对话并自动带上故障现场。进来后**不用打字也能求助**：首屏就是高频问题按钮（Setup / Won't connect / Pairing failed / Membership），点按直接进入一步一屏的分步引导；也可以自由输入，AI 先判断你在问什么、还是在表达情绪——**该答的答准，该安抚的安抚，不把"我没把握"的模板话术甩给一个正在生气的人**。它答不准事实性问题时不硬撑：检索不到可靠依据就明说，主动给转人工；但它也不许"动不动就转人工"——连续两次没把握，直接给转人工大按钮，不消耗用户第三次耐心。转人工时自动带上会话摘要 + SN + 设备型号（用户可见、可补充），并按真实通路如实告知回复渠道与预计时间，**不做兑现不了的承诺**。

第一阶段的定位是诚实的：**体验补课到及格线（答得准 + 转得顺 + 找得到门 + 出得去门），同时为第二阶段攒数据与回流体系**。差异化王牌（AI + 设备诊断，全品类无人做到）留在第二阶段，本期不做，但接口争取从现在并行启动。

- 四项**并行**，总窗口 **≤2 周**；门槛与 PRD 编写并行——不依赖 G 数据的部分（F03/F08/合规 NFR/状态矩阵）先写，门槛卡的是 **PRD 终稿定稿与拍板 1/5**，不是全员停工。

- **G3 回退**：反向通路查不到接口，F03 目标态本期直接降级为底线态，不留"争取一下"的模糊区。
- **G4 回退**：映射链不存在，退货归因降级为"渠道原因码粗分类 + 月度趋势"，对应验收承诺同步降级。
- G1 数据同时用于：反向校验 F01–F06 优先级与 60% 目标、知识库改造清单排序（改造执行必须排在 G1 之后）、成本账的会话量/token 估算、拒答率预期区间校准。

## 5. 技术形态与状态约束（供 PRD/设计消化）

- **执行顺序（写死）**：用户消息 → **意图分类**（知识求解 / 情绪 / 闲聊 / 流程推进 / 追问澄清）→ 仅知识求解类进三层拒答：①检索相关度低于阈值 → "承认不会+转人工"；②**事实性解答消息**必须引用命中知识条目，无引用即拒答（追问/共情/流程话术显式豁免，豁免类别用评测集陷阱题防滥用）；③敏感/超范围硬规则拒答。验收区分拒答准确率与**引用忠实率**；反向指标：高频误拒率上限、单会话连续拒答 ≤2 次。
- **情绪路径**：退款/愤怒类关键词规则触发出口置顶（转人工+退货政策入口常驻可见，确定性逻辑、可硬验收）；怒气样本入评测集与灰度抽检（概率性识别不进硬验收）。
- **排障形态**：结构化流程（步骤+分支显式建模）+ LLM 意图识别/上下文衔接/话术生成；"无死胡同"图遍历自动验证。
- **两条上线线与灰度**：**引擎线**=服务端按用户分桶+远程开关，2 周 20%→50%→100% 承诺仅对此线有效；**放量前置条件=评测集命中率 ≥80% 且当前桶拒答率落在预期区间**（知识库没就绪就不放量，洪水关在小流量里）。**发版线**=F08 入口/按钮组/卡片 UI，灰度计划单列"发版节奏+版本覆盖率"；灰度对比结论区分"引擎效果"与"入口效果"。
- **知识库接入**：飞书导出+定期增量重建索引，变更生效 ≤24h；飞书 API 权限前置登记。
- **状态矩阵（任何故障态不出死屏）**：流式响应指示；响应超时（建议 8–10 秒，PRD 定数）重试提示；LLM 超时/限流/不可用 → 降级直达转人工+排障文章；手机离线本地提示。
- **埋点**：事件 schema（会话开始/结束、转人工、评分、解决标记、语言、**entry_source、app_version、channel（默认 app）**）与功能同步交付、同步验收。
- **演进约束（见 §10）**：引擎核心接口不假设 App 来源。
- **设计一致性与无障碍（NFR，🟩）**：沿用现有 App 设计规范、聊天遵循平台惯例；字体缩放不破版、关键按钮 ≥44pt、基础 VoiceOver 走查（不下放加分项）。
- **首屏路由**：高频按钮→对应 F02 引导流；**Membership 按钮=预置意图直达 F01 知识问答（跳过打字）**，会员类条目列入改造清单候选、G1 数据裁决；自由文本→意图分类→路由。

## 6. 核心用户旅程

**旅程 A · 自助解决（主路径，目标占高频类 60%）**
北美用户 Sarah 配对到一半卡住，配对失败页直接显示"Get help" → 点进去首屏就有"Pairing failed"按钮，不用打字 → 分步引导第一步问"你连的是 2.4GHz 还是 5GHz？"配路由器示意图 → Sarah 切出 App 去改路由器设置（超过 30 分钟也没关系）→ 回来自动恢复到当前步骤 → 点"Done"，配对成功 → AI 确认解决，弹出轻量评分 → 全程 8 分钟，零打字也零等待。

**旅程 B · 转人工兜底（不干等、不复述、知道去哪等）**
用户 Mike 扫码绑定失败，引导两轮自查仍失败 → AI 主动说"这个情况需要人工用你的设备序列号定位"，展示将发给客服的摘要，Mike 补充"绑定时 App 闪退过一次" → 确认转人工，界面按真实通路显示等待承诺（目标态："已转接，预计 X 小时内回复，可关闭页面，回复会通知你"；底线态："回复将通过邮件送达，通常 X 小时内，请留意收件箱"）→ 人工客服首条回复即引用摘要直奔问题 → Mike 全程零复述、零虚假期待。

**旅程 C · 情绪崩溃路径（退货率的直接来源）**
用户折腾 2 小时后打出"this thing is garbage, I want a refund" → 关键词规则命中，**不进拒答判定、不追问技术细节** → 先共情，出口置顶：转人工（优先接入）+ 退货政策入口 → 若用户愿意，再给"最后试一步"最短排障路径。验收点：愤怒/退款类关键词触发出口置顶为硬验收；怒气会话入灰度抽检。

## 7. 指标与验收口径

## 10. 演进约束（零成本，现在不写=两年后还债）

1. **引擎渠道无关化**：对话引擎核心接口不假设 App 来源；故障上下文等 App 专属信息作为可选结构化输入传入；未来邮箱/官网渠道接入只写渠道适配层、不重写引擎——决策 0 若选 A，这是"一个 agent 服务全渠道"从愿景变成架构的唯一机会窗口。
2. **埋点 channel 字段**：事件 schema 带 channel 字段（默认 app），省掉未来全渠道报表口径断代。
3. **转人工最小交接数据契约**：固定字段顺序（已试步骤/SN/型号/卡点+会话 ID），兼作未来 Zendesk 字段映射底稿。
4. **F07 两条约束**：文案与 prompt 模板不硬编码语言；知识条目带语言字段。
5. **排障流程 schema 与知识条目均渠道中立**。

## 13. 风险与缓解（方案级）

- **失败模式 1 · AI 编答案**：三层拒答 + 引用忠实率单列验收 + 四类陷阱题回归 + 点踩样本周度修复。
- **失败模式 2 · 拒答洪水（新升级）**：薄知识库+严拒答=爬坡期转人工不降反升，砸在 3 人团队最没经验的时期 → 意图分类豁免非事实性对话 + 误拒率/连续拒答上限 + **灰度放量与评测集命中率/拒答率区间联动** + 拒答率分层周监控 + 容量预警响应预案（业务侧，灰度前到位）。
- **失败模式 3 · 运营缺位机制空转**：拍板 2 不落地则回流/抽检/归因/度量全部按虚线画 → 拍板 2 列最高优先，给不出 owner+工时就缩范围（砍 F05 承诺、下调目标）。
- **失败模式 4 · 时间无 owner，集体滑过旺季**：每环节合理慢一周=错过第一年最大价值窗口 → G1–G4 硬窗口 ≤2 周 + 超期自动落保守版 C + 拍板 3 同步产出倒排表与时间线 owner。
- **失败模式 5 · 指标自我欺骗**：双口径 + 沉默放弃率 + 三指标交叉校验 + **解决率按入口分层**（错误态入口流量更难，混算会污染灰度结论）。
- **失败模式 6 · 客服不看摘要，零复述落空**：SOP 包 + 首条回复引用摘要入验收 + 周抽检（owner 待拍板 2）。
- **失败模式 7 · 承诺兑现不了**：三件套/看板/灰度对比若按目标态无条件承诺，G3/G4/发版现实会逐一打脸 → 全部改为查证分层承诺（G3 双栏、G4 回退、F08 发版线单列），底线态话术不说"回复会通知你"。

## 14. 待企业家拍板（5 项 · P1–P4 与原决策 1–3 合并去重）

### 拍板 1 ｜ 现有 AI 客服处置：重建服务端对话引擎，还是升级现有系统？（原 P1/决策 0）

- **背景**：现有自研 AI 客服缺的不只是知识库，拒答/排障/埋点同样不存在——但这是待 G2 验证的断言，不是证据。前置：G1 基线 + G2 盘点（含选项 B 能力对照表 + 三集成点可插拔判定）完成后拍。
- **选项**：A 重建服务端引擎（App 端复用入口）——拒答/排障/埋点从零建到位，且是"引擎渠道无关化"的架构窗口；代价=最大工程投入。B 升级现有系统+知识库工程——可能 1/3 成本拿 70% 价值；代价=受旧架构约束、上限未知。
- **推荐**：倾向 A，但 G2 对照表若显示旧系统三个集成点均"可插/需改造"，转 B 不丢人。**无论 A/B：F01–F08 用户可见完成标准为形态无关硬验收，选 B 后达不成的项逐条摆回桌面重拍，不许静默缩水。**
- **代价**：A=工程投入最大、若旧系统本可修补则是机会成本黑洞；B=及格线可能守不住（三件套/卡片化/状态矩阵落不了地时必须重新拍板）。

### 拍板 2 ｜ 运营与投入承诺实名化（原 P2 · **最高优先，其他机制真假的开关**）

- **背景**：回流、抽检、归因、度量全部依赖"有名字的人+工时数字"；四方评审一致认定这是全方案唯一不能拖的项。
- **待实名清单**：①知识库内容运营（前置改造人日 + 每周消化 Top10 + **评测集编写维护** + **补图/话术/非英语兜底维护**，给出周工时数）②退货归因月报 owner ③客服 SOP 培训与抽检 owner（建议企业家团队）④技术团队上线后 6 个月每月人日（**拒答阈值调优为第一用途**）。
- **选项**：现有人员兼任（零现金成本，风险=没人真干）vs 新增 0.5 人力（费用入成本账）。
- **推荐**：知识库运营岗必须有实名 owner + 周工时数字；给不出就砍 F05 回流承诺并下调目标——宁可缩范围，不要纸面机制。
- **代价**：兼任=机制空转风险由企业家自担；加人=真金白银入成本账。

### 拍板 3 ｜ 上线时间表、灰度节奏与 Q4 旺季策略（原 P3 + 原决策 1 合并）

- **背景**：红线=爬坡期不许撞旺季峰值；倒排回来灰度爬坡须在 11 月中旬前完成。灰度机制已定形：引擎线服务端分桶 2 周走完（放量前置条件=评测集 ≥80% 且拒答率在区间内）；F08 走发版线、覆盖率如实呈报；旧系统基线二选一（补最小埋点跑 2 周——前提 G2 确认可行，或承认 G1 估算口径）。
- **选项**：A 旺季前完成完整灰度爬坡（工期紧）；B 避开旺季 Q4 后灰度（错过峰值价值窗口，商业评审判定为三选项中唯一确定亏钱）；C 旺季前只上保守版（§4 已显式定义，不再是一行字）。
- **推荐**：待 G1 与开发排期后在 A/C 中选（不推荐 B）；**G1 超 2 周未产出自动落 C**。
- **随本项同步确认**：倒排表 + **时间线 owner**（每周核对进度、有权拉响延期警报）+ 灰度值守分工（谁看数据/谁抽检/每周几小时）。
- **代价**：A=知识库改造时间被压缩，质量风险；C=部分体验项（错误态入口覆盖、加分项）延后兑现。

### 拍板 4 ｜ 价值账口径修正 + 成本账同表确认（原 P4 + 商业条件合并）

- **背景**：价值块①与③来源为同一份释放容量，涉嫌重复计算；V0.5 的 ¥105–123 万下限复算不出（75+24=99）。
- **修正后的可复算分解式**：
  - 中性合计 = ②减退货 ¥75 万 + ③避免加人 ¥24–48 万 = **¥99–123 万/年**；
  - ①拆两行：①a 客服工作量减半（¥9–13 万，与③互斥、仅销量不涨的悲观情景计入）；①b 技术定位省来回（约 ¥3–5 万，工程师工时、独立资源，保守起见不并入中性合计，列为未入账弹性，与店铺评分拉动并列）；
  - **脚注（必须随结论出现）**："两年稳超 ¥200 万"为中性情景，**且以 G1 通过 A-005 检验（退货用户曾咨询比例 ≥30%）为前提**；触发回炉线则②重算、此结论同步重述。
- **同表确认**：成本账量级区间（§9）与价值账并排——批的是净值概念，不是只有收入页的账。
- **推荐**：接受修正。数字略降没关系，复算不出来才致命；这本账要经得起 12 个月后回看。
- **代价**：对外叙事数字从"120–130 万"降为"99–123 万"。

### 拍板 5 ｜ 知识库改造顺序 + 转人工通路层级（原决策 2 + 决策 3 合并 · 低争议确认项）

- **背景**：两项均已有明确建议与查证前置，属"按门槛结果执行"的授权确认。
- **知识库改造（原决策 2）**：三大高频场景条目上线前改造、其余走回流补齐；清单排序在 G1 之后（会员/账号类占比意外高则清单跟着改）；完成标准=schema 校验+评测集命中率 ≥80%。
- **转人工通路（原决策 3）**：沿用现有渠道（不提前接 Zendesk）；层级按 G3 双栏查证结果定——反向通路可行则目标态（写回会话流+push），否则底线态（结构化消息推工作群/邮件模板+如实告知），三件套话术随层级对齐；G3 须回答"底线态离及格线多远"，若差距过大再复评提前接 Zendesk 的成本对比。
- **推荐**：两项均按建议授权执行，G1/G3 结果出来后无需再上会（触发回炉线除外）。
- **代价**：底线态用户体验弱于目标态（回复不在同一会话流）——这是查证结果决定的现实，不是方案选择。
