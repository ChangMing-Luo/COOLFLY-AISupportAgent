## 2. 页面概述

### 2.1 一句话定位

让自助未解决的用户一键把问题交给人工客服：系统自动生成交接摘要（用户完整可见、可补充），提交后如实告知"回复从哪来、大概多久、超时找谁"——到了人工那里不用从头复述（US-F03-01 / US-F03-02）。

### 2.2 存在理由

1. 无此面板则用户转人工后必须向客服从头复述已试步骤、SN、型号——这是差评原话里的核心痛点，AC-M-07 要求客服侧零复述。
2. 无摘要预览则系统"替用户说了什么"不透明；契约要求摘要对用户完整可见、可补充（AC-M-06），透明是信任基础。
3. 无等待承诺分层则用户"对着聊天窗干等一个不会来的回复"；底线态必须如实告知渠道与时限、禁止虚假通知承诺（AC-I-05）。

### 2.3 页面目标（可衡量）

| 目标维度 | 具体指标 |
| :--- | :--- |
| 零复述 | 客服收到摘要固定字段 + 用户补充 + 会话 ID + 会话记录摘要文本 + 情绪标记，无需向用户再要一遍（AC-M-07） |
| 提交唯一性 | 重复点击确认只产生一次转接，客服侧不收到重复单（REQ-F03-01） |
| 可用性优先 | 摘要生成失败 / SN 缺失 / 多设备均不阻塞转接（AC-E-09 / AC-E-10）；任何故障态不出死屏（PRD §7 原则） |
| 承诺可信 | 预计响应时间为滚动实际值或分档，界面 0 处硬编码固定时长；底线态话术 0 处"回复会通知你"（AC-I-05） |
| 首响不劣化 | 转人工首响不劣于上线前人工渠道水平（基线 [PRD 定数 · G1 后回填]，AC-I-03；测量口径随 G3 分层） |

### 2.4 不做什么（范围边界）

- **不做**任何转人工前置门槛（"必须先走完 N 步排障才许转"）——AC-I-01 明令不硬拦截，硬拦截压转人工率属 PRD §0.3 不做边界。
- **不做**任何 "priority" 类优先处理表述——情绪会话标记为纯内部字段，客服 SOP 实际支持优先处理前，界面与话术不得出现（PRD §12.3 / R2-裁决 7）。
- **不做**硬编码预计响应时长——一律取滚动实际值或分档（REQ-F03-02）；冷启动兜底也只用分档措辞。
- **不做**底线态"是否解决"提问——底线态转接确认只触达服务体验类反馈（AC-M-12，元素归对话页 F04），此刻问题未被解决，问了必得系统性负样本。
- **不做**客服侧工作台界面——客服接收侧无本产品界面（D-3 本期不做客服侧工具）；Zendesk 映射属阶段2+（PAGE-F03-02，planned）。
- **不做**多字段表单——仅 Add details 单字段（蓝图 §5），无草稿保存 / 离开拦截，内容随摘要即时提交。

## 3. 用户与场景

### 3.1 目标用户

| 维度 | 描述 |
| :--- | :--- |
| 角色 | COOLFLY App 用户（自助未解决 / 主动要人工的求助者） |
| 人数 | 单次使用 1 人 |
| 技术熟练度 | 偏低至中等（含中老年用户，高对比可读性优先，蓝图 §6） |
| 使用设备 | 手机竖屏（375–430pt 宽基准） |
| 使用姿势 | 手持，多处于设备故障 / 弱网现场，情绪可能已挫败 |

### 3.2 核心使用场景

**场景 A：排障未解决转人工（主场景）**
- 时机：排障流某步点了 "It didn't work" 走到分支终点，或拒答第 2 次出现转人工大按钮
- 前置：会话中已积累已试步骤、SN、型号等上下文
- 动作：点转人工触点 → 抽屉升起，看到系统整理好的摘要 4 字段 → 补充一句细节 → 点 Send & connect → 看到等待承诺 → 回到会话等待
- 情绪：从"又要从头讲一遍"的预期挫败，转为"它替我说清楚了"的松一口气

**场景 B：情绪路径转人工（高敏场景）**
- 时机：用户表达强挫败 / 退款诉求，情绪出口置顶卡出现
- 前置：会话命中情绪路径，交接契约将自动携带内部情绪标记（用户不可见）
- 动作：点置顶卡 Talk to a human → 摘要可见 → 直接 Send & connect（可不补充）
- 情绪：烦躁、不想多打字——流程必须短、零追问、零推销

**场景 C：提交失败后重试（兜底场景）**
- 时机：弱网 / 渠道故障导致转接提交失败
- 前置：已点 Send & connect 但提交未成功
- 动作：看到显式失败提示 → 点 Retry；连续失败「建议值 2 次 · 终稿前确认」后看到兜底客服邮箱，摘要保留在面板可复制
- 情绪：不焦虑——请求没有被静默丢弃，永远有下一步出路

### 3.3 用户核心诉求（优先级排序）

1. **零复述**：系统自动带上已试步骤 / SN / 型号，不用我重讲
2. **透明**：发出去之前让我看到并能改
3. **知道去哪等**：回复从哪个渠道来、大概多久、超时找谁
4. **不被拦**：任何状态下想转就能转，不设排障门槛
5. **不被骗**：不许诺做不到的通知和时限

## 4. 信息架构

### 4.1 区域划分

底部抽屉（全屏级模态，自下而上）：

1. 抽屉标题区
2. 摘要预览卡区
3. Add details 补充输入区
4. 操作按钮区（主 + 次）
5. 提交反馈区（失败提示 / 兜底联系方式，仅异常时出现）

提交成功后抽屉收起，等待承诺等后续消息落回对话页会话流（本页定义其内容与触发，展示载体为 PAGE-F01-01 会话流）。

### 4.2 区域内容

**1. 抽屉标题区**
- 摘要卡标题（"Here's what we'll send to our team"）

**2. 摘要预览卡区**
- 固定字段顺序展示（§12.3 契约，不重排）：已试步骤 / SN / 型号 / 卡点，对用户完整可见
- SN / 型号缺失时对应字段显空并提示可手动补充；多设备时提供涉事设备选择
- 摘要生成失败时本区降级（见 §7.1 降级态）

**3. Add details 补充输入区**
- 编辑入口 `Add details`；单字段文本输入 + 字符计数（上限「建议值 500 字符 · 终稿前确认」）
- 补充内容追加进摘要卡点字段，用户可见

**4. 操作按钮区**
- 主按钮 `Send & connect`（提交转接）
- 次级按钮 `Not now`（返回原会话，不转接）

**5. 提交反馈区（异常时）**
- 提交失败提示 + `Retry` 按钮
- 连续失败后的兜底联系方式（客服邮箱）+ 摘要保留可复制说明

## 5. 界面内容

> 全部用户可见文案引用 PRD §5.4 文案定稿（唯一落点），英文文案逐字照抄、禁止改写。

### 5.1 元素清单

**摘要卡标题**
- 文案："Here's what we'll send to our team"
- 显示条件：抽屉调起即显示

**转人工摘要预览卡**
- 内容：固定字段顺序 = 已试步骤（来自 F02 进度或会话内容提炼）/ SN（缺失时留空并标注）/ 设备型号 / 卡点（当前问题一句话描述 + 用户补充内容）
- 数据来源：系统自动生成（F02 排障进度 / 会话内容 / 宿主注入的 SN·型号）
- 显示条件：触发转人工时自动生成并对用户完整可见；随附发送的会话 ID 不需要用户理解但不隐瞒其随摘要发送；情绪会话标记为纯内部字段，不在本卡展示
- 操作后：可补充后确认；无禁用条件

**涉事设备选择**（仅多设备时）
- 内容：用户已绑定设备列表，选择涉事设备填入 SN / 型号
- 显示条件：账号绑定多台设备；不选择不阻塞转接

**Add details 输入区**
- 类型：单字段文本输入
- 占位文案："Anything else we should know?"
- 辅助信息：字符计数，上限「建议值 500 字符 · 终稿前确认」
- 默认态：空；操作后：补充内容追加进摘要，用户可见

**Send & connect 按钮**
- 文案：`Send & connect`
- 默认态：可用；提交中置灰防重复提交
- 操作后：提交转接 → 按 G3 层级显示等待承诺（分目标态 / 底线态）

**Not now 按钮**
- 文案：`Not now`
- 操作后：返回原会话，不转接；无禁用条件

**等待承诺消息 · 目标态（G3 反向通路查证可行时启用，系统消息，落回会话流）**
- ①："You're connected to our support team. Expected reply: {rolling_estimate}."（{rolling_estimate}=近期实际首响滚动值或分档展示，如 "usually within 2 hours — replies may take longer right now"；禁止硬编码固定时长）
- ②："You can close this page — we'll notify you here when they reply."（发送前完成场景化通知权限请求）

**push 权限请求（目标态，系统弹窗）**
- 显示条件：转接确认时机场景化触发，仅在未授权时；已授权 / 底线态不触发
- 拒绝后明示文案："Notifications are off, so please check back here for your reply."（不重复弹权限）

**超时安抚消息 · 目标态 ③（系统消息，落回会话流）**
- 文案："Sorry for the wait — our team is still on your case. If it's urgent, reach us at {support_email}."
- 显示条件：超过承诺时间 × 缓冲系数「建议值 1.5 倍 · 终稿前确认」未有人工回复时自动下发（触发定义与 AC-E-07 一致）；是状态说明不是新承诺

**等待承诺消息 · 底线态（G3 反向通路不可行时启用，系统消息，落回会话流；话术禁止出现"回复会通知你"）**
- ①："Your request and the summary below have been sent to our support team."
- ②："They'll reply by email ({user_email}) — {rolling_estimate}. Please keep an eye on your inbox (and spam folder)."
- ②-fallback（账号无可见邮箱：Apple 隐私转发 / 未绑定邮箱时）："They'll reply by email — please make sure the email address on your COOLFLY account is up to date."
- ③："If you don't hear back within {promised_window}, contact us directly at {support_email}."

**转接提交失败提示**
- 文案："We couldn't send your request just now. Please try again." + 按钮 `Retry`
- 显示条件：提交失败（网络 / 渠道故障）

**转接连续失败兜底**
- 文案："Still not going through — sorry about that. You can reach our team directly at {support_email}; your summary above is saved here so you can copy it."
- 显示条件：连续失败「建议值 2 次 · 终稿前确认」后

**转接后继续输入提示（「已转接等待」态，展示于对话页会话流，本页定义触发）**
- 目标态："You're connected with our support team — your message has been added to this conversation for them to see."
- 底线态："This conversation has been handed to our support team — they'll reply through the channel above. Need help with something else in the meantime?" + 按钮 `Continue with the AI assistant`（点击开启新自助会话，原转接与人工处理不受影响）

### 5.2 辅助信息

- 底线态转接确认后，对话页触达服务体验类轻量反馈（"How was your experience with our assistant so far?"，不问"是否解决"）——触发源为本面板的转接确认，元素与验收归 PAGE-F01-01 / F04（AC-M-12）。
- 本面板无页脚 / 版本号等附加信息；无帮助文案入口（Source IDs 未要求）。

## 6. 交互流程

### 6.1 页面加载与初始化

- 用户在对话页点任一转人工触点（五类）→ 底部抽屉升起。
- 系统自动生成交接摘要并完整展示：已试步骤（F02 进度或会话内容）、SN、型号、卡点；会话 ID 与情绪会话标记（内部）随契约准备，不在界面渲染情绪标记。
- SN / 型号缺失 → 对应字段显空 + 提示可手动补充；多设备 → 出涉事设备选择。
- 摘要自动生成失败 → 不阻塞：降级为"会话记录直达客服" + 用户手填卡点描述（见 §7.1）。

### 6.2 核心操作流程

```
用户点转人工触点（拒答链接 / 大按钮 / 情绪置顶卡 / 排障终点 / 会话菜单）
    │
    ▼
抽屉升起：摘要 4 字段完整可见（缺失字段显空可补；多设备先选涉事设备）
    │
    ├─ 点 Not now ──→ 抽屉收起，返回原会话，不转接
    │
    ├─ （可选）Add details 补充 ≤500 字符，追加进摘要
    │
    └─ 点 Send & connect ──→ 按钮置灰（防重复）
         │
         ├─ 提交失败 → 显式失败提示 + Retry
         │     └─ 连续失败达建议值 2 次 → 兜底客服邮箱 + 摘要保留可复制（不出死屏）
         │
         └─ 提交成功 → 会话进入「已转接等待」态，抽屉收起，按 G3 层级出等待承诺：
              │
              ├─ 目标态：①已转接 + 滚动预计响应 ②可关闭页面、回复会通知
              │     ├─ push 未授权 → 场景化请求一次；拒绝 → 明示"回来查看"，不再弹
              │     ├─ 客服首条回复（须引用摘要）写回同一会话流 + push
              │     └─ 超承诺时间 ×1.5（建议值）未回复 → 自动下发安抚消息 ③
              │
              └─ 底线态：①已发送 ②邮件渠道 + 滚动时限（无邮箱走 fallback 文案）
                    ③超时联系方式；话术全程禁"回复会通知你"
                    └─ 转接确认时触达服务体验反馈（AC-M-12，归对话页）
```

### 6.3 辅助操作

- `Not now` 为唯一取消路径，随时可用，返回原会话且不产生转接。
- 转人工在任何会话状态下可达（AC-I-01），本面板不设任何前置完成条件。

## 7. 状态与边界

### 7.1 页面状态全景

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 初始态（摘要就绪） | 触发转人工、摘要生成成功 | 摘要 4 字段完整可见，Add details 空，Send & connect 可用 |
| 字段缺失态 | SN / 型号缺失（未绑定设备） | 对应字段显空 + 提示可手动补充，不阻塞转接 |
| 多设备选择态 | 账号绑定多台设备 | 出涉事设备选择；选择后填入 SN / 型号 |
| 摘要降级态 | 摘要自动生成失败 | 不阻塞转人工：提示会话记录将直达客服 + 用户手填卡点描述输入 |
| 输入态 | 用户在 Add details 输入 | 实时字符计数，上限 500 字符（建议值） |
| 提交态 | 点 Send & connect | 按钮置灰不可重复点击，只产生一次转接 |
| 成功态 · 目标态 | 提交成功且 G3 反向通路可行 | 抽屉收起；会话流出现等待承诺①②；未授权时场景化请求 push 权限 |
| 成功态 · 底线态 | 提交成功且反向通路不可行 | 抽屉收起；会话流出现底线态①②③三件套（禁"回复会通知你"；无邮箱走 fallback） |
| 失败态 | 提交失败（网络 / 渠道故障） | 显式失败提示 + Retry，摘要与补充内容保留 |
| 兜底态 | 连续失败达建议值 2 次 | 展示兜底客服邮箱，摘要保留可复制，不出死屏 |
| 已转接等待态（回会话页后） | 转接确认后；目标态持续至人工会话关闭，底线态持续至等待窗口「建议值 24h」结束 | 用户继续输入不静默丢弃：目标态入同一会话流待客服查看 + 提示；底线态提示 + `Continue with the AI assistant` 按钮；该态豁免 30 分钟静默判定 |

### 7.2 边界与容错

| 边界场景 | 处理策略 |
| :--- | :--- |
| SN / 型号缺失或多设备 | 显空可手补 / 让用户选涉事设备；缺失与多选均不阻塞转接（AC-E-10） |
| 摘要自动生成失败 | 降级为"会话记录直达客服"+ 手填卡点；转人工可用性优先于摘要完整性（AC-E-09） |
| 提交失败（网络 / 渠道故障） | 显式失败提示 + Retry；不静默丢弃请求（AC-E-08） |
| 连续提交失败 | 达「建议值 2 次 · 终稿前确认」后展示兜底客服邮箱，摘要保留可复制，不出死屏 |
| 重复点击 Send & connect | 提交中置灰，只产生一次转接，客服侧不收到重复单（REQ-F03-01） |
| 滚动首响值不可得（冷启动 / 数据不足） | 分档兜底展示（"usually within a few hours"），仍禁止硬编码具体小时数 |
| 账号无可见邮箱（Apple 隐私转发 / 未绑定） | 底线态 ② 使用 fallback 文案，不展示空邮箱变量 |
| push 权限被拒（目标态） | 界面明示 "Notifications are off, so please check back here for your reply."，不重复弹权限（AC-S-07） |
| 目标态超承诺时间未回复 | 超过承诺时间 ×「建议值 1.5 倍」自动下发安抚消息（状态说明非新承诺，AC-E-07） |
| 已转接等待中用户继续输入 | 两态均不静默丢弃：目标态入同一会话流 + 目标态提示；底线态出提示 + 继续自助按钮，点按开新会话、原转接不受影响（AC-F03-11 关联，状态归对话页承载） |
| 超长补充输入 | 达 500 字符（建议值）上限即计数提示并截止输入，不发起超限提交 |

## 8. 业务规则与校验

### 8.1 字段定义

| 字段 | 说明 |
| :--- | :--- |
| 已试步骤 | 契约字段 1；来自 F02 排障进度或会话内容提炼 |
| SN | 契约字段 2；设备序列号，缺失时留空并标注，可手动补充 |
| 设备型号 | 契约字段 3；多设备时取用户所选涉事设备 |
| 卡点 | 契约字段 4；当前问题一句话描述 + 用户 Add details 补充内容 |
| 会话 ID | 契约字段 5；随附会话记录摘要文本供客服回溯（默认载体，R5-T3；可点开会话链接为 G3 查证项，查证通过才启用）；用户可见部分为字段 1–4，会话 ID 不需要用户理解但不隐瞒其随摘要发送 |
| 情绪会话标记 | 契约字段 6；内部字段，会话是否命中情绪路径（关键词规则或分类器任一触发即置位）；不向用户展示、不产生任何用户可见优先处理承诺 |
| Add details 补充 | 用户输入，上限「建议值 500 字符 · 终稿前确认」，追加进摘要（卡点字段） |

### 8.2 校验规则

| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 补充字符上限 | 输入时 | ≤500 字符（建议值），实时计数 | 达上限截止输入，计数提示 |
| 摘要字段完整性 | 提交时 | SN / 型号可为空——缺失不阻塞转接 | 无拦截；字段显空并标注 |
| 重复提交 | 提交中 | 置灰禁用，仅一次转接 | 无（按钮不可点） |
| 提交送达 | 服务端 | 写入人工客服通路（G3 正向） | "We couldn't send your request just now. Please try again." + `Retry` |

### 8.3 特殊业务规则

- **契约字段顺序固定**：已试步骤 / SN / 型号 / 卡点 / 会话 ID / 情绪标记，用户可见摘要与客服侧接收一致、不重排（兼未来 Zendesk 映射底稿，§3.7-3 / §12.3）。
- **零复述交付**：确认转接后客服侧可见摘要固定字段 + 用户补充 + 会话 ID + 会话记录摘要文本 + 情绪标记；客服首条回复须引用摘要（SOP 运营侧验收，PRD §9.12）。
- **承诺分层随 G3**：目标态 / 底线态两套话术互斥启用；底线态话术禁止出现"回复会通知你"（Round 3 裁决 9）；预计响应时间一律滚动实际值（「建议值 近 7 天首响中位数 · 终稿前确认」）或分档，禁止硬编码。
- **push 权限只弹一次**：场景化时机（转接确认时）、仅未授权时触发；拒绝后不重复弹。
- **禁 "priority" 表述**：情绪标记不产生任何用户可见优先处理承诺（R2-裁决 7）。
- **底线态只问体验**：转接确认时仅触达服务体验类反馈，不出现"是否解决"（AC-M-12，R2-裁决 2）。

## 9. 页面流转

### 9.1 流转图

```
客服对话页（PAGE-F01-01）
 五类触点：拒答链接 / 第2次拒答大按钮 / 情绪置顶卡 / 排障终点 / 会话菜单
        │
        ▼
 转人工确认面板（本页 · 底部抽屉）
        │
   ├── Not now ────────────→ 返回原会话（不转接）
   │
   └── Send & connect
          │
     提交失败 ←→ Retry（连续失败→兜底邮箱，留在面板）
          │
       提交成功
          │
          ▼
 客服对话页 · 「已转接等待」态
   ├─ 目标态：等待承诺①② → (push 请求) → 客服回复写回会话流 + push
   │          → 人工会话关闭 → 「已结束」态（→ 会话评分卡，归 F04）
   └─ 底线态：三件套①②③ + 服务体验反馈（AC-M-12）
              → 等待窗口(建议值24h)结束 → 「已结束」态，其后再输入=新会话
```

### 9.2 与其他模块的关系

- **F02 引导式排障**：摘要"已试步骤"字段取自排障进度；排障分支终点是本面板触点之一。
- **F04 会话反馈**：底线态转接确认触发服务体验反馈（不问"是否解决"）；目标态在人工会话关闭后才触达会话评分卡——均展示于对话页，本面板只是触发源。
- **F06 效果度量**：转接提交产生转人工事件、目标态"客服首条回复送达"事件（§4.2 埋点），进看板转人工率与首响测量；本面板不展示任何度量数据。
- **F05 回流**：转人工会话是回流四触发源之一（数据管道行为，无本页界面）。
- **客服人工侧**：仅数据交接（契约 6 字段），无本产品界面；隔离——本期不做任何客服侧工具（D-3）。

- 不需要工单历史 / 历史转接记录——每次转接以当前会话为限。
- 不提交任何未脱敏的会话原文进分析库（脱敏规则归 §4.5；本面板提交物为交接通路数据，回溯载体受权限控制）。
