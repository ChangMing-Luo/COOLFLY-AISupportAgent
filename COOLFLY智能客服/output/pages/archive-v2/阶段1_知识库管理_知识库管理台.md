## 2. 页面概述

### 2.1 一句话定位

知识库内容运营在此完成知识条目的录入（人工 + AI）、统一审核与发布，并查看数据看板——管理台是知识库的**唯一权威源**（飞书 120+ 篇一次性导入后不做双向同步）；**人工与 AI 录入统一流入审核队列**，未经审核并通过发布门禁的内容，永远不会进入知识库总页面、不会出现在 App 用户的回答里（US-F09-01/02/03/04，AC-M-15/18）。

### 2.2 存在理由

1. 无管理台则飞书 120+ 篇存量文档无法结构化为可检索条目，F01 命中率目标（§8）失去内容供给侧支撑；条目的录入、修订、审核、发布无统一落点，口径分叉（这正是拍板"不做双向同步"要防的问题）。
2. 无统一审核队列则「无人审不生效」铁律（AC-M-15/18，第三轮拍板从"仅 AI 草稿"扩展为**全部新条目/修订**）无执行载体：F05 回流闭环断在"消化"环节，人工录入也失去过审通道，周消化 Top 10 SLA（§5.6）无法落地。
3. 无发布门禁界面则评测集回归（§4.3 F09 条目发布门禁 🟩）的结果无处留痕呈现，"回归失败但条目已上线"的中间态无法被排除（AC-E-14）。
4. 无书目录式章节树（AC-M-17）则条目规模化后（120+ 起步）扁平列表不可导航，运营无法按知识体系维护归属与查缺。

### 2.3 页面目标（可衡量）

| 目标维度 | 具体指标 |
| :--- | :--- |
| 统一过审铁律 | 人工录入、批量导入、AI 录入的未审核条目 100% 只出现在审核队列，不进知识库总页面、不进检索库、不被 F01 命中（AC-M-15/AC-M-18） |
| 发布门禁 | 每次转入「已上线」100% 触发评测集回归且结果留痕；回归失败条目 0 生效（AC-E-14） |
| 发布时效 | 回归通过后条目生效（可被检索命中）≤24h（AC-M-13，§4.4 既有承诺） |
| 章节树可导航 | 条目按大章节→小章节两级层级组织，树可折叠、条目挂小章节下、章节可维护（AC-M-17） |
| AI 降级不阻塞 | AI 建议/起草服务不可用时，人工录入/编辑/审核/发布 100% 照常可用（AC-E-13，§5.10 异常） |
| 留痕完整 | 每次修订与状态流转均有留痕（修订人/时间/变更摘要），历史版本可查（§5.10 交互逻辑 1） |
| 访问安全 | 无口令访问 100% 被拦截（建议值 Basic Auth·终稿前确认）；操作留痕审计（蓝图 §3） |

### 2.4 不做什么（范围边界）

- **不做**与飞书的双向同步——管理台是唯一权威源，飞书仅一次性迁移来源（08-04-2026 拍板，防口径分叉）；迁移完成后飞书侧变更不回流。
- **不做**任何绕过审核的发布通道——第三轮拍板统一过审：**不存在"人工直接编辑发布入库"路径**，人工录入/批量导入/AI 录入一律进审核队列（AC-M-15/18）；界面上不提供绕过操作。原「待整理」队列已并入审核队列，不再单独存在。
- **不做**标签管理一级导航区——第三轮拍板：AI 问题标签建议在录入与审核流程内确认（建议卡照旧），知识库总页面筛选保留标签维度；标签能力不删，仅导航归属调整（DEC-011 废止）。
- **不做**多级权限/角色管理界面——内部工具面不做多级权限（蓝图 §3，阶段二随 Zendesk/多角色再议）；访问控制仅建议值口令（Basic Auth）+ 链接不公开。
- **不做**与 F06 业务看板重复建设——同一聚合数据两处呈现：管理台「数据看板 · 客服工作数据看板」内嵌呈现 F06 同源内容（口径同 §8，图卡构成同 §5.7），PAGE-F06-01 独立看板页保留供业务负责人直达（§5.7 双处呈现拍板）；知识库数据子看板只看条目供给侧效果，零新增埋点（§4.2）。
- **不做**条目内容语言的强制限定——条目内容语言由录入时语言字段选择决定（第三轮拍板修订，替代二轮「条目内容保持英文」表述）；生产环境服务英文用户的条目为英文，界面与示例全中文。
- **不做**多渠道客诉采集（应用商店评分/客服邮件）——阶段二范围（PAGE-F05-01 planned），本期 AI 录入输入仅 F05 四触发源回流会话。
- **不做**移动端适配承诺——桌面 1280+（与看板同体系）。

## 3. 用户与场景

### 3.1 目标用户

| 维度 | 描述 |
| :--- | :--- |
| 角色 | **知识库内容运营**（直接角色·内部工具，拍板 2 名单，现有人员兼任 2 名，§2.1 08-04-2026 增补）；**业务负责人**（管理台使用者之一，查看数据看板与审核动态） |
| 人数 | 单次使用 1 人；全量使用者固定小圈子（内部链接不公开） |
| 技术熟练度 | 中高（日常使用飞书文档与内部系统；非工程师，编辑器操作须直观） |
| 使用设备 | 桌面电脑 / 笔记本（1280+ 宽浏览器） |
| 使用姿势 | 初期集中审核存量导入内容；此后每日看 AI 录入批次 + 周度例行消化审核队列 Top 10 + 按需录入修订 + 维护章节树 |
| 数据边界 | 管理台全量知识条目、章节树与审核队列；来源会话仅脱敏后摘要/链接（§4.5 PII 规则）；无 App 用户明细数据 |

### 3.2 核心使用场景

**场景 A：周度审核消化（主场景，F05 消化工作面 + 统一过审）**
- 时机：每周例行（周消化 Top 10 SLA，§5.6），或看到待审数量增长时
- 前置：AI 每日批次抓取已起草草稿进审核队列（AC-M-14）；同事的人工录入/批量导入条目也在队列中（来源标注区分）
- 动作：口令进入 → 打开审核队列（AI 草稿按频次降序、人工/导入按提交时间降序，可按来源筛选）→ 逐条打开：查看正文、问题标签建议、来源会话链接/脱敏摘要、频次 → 三操作择一：「通过发布」（触发发布门禁回归，通过后条目转入知识库总页面对应章节）/「驳回」（必填原因）/「改后发布」→ 处理完 Top 10
- 情绪：例行、求准——最在意"草稿质量如何、来源频次是否真实、发布后会不会答错"

**场景 B：存量迁移（初始批量场景）**
- 时机：管理台上线初期，飞书 120+ 篇存量文档一次性迁移
- 前置：飞书文档已导出为可导入文件（或走批量导入入口直接迁移）
- 动作：进入「人工录入」→ 批量导入（飞书迁移/Markdown/CSV）→ 导入内容全部进**审核队列**（来源标注「批量导入」）、逐条看到导入结果 → 在审核队列逐条打开：参考 AI 切条/标签/场景/章节归类建议（逐项采纳/修改/拒绝）→ 通过发布后条目落入总页面对应章节
- 情绪：任务量大但有 AI 辅助——在意"进度可见、失败条目别静默丢、建议别替我做主"

**场景 C：每日看 AI 录入批次（新场景，第三轮拍板）**
- 时机：每日（AI 抓取节奏「建议值 每日 · 终稿前确认」）
- 前置：系统按日抓取 F05 四触发源回流会话，聚类总结生成草稿
- 动作：进入「AI 录入」→ 查看当日批次（抓取时间/来源会话数/生成草稿数/状态）→ 点批次查看该批草稿 → 跳转审核队列处理（草稿本体在审核队列）
- 情绪：例行巡查——在意"今天抓了多少、失败/空批次要如实标注，别静默缺批次"

**场景 D：维护章节树（新场景，AC-M-17）**
- 时机：审核通过条目落章节时发现归属不合理，或知识体系扩展时
- 前置：知识库总页面章节树已有两级结构（大章节→小章节→条目）
- 动作：进入「知识库总页面」→ 展开/折叠章节树定位 → 「新建章节」「重命名」「调整层级」（移动小章节或条目归属）→ 变更即时反映在章节树、操作留痕
- 情绪：像整理一本书的目录——在意"移动别丢条目、含条目的章节别被误删"

**场景 E：AI 不可用时的人工兜底（兜底场景，§5.10 异常）**
- 时机：LLM 故障，AI 整理/起草服务不可用
- 前置：建议卡隐藏并明示"AI 建议暂不可用"；AI 录入当日批次标注失败
- 动作：照常手工录入 → 人工填写标签与归类 → 提交进审核队列 → 照常审核、发布（发布门禁回归照常执行）
- 情绪：可接受——AI 是增强不是依赖，我的工作不被卡住

**场景 F：发布回归失败处理（兜底场景，AC-E-14）**
- 时机：发布（含改后发布）触发评测集回归，回归失败
- 前置：条目未生效、状态回炉（回草稿）
- 动作：在发布门禁结果面板看到失败原因与失败用例 → 修订条目 → 重新发布 → 回归通过后生效
- 情绪：不慌——失败原因可见、有明确的修复路径，不存在"不知道为什么没上线"

### 3.3 用户核心诉求（优先级排序）

1. **不出错**：未审核的绝不生效（人工与 AI 一视同仁）、回归不过的绝不上线——出错的代价是 App 用户拿到错误答案
2. **可追溯**：谁改的、什么时候改的、为什么驳回、回归结果如何、章节怎么动的，全部留痕可查
3. **效率**：AI 建议帮我少打字、频次排序帮我抓重点、批量导入帮我搬存量、章节树帮我快速定位
4. **可控**：AI 只是建议态，采纳/修改/拒绝由我定；AI 挂了我照常干活

### 4.1 区域划分

左侧固定导航 + 右侧内容区（design-derived: DEC-010——五区构成为 PRD §5.10 明定（08-04-2026 第三轮拍板），左侧导航 + 右侧内容的布局分区为设计补充）：

3. 内容区 · 数据看板（双子板 tab：知识库数据看板 / 客服工作数据看板）

- 产品标识 +「知识库管理台」标题

**2. 左侧导航区（五区，§5.10 文案定稿）**

- 知识库总页面（默认落点；含条目计数）
- 人工录入
- AI 录入（含当日批次草稿计数）

**3. 数据看板（①区，双子板 tab，§5.10 交互逻辑 7）**

  - 关键图卡内嵌呈现（图卡构成/口径/异常处理见 §5.7 与 §8，本页引用不复制；周粒度、只读、可切分层维度同 §5.7）

- 两子板均与 F06 同源埋点聚合（§4.2 既有事件，零新增埋点）；F06 看会话与业务结果，知识库数据子看板看条目供给侧效果，呈报视角区隔

**4. 知识库总页面（②区，书目录式章节树，AC-M-17/18）**
- 章节树：大章节 → 小章节 → 条目两级章节层级，可折叠展开，条目挂小章节下；点小章节展开条目、点条目进入详情/编辑器
- 章节管理：「新建章节」「重命名」「调整层级」（移动小章节或条目归属）；变更即时反映、操作留痕；**含条目的章节不可直接删除**（§5.10 异常）
- 搜索与组合筛选：全库搜索跨章节 + 场景/型号/语言/状态/问题标签筛选（结果标注所属章节）
- 条目列表（章节内）：按所属章节组织，章节内按更新时间降序
- 条目详情与编辑：问答型/排障流程型双编辑器（与③人工录入共用同一编辑器组件；编辑既有条目在本区打开，修订须重新过审）+ 状态流转控件 + 修订历史时间线 + 发布门禁结果面板（跨区复用）
- **仅审核通过的条目出现在本区**（AC-M-18）

**5. 人工录入（③区，统一过审）**
- 手工录入表单：问答型/排障流程型双编辑器（字段对齐 §4.1 schema，含「所属章节」）
- AI 整理建议卡：①切条建议 ②问题标签建议 ③场景与型号归类建议 ④**所属章节归类建议**（第三轮增补第 4 项）——全部建议态，逐项采纳/修改/拒绝；拒绝不阻塞提交进审核队列（AC-E-13 修订语义）
- 批量导入：Markdown / CSV 文件上传（飞书一次性迁移走同一入口；单文件上限「建议值 500 条 · 终稿前确认」）；导入结果逐条报告
- 提交出口唯一：**提交进审核队列**（来源标注「人工录入」/「批量导入」）或存为个人草稿；**不存在直接发布入库路径**（AC-M-18）
- 提交确认提示：「已提交审核队列：审核通过后条目才会进入知识库并生效。」（§5.10 文案定稿）

**6. AI 录入（④区，每日抓取批次，第三轮拍板）**
- 抓取批次列表：每批次展示抓取时间 / 来源会话数 / 生成草稿数 / 批次状态，按时间降序，当日与近期批次可见
- 批次摘要文案：「{日期} 批次：抓取 {n} 个会话，生成 {m} 条草稿待审核。」（§5.10 文案定稿）
- 点批次查看该批生成的草稿（草稿本体在审核队列，跳转⑤区处理）
- 失败/空批次如实标注「失败」「无新草稿」，不静默缺批次（§5.10 异常）

**7. 审核队列（⑤区，人工 + AI 统一流入，F05 消化工作面，§5.6 引用本区）**
- 队列列表：**来源标注**「人工录入」「批量导入」「AI 录入」（§5.10 文案定稿），可按来源筛选；AI 提炼草稿按频次降序、人工与导入条目按提交时间降序；待审数量可见
- 单条审核视图：草稿全文 + 问题标签建议 + 来源会话链接/脱敏摘要 + 频次（AI 录入条目）+ 三操作按钮（通过发布 / 驳回 / 改后发布）+ 驳回原因输入（必填）
- 通过并过发布门禁 → 条目转入知识库总页面对应章节（AC-M-18）
- 发布门禁结果面板：评测集回归结果 + 留痕记录；失败展示失败原因与失败用例（AC-E-14）
- 周清单导出按钮（常驻；导出任意周区间待补清单，字段同 §4.4，周度导出保留）

- 问答型：表单（标题/所属章节/场景/型号/语言/正文/问题标签，字段对齐 §4.1 schema——含第三轮增补的「所属章节」）

## 6. 交互流程

### 6.1 页面加载与初始化

- 访问内部链接 → 口令校验（建议值 Basic Auth · 终稿前确认，与 F06 看板同机制）→ 未通过 100% 拦截，无内容泄露
- 通过 → 默认落知识库总页面（章节树 + 条目列表）；顶部显示待审数量
- **空库初始态**（design-derived: DEC-012——上游未定义空库形态）：知识库总页面为空（飞书迁移尚未执行）时，展示引导——说明管理台为唯一权威源，引导先执行批量导入（飞书一次性迁移入口，导入进审核队列），不展示空章节树裸奔

### 6.2 核心操作流程

**流程一：人工录入/导入 → 审核队列 → 发布门禁 → 知识库总页面（AC-M-13/18 闭环主链，统一过审）**

```
③人工录入：手工录入表单（双编辑器）/ 批量导入（飞书迁移·Markdown·CSV）
    │
    ├─ AI 可用 → 建议卡自动生成（切条/标签/场景型号/所属章节归类，建议态）
    │      └─ 运营逐项「采纳」/「修改」（按修改内容生效）/「拒绝」（不生效，且不阻塞提交，AC-E-13）
    ├─ AI 不可用 → 建议卡隐藏+明示，人工照常填写（不受阻）
    ├─ 导入部分失败 → 成功条目照常进审核队列，失败条目逐条报告行号+原因（不整批静默失败）
    │
    ▼
⑤审核队列（来源标注「人工录入」/「批量导入」；未审核期间：不进总页面、不进检索库、不被 F01 命中，AC-M-15/18 铁律）
    │
    ├─ 「通过发布」→ 触发发布门禁：评测集回归（§4.3，结果留痕）
    ├─ 「驳回」→ 必填驳回原因 → 条目不生效
    └─ 「改后发布」→ 编辑器修改 → 触发发布门禁
    │
    ├─ 回归失败 → 条目不生效、回炉（回草稿）；面板展示失败原因+失败用例（AC-E-14）→ 修订后重发
    └─ 回归通过 → 条目转入②知识库总页面对应章节、索引更新（≤24h）→ F01 可检索命中、来源标注一致（AC-M-13）
```

**流程二：AI 录入每日批次 → 审核队列（AC-M-14/15，F05 消化工作面）**

```
F05 回流四触发源会话累积（§4.4）
    │
    ▼
系统按「建议值 每日 · 终稿前确认」节奏抓取会话 → AI 聚类总结起草条目草稿
（含正文+问题标签建议+来源会话链接/脱敏摘要+频次）
    │
    ├─ ④AI 录入：批次列表展示（抓取时间/来源会话数/生成草稿数/状态）
    │      └─ 失败/空批次如实标注「失败」「无新草稿」；失败批次次日照常抓取
    │
    ▼
⑤审核队列（来源标注「AI 录入」，按频次降序）——与人工录入统一流入同一队列
    │
    └─ 三操作与发布门禁同流程一；无人审不生效（AC-M-15 铁律）
```

**流程三：章节树维护（AC-M-17，§5.10 交互逻辑 1）**

```
②知识库总页面：章节树（大章节 → 小章节 → 条目，可折叠展开）
    │
    ├─ 「新建章节」→ 新章节即时出现在树中，留痕
    ├─ 「重命名」→ 即时反映，留痕
    ├─ 「调整层级」→ 移动小章节/条目归属 → 树即时更新，留痕
    └─ 删除章节 → 含条目/子章节的章节拦截：须先移空才可删除（防孤儿条目）
```

**流程四：条目状态流转（§5.10 交互逻辑 1/5）**

```
草稿 ──(过审核+发布门禁)──▶ 已上线 ──▶ 待改造 / 已下线
每次流转留痕（操作人/时间/变更摘要）；未过审核/回归的条目不可流转为已上线（控件禁用）；
修订已上线条目 → 修订须重新过审（统一过审）
```

### 6.3 辅助操作

- 修订历史：条目详情内打开时间线，可查看任一历史版本（只读）

### 7.2 边界与容错

| 边界场景 | 处理策略 |
| :--- | :--- |
| 并发编辑同一条目 | 后提交者收到冲突提示（文案见 7.1），须基于最新版本重做；不静默覆盖，修订历史可回溯（§5.10 异常场景） |
| 批量导入超单文件上限 | 上限「建议值 500 条 · 终稿前确认」；超限显式拒绝并提示拆分，不截断静默导入 |
| 问题标签超上限 | 「建议值 每条目 ≤20 个 · 终稿前确认」；超限时拦截并提示，不静默丢弃标签 |
| 章节层级越界 | 章节层级固定两级（大章节 → 小章节，§5.10 边界数值）；不提供更深层级创建入口 |
| 飞书一次性迁移失败 | 走 §9.2 兜底：人工从飞书导出文件经批量导入入库（进审核队列，来源标注「批量导入」）；迁移失败不阻塞管理台其余能力（§5.10 异常场景） |
| 网络异常/提交失败 | 显式失败提示可重试；编辑中内容不因提交失败丢失；不出死屏 |
| AI 起草草稿质量差 | 运营用「驳回」（必填原因供起草复盘）或「改后发布」兜底；AI 输出永远不绕过人工审核（AC-M-15） |
| 审核队列洪水期（拒答激增） | 频次降序保持 Top 优先可操作（§5.6 触发量激增同理）；激增本身由 F06 拒答率预警承接，不在本页处理 |
| 24h 生效窗口内用户复问 | 得到旧答案属预期行为，不计缺陷（§5.6 异常场景）；管理台内条目状态已如实为「已上线」 |

## 8. 业务规则与校验

### 8.1 字段定义（对齐 PRD §4.1 概念 schema，不新增字段）

| 字段 | 说明 |
| :--- | :--- |
| 条目标识 | 唯一、稳定，系统生成；供回答引用与回流清单关联 |
| 标题/问题描述 | 用户语言的问题表述（内容运营填写） |
| 场景分类 | 安装/联网/配对/会员/其他（与 G1 咨询分布口径对齐，G1 后可调） |
| **所属章节** | 大章节/小章节两级归属（书目录式层级，章节树导航用，§4.1 第三轮增补）；层级归属可调整（条目/小章节可移动）；章节由运营在总页面内维护 |
| 适用设备型号 | 可多值；空 = 全型号通用 |
| 语言字段 | F07 约束，字段必须存在（缺失可被校验发现，AC-C-06）；**条目语言在录入时选择**（第三轮修订，不再限定恒英文；服务 App 英文用户的生产条目为英文） |
| 正文内容 | 事实性解答内容，F01 第②层引用对象 |
| 来源与版本 | 初始导入来源标识（飞书一次性迁移）+ 更新时间，支撑 ≤24h 生效追踪 |
| 问题标签 | 多值（用户问法变体）；AI 建议 + 人工确认后生效；确认后作为 F01 检索信号（扩充召回+过滤） |
| 审核信息 | 草稿来源（人工录入/批量导入/会话提炼）+ 审核人/审核时间；未审核条目不进检索库 |
| 状态 | 草稿/已上线/待改造/已下线（枚举文案见 §5.10 定稿） |
| 排障型附加：步骤节点/分支/终止节点 | 每步仅两出口（完成→下一节点；没有解决→分支节点）；默认禁止环，确需回指的环上必须有转人工出口；终止节点只允许确认解决/转人工两类（§4.1） |

### 8.2 校验规则

| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 排障流程完整性 | 排障型保存时 | 无死胡同图遍历校验（§3.6：每节点可达终止节点，终止节点仅两类，环上须有转人工出口） | 不允许发布，编辑器内标出问题节点 |
| 发布门禁 | 条目转入「已上线」（含改后发布）时 | §4.3 评测集回归必须通过 | 回归失败提示（§5.10 定稿文案）+ 条目回炉 + 失败用例可见 |
| 统一过审 | 任何新条目/修订提交时 | 一律进审核队列，人工审核通过后才可发布（AC-M-15/18） | 提交确认提示（§5.10 定稿文案）；无绕过路径 |
| 驳回原因必填 | 审核「驳回」提交时 | 原因非空 | 占位提示「填写驳回原因（必填），供起草复盘」，空值不提交 |
| 导入文件校验 | 批量导入时 | 格式可解析、字段完整、单文件 ≤ 建议值 500 条 | 部分失败逐条报告行号+原因；整体不可解析显式拒绝 |
| 问题标签上限 | 编辑/确认标签时 | 每条目 ≤ 建议值 20 个 | 超限拦截提示 |
| 章节删除校验 | 删除章节时 | 章节内无条目且无子章节 | 拦截并提示先移空（防孤儿条目） |
| 并发版本校验 | 条目提交时 | 基于最新版本提交 | 冲突提示（§5.10 定稿文案），不静默覆盖 |
| 语言字段存在性 | 条目保存时 | 语言字段必须存在（录入时选择） | 缺失可被校验发现（AC-C-06），拦截保存 |

### 8.3 特殊业务规则

- **无人审不生效（铁律，第三轮扩展）**：未经审核的条目（**人工录入、批量导入、AI 录入一视同仁**）不进知识库总页面、不进检索库、不被 F01 命中、不出现在任何回答引用中；只有审核通过并过发布门禁的条目进入总页面与检索库（AC-M-15/AC-M-18，08-03-2026 拍板确立、08-04-2026 第三轮从"仅 AI 草稿"扩展为全部新条目/修订）。界面上不存在任何绕过路径。
- **唯一权威源**：条目的录入、修订、审核、发布全部在管理台完成；不做与飞书的双向同步（08-04-2026 拍板，防口径分叉）。
- **AI 建议态非门槛**：AI 切条/标签/场景型号/所属章节归类建议须人工采纳/修改/拒绝后方生效；**拒绝不阻塞提交进审核队列**（AC-E-13，第三轮语义修订：原"不阻塞人工直接编辑发布"随统一过审改为本表述；条目后续仍须经审核队列过审后入库）。
- **章节树规则**：章节层级固定两级（大章节→小章节）；小章节与条目归属可调整（移动）；含条目的章节不可直接删除；章节由运营维护、变更留痕（AC-M-17）。
- **全程留痕**：每次修订、状态流转与章节操作记录操作人/时间/变更摘要；回归结果留痕可追溯；操作审计留痕（蓝图 §3/§9：时间/操作者/动作）。
- **生效时限**：回归通过后发布生效、索引更新 ≤24h（§4.4 既有承诺不变）。
- **检索联动不改指标**：人工确认后的问题标签作为 F01 检索信号；命中率仍以评测集验收，§8 目标值不变、不新增指标（§5.10 交互逻辑 6）。
- **界面语言 100% 简体中文（第三轮扩展至示例内容）**：全部界面元素与界面示例内容简体中文（品牌词 "COOLFLY" 允许保留；语言字段徽章可展示「EN/中文」枚举）；条目内容语言由语言字段决定；管理台 UI 多语言切换为后续增强（复用 F07「文案不硬编码语言」约束，第一版仅中文资源）。
- **数据看板口径引用不复制**：知识库数据子看板四卡与条目效果列表全部指标口径唯一落点 §8.2「知识条目效果」行；客服工作数据子看板图卡构成/口径归 §5.7/§8——本页均逐项引用不复制定义；数据粒度=周；标黄线=「建议值 60% · 终稿前确认」、条目准确率样本量下限=「建议值 引用 10 次 · 终稿前确认」；全部只读、零新增埋点，与 F06 同源聚合、双处呈现不重复建设（§5.7/§5.10 交互逻辑 7）。

### 10.3 明确排除的数据

- 不需要 App 用户明细/未脱敏会话原文——来源会话仅脱敏摘要/链接（§4.5 PII 规则）
- 不需要埋点原始事件明细——数据看板仅消费聚合结果（知识库数据子板口径 §8.2「知识条目效果」行；客服工作数据子板口径 §5.7/§8）；同源聚合、双处呈现，不重复建设
- 不需要飞书侧实时数据——一次性迁移后不做双向同步
- 不需要 App 界面专属字段——两类 schema 渠道中立（§4.1/§3.7 第 5 条）

## 11. 验收标准

> Source AC 对照：F-01/F-02 ↔ AC-M-13；F-03 ↔ AC-M-14；F-04 ↔ AC-M-15（第三轮扩展至统一过审）；F-05 ↔ AC-E-13（第三轮语义修订）；F-06 ↔ AC-E-14；F-13 ↔ AC-M-16（改组归入数据看板）；F-14 ↔ AC-E-15；F-15 ↔ AC-M-17（章节树，第三轮增补）；F-16 ↔ AC-M-18（人工录入未审不入总页面，第三轮增补）；其余为 §5.10 元素表/交互/异常/文案定稿与蓝图审计约束的落验条目。

### 11.1 功能验收

| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| F-01 | 录入→审核→发布→检索闭环（AC-M-13） | 新建（或改后发布）条目，审核通过且发布门禁回归通过后：状态变「已上线」、转入知识库总页面对应章节、回归结果留痕可查；≤24h 内 App 用户就该条目覆盖问题提问可被检索命中并作为引用来源，来源标注与该条目一致 |
| F-02 | 发布门禁强制触发（AC-M-13/AC-E-14） | 任何条目转入「已上线」（含改后发布）100% 触发评测集回归；不存在"回归失败/回归中但条目已上线"的中间态 |
| F-03 | AI 录入草稿呈现（AC-M-14） | 回流触发源会话累积、每日批次抓取后：④区批次可见（抓取时间/来源会话数/生成草稿数/状态），⑤区队列出现 AI 聚类起草草稿（来源标注「AI 录入」），每条含来源会话链接（或脱敏摘要）、聚合频次与问题标签建议，按频次降序排列 |
| F-04 | 无人审不生效铁律（AC-M-15，统一过审） | 存在未审核条目（含人工录入与批量导入）时，App 用户提出该条目覆盖的问题：未审核条目不被检索命中、不出现在任何回答引用中；只有审核通过并过发布门禁的条目进入检索库 |
| F-05 | AI 建议逐项裁决（AC-E-13，第三轮语义修订） | 对切条/标签/场景型号/所属章节归类建议逐项操作：修改后按运营修改内容生效；拒绝后该建议不生效，且**不阻塞人工提交进审核队列**（AI 建议为建议态、非门槛；条目后续仍须经审核队列过审后入库） |
| F-06 | 回归失败回炉（AC-E-14） | 发布时回归失败：条目不生效（不进检索库、状态回炉），管理台内可见回归失败原因与失败用例；修订后可重新发布 |
| F-07 | 批量导入进审核队列 | 导入（飞书迁移/Markdown/CSV）内容 100% 进审核队列（来源标注「批量导入」），不直接上线；部分失败时成功条目照常入队、失败条目逐条报告行号与原因 |
| F-08 | 修订与流转留痕 | 每次修订与状态流转记录修订人/时间/变更摘要；任一历史版本可查；状态流转控件对未过审核/回归条目禁用「已上线」；修订已上线条目须重新过审 |
| F-09 | 排障型无死胡同校验 | 排障流程型保存时执行图遍历校验；死胡同/非法环时不允许发布且编辑器内标出问题节点 |
| F-10 | 组合筛选与搜索（层级下保留） | 总页面支持全库搜索跨章节 + 场景/型号/语言/状态/问题标签组合筛选，即时过滤，结果标注所属章节 |
| F-11 | 周清单导出保留 | ⑤区可导出任意周区间待补清单，字段=原始问题/命中文档/会话链接/频次，按频次降序；可补导历史周区间 |
| F-12 | 驳回原因必填 | 「驳回」操作原因为空时不可提交；占位文案与 §5.10 定稿一致 |
| F-13 | 数据看板·知识库数据子板（AC-M-16，第三轮改组归入①区） | 打开①数据看板·知识库数据看板子板：四卡可见——场景覆盖（已上线条目场景分布+覆盖场景数）/使用频率（检索命中周趋势）/引用采纳（实际引用进回答周趋势，**与命中分列——命中未被采纳可见**）/知识库准确率（整体+趋势）；条目效果列表逐条目可见命中数/引用数/点踩数/「试了没用」数/条目准确率，可按准确率升序排列（最差条目浮顶）；全部指标口径与 §8.2「知识条目效果」行一致；同一导航区内另可见客服工作数据看板（F06 同源，§5.7/§5.10） |
| F-14 | 样本不足不显示误导准确率（AC-E-15） | 条目引用数低于样本量下限（「建议值 10 次 · 终稿前确认」）时：不显示准确率数值，准确率位置显示「样本积累中」；其余指标（命中数/引用数/点踩数/「试了没用」数）照常显示 |
| F-15 | 章节树导航（AC-M-17，第三轮增补） | 打开②知识库总页面：条目按大章节→小章节两级书目录式层级组织可导航——章节树可折叠展开、条目挂在小章节下、点击条目进入详情/编辑器；章节可由运营新建/重命名/调整层级；含条目的章节不可直接删除；搜索与筛选在层级结构下保留可用 |
| F-16 | 人工录入未审不入总页面（AC-M-18，第三轮增补） | 在③人工录入提交新条目后、人工审核前：该条目仅出现在⑤审核队列（来源标注「人工录入」），**不出现在②知识库总页面**、不进检索库；人工审核通过并过发布门禁后才转入总页面对应章节 |
| F-17 | 审核队列来源标注与筛选 | ⑤区每条待审条目带来源标注（「人工录入」「批量导入」「AI 录入」，与 §5.10 定稿一致），可按来源筛选；AI 草稿按频次降序、人工/导入按提交时间降序 |
| F-18 | AI 批次异常如实标注 | 抓取失败或当日无可提炼会话时：④区批次列表如实标注「失败」或「无新草稿」，不静默缺批次；失败批次次日照常抓取，人工录入与审核不受阻 |
