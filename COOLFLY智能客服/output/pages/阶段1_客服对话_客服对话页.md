## 2. 页面概述

### 2.1 一句话定位

COOLFLY App 用户的唯一客服会话界面：一个会话流承载智能问答（F01）、引导式排障（F02）、双层反馈（F04）与全部入口到达行为（F08 到达点），让"刚拿到设备、卡在安装/联网/配对"的用户几分钟内自助解决问题，解决不了时无缝走向转人工。

### 2.2 存在理由

1. 差评实证"设备掉线没有任何指引"（复述："my device went off-line…no instructions"，PRD §1.2）——没有本页，用户故障时无处求助，挫败型退货持续流血（退货率约 11%）。
2. 人工回复平均 1–2 小时、口径不一；没有本页的秒级 AI 应答与统一知识库回答，解决速度与口径一致性无从谈起。
3. 中老年用户打字意愿低——没有首屏零打字按钮组与一步一屏排障，这批主力用户面对空白输入框直接放弃。

### 2.3 页面目标（可衡量）

| 目标维度 | 具体指标（口径归 PRD §8，本页不另定义） |
| :--- | :--- |
| 自助解决率（严口径） | 高频类目标 60% / 底线 45%（上线 3 个月，假设值 A-004，G1 后校准） |
| 自助解决时长 | 自助场景从进入会话到确认解决 ≤10 分钟（假设值） |
| 无死屏 | 任何故障态均有状态说明 + 至少一个可用出路（PRD §7 写死原则，100%） |
| 连续拒答 | 单会话连续拒答 ≤2 次（硬上限，不存在第 3 次"我没把握"） |

### 2.4 不做什么（范围边界）

- **不做**设备状态读取/远程诊断类功能或承诺（AC-F02-07 不变行为；排障上限 = 引导自查 + 带 SN 转人工，A-003）——第二阶段王牌，本期界面不得出现相关暗示。
- **不做**独立全屏排障模式或浮层页面（PRD §5.3 R5-S1 写死）——步骤卡是会话流内全宽消息卡，不拆页。
- **不做**注册/登录/账号界面——用户身份由宿主 App 登录态注入 RN 容器（蓝图 §3），requirements 无认证 REQ。
- **不做**转人工确认面板本体——面板为独立页面 PAGE-F03-01（本页内底部抽屉），本页只负责五类触点与「已转接等待」态的会话流表现。
- **不做**任何用户可见的"优先处理"承诺（R2-裁决 7）——情绪会话标记为纯内部字段；界面与话术不得出现 "priority" 类表述。
- **不做**硬拦截转人工（REQ-F03-07 / AC-I-01 不变行为）——不存在"必须先走完 N 步排障才许转"。

## 3. 用户与场景

### 3.1 目标用户

| 维度 | 描述 |
| :--- | :--- |
| 角色 | App 用户（COOLFLY 智能喂鸟器/鸟类相机买家；单直接角色产品） |
| 人数 | 单次会话 1 人（同一账号多设备并发见 §7.2） |
| 技术熟练度 | 中低——主力北美英文用户，中老年占比高、打字意愿低 |
| 使用设备 | 手机（竖屏手持） |
| 使用姿势 | 典型状态"刚拿到设备，卡在安装/联网/配对"，常处于弱网/切换网络环境（改路由器设置是主路径） |

### 3.2 核心使用场景

**场景 A：错误态一键进入 + 零打字排障（主场景，旅程 A）**
- 时机：配对到一半卡住，配对失败页出现 "Get help"。
- 前置：错误码已结构化（G2 前提满足），故障上下文随入口注入。
- 动作：点 "Get help" → 首条为开场确认 "Looks like pairing didn't go through. Want me to walk you through fixing it?" → 点 [Yes, help me] → 进入配对排障流第一步（一步一屏、配图）→ 中途切出 App 改路由器设置 → 返回自动恢复到原步骤 → 点 `Done` 至末步 → 解决确认 + 评分卡。
- 情绪：从挫败到被接住；全程零打字、零复述。

**场景 B：自由提问被拒答后转人工（兜底场景，旅程 B）**
- 时机：用户自由输入知识库覆盖不到的事实性问题。
- 前置：检索无可靠依据（拒答第①/②层）。
- 动作：收到常规拒答话术 + 内联转人工链接 → 追问再次拒答 → 第 2 次直接呈现极短说明句 + `Talk to a human` 大按钮 → 点按进转人工确认面板（PAGE-F03-01）。
- 情绪：不被消耗第三次耐心，知道出路在哪。

**场景 C：情绪崩溃路径（旅程 C）**
- 时机：用户折腾 2 小时后打出 "this thing is garbage, I want a refund"。
- 前置：消息命中退款/愤怒关键词清单 v1（PRD §12.7，确定性规则）。
- 动作：不被追问技术细节 → 收到共情开场 → 情绪出口置顶卡出现并常驻（`Talk to a human` ｜ `Refund & return policy`）→ 用户自选出口或接受"最后试一步"。
- 情绪：先被安抚，出口就在眼前。

**场景 D：弱网/离线中排障（兜底场景——核心用户正处于连接故障中）**
- 时机：排障中手机断网或流式输出中连接中断。
- 前置：会话与排障进度已存在。
- 动作：离线提示可见、当前步骤卡保持可读、发送置灰 → 恢复网络后无需任何动作回到原状态、操作生效。
- 情绪：不恐慌——进度不丢、不出死屏。

### 3.3 用户核心诉求（优先级排序）

1. **快**：秒级响应、零打字入口、几分钟内解决。
2. **不迷路**：一步一屏两个大按钮，永无死胡同；任何状态都有出路。
3. **不复述**：转人工时摘要自动带上已试步骤/SN/型号。
4. **被诚实对待**：AI 身份开场披露；没把握明说不猜；不虚假承诺。
5. **情绪被接住**：愤怒时先共情、出口置顶，不被技术追问。

## 4. 信息架构

### 4.1 区域划分

1. 顶部栏（会话菜单）
2. 情绪出口置顶卡位（触发后常驻，不随滚动消失）
3. 会话流主体（自上而下时间序：系统消息 / 用户消息 / AI 回答 / 排障步骤卡 / 各故障态卡 / 评分卡）
4. 恢复/过期/转人工附加提示条位（按时间序插入会话流）
5. 底部输入区（自由输入框 + 发送按钮）

### 4.2 区域内容

**1. 顶部栏**
- 会话菜单三项：转人工 / 重看首屏按钮 / 结束会话（常驻可见）。

**2. 情绪出口置顶卡位**
- 情绪路径触发后置顶常驻：`Talk to a human` ｜ `Refund & return policy` 双按钮；无任何"优先处理"类承诺。

**3. 会话流主体**
- 开场消息（AI 身份披露）；首屏按钮组（Setup / Won't connect / Pairing failed / Membership）；错误态进入时的携带上下文开场确认（F08 到达行为）；AI 回答气泡（流式 + 末尾来源标注 + 消息级 👍/👎）；拒答消息（四形态）；非英语兜底消息；追问澄清消息；排障步骤卡（全宽消息卡：进度指示 + 标题/说明 + 配图 + Done / It didn't work 双大按钮 + 转人工次级入口）；转人工大按钮；已转接等待提示；客服回复消息（目标态）；会话评分卡 / 服务体验反馈；各故障态卡（超时 / 中断 / LLM 降级 / 发送失败）。

**4. 提示条位**
- 恢复提示条（24h 接续）；过期提示；同一步骤二次到达附加的转人工提示条。

**5. 底部输入区**
- 自由输入框（占位 "Type your question…"）+ 发送按钮（空/离线置灰；超长计数禁发）。

## 5. 界面内容

### 5.1 元素清单

> 全部用户可见文案引用 PRD §5 定稿原文（唯一落点），英文文案禁止改写。

**开场消息（AI 身份披露）**（REQ-F01-06 / AC-F01-21）
- 类型：系统消息气泡，每个新会话首条自动出现，不可交互。
- 文案："Hi! I'm COOLFLY's AI assistant. I'll do my best to help you fix things fast — and I'll bring in a human teammate whenever you need one."
- 数据来源：语言资源（F07 约束一：不硬编码）。
- 显示条件：每个新会话首条；旧版本降级形态见 §7.1「旧版本纯文本降级」。

**首屏按钮组**（REQ-F02-01 / AC-F02-01；按钮组属发版线，EAS 热更承载）
- 类型：大按钮 ×4：`Setup` ｜ `Won't connect` ｜ `Pairing failed` ｜ `Membership`。
- 操作后：前三个→进入对应 F02 引导流；`Membership`→预置意图直达知识问答（零打字，AC-F01-01）。
- 显示条件：开场消息下方常驻；会话产生首条用户消息后收起，可从会话菜单「重看首屏按钮」重新唤起。

**自由输入框 + 发送按钮**（REQ-F01-08）
- 占位文案："Type your question…"
- 操作后：发送后清空、消息入会话流；AI 流式输出中仍可输入、可发送，消息进入队列按序应答。
- 禁用条件：输入为空 / 手机离线 → 发送按钮置灰；超长（上限建议值 1,000 字符·终稿前确认）→ 计数提示、禁止发送（不截断静默发送）。

**AI 回答气泡（流式 + 来源标注）**（REQ-F01-02 / AC-F01-02）
- 类型：流式消息；消息发出即显示 responding 指示，随后流式逐字输出。
- 来源标注：知识求解类回答末尾附简短标注，格式 "Source: {document title}"（如 "Source: Setup Guide"）；不展开引用全文、不做跳转承诺；标注必须与实际命中条目一致。
- 操作后：输出完成后消息级 👍/👎 出现（挂全部 F01 事实性回答，含 Membership 预置意图路径产生的回答）。

**拒答消息 · 四形态**（REQ-F01-03 / AC-F01-03/04/07；情绪形态见 REQ-F01-04）

| 形态 | 触发 | 文案（定稿原文） | 出口 |
| :--- | :--- | :--- | :--- |
| 常规套（第 1 次） | 三层拒答任一层，非情绪会话 | "I don't want to guess on this one — I couldn't find a reliable answer in our guides. Let me connect you with our support team; they'll already have your conversation and device info." | 内联转人工链接 |
| 第 2 次（连续） | 同会话连续第 2 次拒答 | "I'm still not able to answer this confidently — let's get a human on it." | 大按钮 `Talk to a human`；此后本会话不再输出任何拒答类消息 |
| 情绪场景 | 情绪会话内知识求解触发拒答（任一次） | "This one's taking more effort than it should — let me get a human teammate on it for you." | 大按钮 `Talk to a human`；照常计入连续拒答计数；禁止技术追问、"我没把握"模板、优先承诺 |
| 超范围/敏感（第③层专属） | 硬规则命中 | "This is outside what I can help with in this chat — but a human teammate can take it from here." | 内联转人工入口；说明能力边界而非知识缺口；照常计入计数；情绪会话内仍按情绪形态呈现 |

**转人工大按钮**
- 类型：全宽大按钮（≥44pt），文案 `Talk to a human`。
- 显示条件：默认隐藏；第 2 次拒答后紧随极短说明句出现；情绪会话内任一次拒答随共情式短语出现。
- 操作后：进入转人工确认面板（PAGE-F03-01）。

**情绪出口置顶卡**（REQ-F01-04 / AC-F01-05）
- 类型：置顶卡片，双按钮 `Talk to a human` ｜ `Refund & return policy`；无任何"优先处理"类承诺。
- 伴随消息（共情开场）："I'm really sorry — you've spent way too long on this, and that's frustrating. Let's get this sorted." 可选跟随句："If you're open to one last quick check, there's one step that fixes this most often — your call."
- 显示条件：默认隐藏；情绪路径（关键词规则命中或分类器判情绪类）触发后置顶常驻，不随消息滚动消失。

**非英语兜底消息**（REQ-F01-05 / AC-F01-06）
- 类型：消息气泡（英文 + 用户所用语言双语模板句），检测到非英语输入即出现（决策步骤 0，先于关键词规则与意图分类）。
- 文案（西班牙语例）："Right now I can only help in English. / Por ahora solo puedo ayudarte en inglés."＋"You can keep typing in English, or reach our human team here: [Talk to a human] / Puedes escribir en inglés o contactar a nuestro equipo aquí: [Talk to a human]"
- 预置双语语言集合「建议值 西班牙语/法语/德语 · 终稿前确认」；集合外语言回落纯英文兜底句，转人工入口照常。

**追问澄清消息**（REQ-F01-08 / AC-F01-08）
- 文案："Could you tell me a bit more about what's happening?"
- 显示条件：无意义输入（乱码/纯表情）时；不计拒答、不触发拒答话术。

**Membership 预置意图开场**（REQ-F01-07 / AC-F01-01）
- 文案："What would you like to know about your membership?" 类会员主题开场提问/高频问题引导。
- 属追问澄清类豁免，不计事实性解答。

**排障步骤卡**（REQ-F02-01/02 / AC-F02-01/02/03；卡片 UI 发版线，EAS 热更承载）
- 类型：会话流内全宽消息卡，一步一屏，大字（20pt+，蓝图 §6 锚点；具体样式归设计系统）；按时间序插入流中，当前步骤卡保持可回达；不做独立全屏模式或浮层。
- 组成：进度指示（如 "Step 2"，**不带总步数分母**——分支换路径时总数会变）＋步骤标题与操作说明＋配图（Top 3 场景关键分支 🟩；可点看大图；加载失败隐藏图位，文字说明必须独立完整可操作）＋双大按钮 `Done` ｜ `It didn't work`（≥44pt，常驻卡片底部并列）＋转人工次级入口（每张卡片可达，不与两大按钮抢层级）。
- 卡片内不叠 👍/👎（"It didn't work" 本身即负反馈，直接入 F05 回流）。
- 操作后：`Done` → 下一步 / 末步进入解决确认；`It didn't work` → 显式建模的失败分支；任何分支终点只有两种：解决确认 或 转人工（无死胡同）。

**恢复提示条**（REQ-F02-03 / AC-F02-04）
- 文案："Welcome back! You were on Step {n} — ready to pick up where you left off?"
- 显示条件：排障中途离开后 24h 内返回时出现；点击回到离开时的步骤。禁用条件：已超 24h 接续窗口。

**24h 过期提示**（AC-F02-05）
- 文案："Your previous session has expired, so we'll start fresh from Step 1."
- 显示条件：接续窗口过期后用户返回同场景；原会话按已结束处理，新会话从第一步开始。

**同一步骤二次到达 · 转人工提示条**（REQ-F02-02）
- 显示条件：同一步骤第二次到达时卡片附加转人工提示条（循环上限「建议值 2 次 · 终稿前确认」），不让用户无限循环——分支图"环上必有转人工出口"规则的用户侧表现。

**末步解决确认**（AC-F02-02）
- 文案："Great — looks like you're all set!"（评分卡紧随其后触达；"是否解决"问句唯一落点在评分卡）。

**分支穷尽转人工引导**
- 文案："We've tried the usual fixes. This one needs a human with your device's serial number — let me hand you over with everything you've already tried."

**消息级 👍/👎 与点踩原因浮层**（REQ-F04-01 / AC-F04-01）
- 类型：图标按钮对，AI 事实性回答输出完成后出现（灰）；选中高亮，可改选、以最后一次为准。
- 挂载范围：全部 F01 事实性回答消息（含预置意图路径）；排障卡片、拒答消息、系统消息不挂。
- 点踩浮层：三选 `Not relevant` ｜ `Hard to understand` ｜ `I tried it — didn't work`，可跳过；跳过时点踩状态仍保持选中；无论是否选原因均入 F05 回流。

**会话评分卡（解决维度）**（REQ-F04-02）
- 文案："Did this solve your problem?" [Yes] [Not yet] + 可选星级（用户可见标签 Yes / Not yet，语义值 Yes/No，映射归 PRD §4.2）。
- 显示条件：结束判定命中时出现，每会话最多一次；底线态转接场景不出现。

**服务体验反馈（底线态转接）**（AC-F04-02）
- 文案："How was your experience with our assistant so far?" + 轻量星级/表情；不问"是否解决"。
- 显示条件：仅底线态转接确认后出现一次。

**评分致谢**
- 文案："Thanks — this helps us improve."（轻 Toast，蓝图 §5：不用弹窗打断）。

**故障态元素**（REQ-F01-10；文案位 C1/C2/C3 为 PRD §5.1 唯一落点）
- 响应超时提示：**C1** "This is taking longer than usual. [Retry]"。
- LLM 降级卡：**C2** "Our assistant is temporarily unavailable. You can reach our support team directly, or browse these guides."（直达转人工 + 排障文章链接）。
- 离线提示：**C3** "You're offline. Please check your connection."
- 发送失败：消息旁失败标记 + 单条重发按钮。
- 流式中断：已输出内容保留 + 中断标记 + [Retry]。

**已转接等待提示（目标态/底线态）**（REQ-F03-05 会话流表现，ID 归 PAGE-F03-01；文案引用 PRD §5.4）
- 目标态："You're connected with our support team — your message has been added to this conversation for them to see."
- 底线态："This conversation has been handed to our support team — they'll reply through the channel above. Need help with something else in the meantime?" + 按钮 `Continue with the AI assistant`（点击开启新自助会话，原转接与人工处理不受影响）。

**错误态开场确认（F08 到达行为，AC-F08-01 对话页侧表现）**（文案引用 PRD §5.9 定稿）
- 掉线："I can see your camera just went offline. Want me to walk you through getting it back online?" [Yes, help me] [I have a different question]
- 配对失败："Looks like pairing didn't go through. Want me to walk you through fixing it?" [Yes, help me] [I have a different question]
- 扫码失败："Looks like the QR code scan didn't work. Want me to walk you through fixing it?" [Yes, help me] [I have a different question]
- 显示条件：仅错误态入口进入且上下文可判定时为首条；固定入口进入不出现；否认或不可判定 → 落首屏按钮组。

**会话菜单**
- 三项：转人工 / 重看首屏按钮 / 结束会话；顶部常驻可见。

- 全部用户可见文案从可替换语言资源加载（F07 约束一，AC-C-05 口径）；本文档所列英文均为 PRD §5 定稿原文。

## 6. 交互流程

### 6.1 页面加载与初始化

- 宿主注入用户标识/凭证/SN/型号/错误上下文类型/entry_source（RN 桥接契约，规格归 PAGE-F08-01）。
- 固定入口进入 → 新会话：开场披露 + 首屏按钮组 + 自由输入框。
- 错误态入口进入且上下文可判定 → 首条为携带上下文的开场确认；不可判定（错误码未结构化）→ 降级通用进入，落首屏（AC-F08-03 口径）。
- 存在 24h 内可接续的排障会话 → 恢复原会话并出现恢复提示条；超窗 → 过期提示 + 新会话。
- push 深链进入（目标态回复触达）→ 回到原会话流，客服回复可见。
- 冷启动加载失败 → 给出重试态而非空白页（不出死屏原则）。
- 手机离线 → 本地离线提示（C3）可见，恢复后可正常进入。

### 6.2 核心操作流程

```
进入会话
  ├─ 固定入口 ──→ 首屏（开场披露 + 按钮组 + 自由输入）
  └─ 错误态入口 ─→ 开场确认 ── 确认 ──→ 对应排障流第一步
                     └─ 否认 / 不可判定 ──→ 首屏

首屏分流
  ├─ Setup / Won't connect / Pairing failed ──→ F02 引导流（零打字）
  ├─ Membership ──→ 预置意图直达会员问答（零打字，开场提问）
  └─ 自由文本 ──→ §3 决策总顺序（用户可见结果）：
        ⓪ 非英语 ──→ 非英语兜底消息（含转人工按钮，不进后续判定）
        ① 退款/愤怒关键词命中 ──→ 共情开场 + 情绪出口置顶卡常驻
        ② 意图分类：情绪类→同上；闲聊/追问澄清→轻量应答；流程推进→排障推进
        ③ 知识求解 ──→ 三层拒答判定
             ├─ 通过 ──→ 流式回答 + 末尾来源标注 + 👍/👎
             └─ 拒答 ──→ 第1次常规套(或第③层超范围专属文案)＋内联转人工链接
                          第2次极短句＋Talk to a human 大按钮（此后不再拒答类消息）
                          情绪会话内任一次＝共情短语＋大按钮（照常计数）

排障流（会话流内嵌）
  步骤卡 ── Done ──→ 下一步 …… 末步 ──→ "Great — looks like you're all set!" ──→ 评分卡
        └─ It didn't work ──→ 失败分支 ……（任何终点 ∈ {解决确认, 转人工}）
        └─ 同一步骤二次到达 ──→ 卡片附加转人工提示条
  排障中自由输入 ──→ 追问澄清就地解答后回到当前步骤；情绪触发走情绪路径；
                     无关新知识求解照常走决策顺序（含拒答），之后询问是否继续排障

转人工触点（五类，均 → PAGE-F03-01 底部抽屉）
  拒答内联链接 / 第2次拒答大按钮 / 情绪置顶卡 / 排障分支终点 / 会话菜单
  面板返回：Not now → 回原会话；Send & connect → 本页进入「已转接等待」态

会话结束三类（评分触达各异，REQ-F04-02）
  ①确认解决 → 立即弹评分卡（每会话 ≤1 次）
  ②转人工完成 → 目标态：人工会话关闭后触达评分卡；底线态：转接确认时仅服务体验反馈
  ③静默 30 分钟（非排障态）→ 静默流失不追弹
```

### 6.3 辅助操作

- 会话菜单：转人工（REQ-F03-07 全程可达）/ 重看首屏按钮（重新唤起按钮组）/ 结束会话。
- 配图可点看大图（排障步骤卡内）。
- 评分卡出现后用户又输入新消息：评分卡收起，该输入按"重新激活=新会话"处理，旧会话评分记未答复。
- 已结束会话中再输入：开新会话，开场披露重新出现，不继承已失效排障进度（AC-F01-10）。

### 7.2 边界与容错

| 边界场景 | 处理策略 |
| :--- | :--- |
| 网络断开 / 切网（改路由器是主路径） | 会话与排障进度全部保持；恢复后无需用户动作回到原状态；重发去重（最多一条记录，AI 不重复应答） |
| 会话过期 / 重激活 | 静默 30 分钟结束（非排障态）；排障豁免且 24h 接续；已转接等待豁免；已结束再输入=新会话计复问 |
| 连续错误（连续拒答） | 硬上限 2 次：第 2 次即大按钮，此后不再输出拒答类消息；计数规则：成功事实性解答清零，豁免类不清零不累加 |
| 异常输入 | 空/纯空白→发送置灰不产生消息；超长→计数禁发不截断；乱码/纯表情→追问澄清不计拒答；非英语→步骤 0 兜底；高敏输入→AI 不主动索取密码类信息，步骤指引用户在自己设备上操作 |
| 并发操作 | 流式中连续发多条→按发送顺序排队逐条应答、不丢消息；同账号多设备→以服务端会话流为唯一事实，两端完整时间序一致；转人工后客服回复与用户输入按时间序合并 |
| 版本/内容冲突 | 排障内容更新或灰度切换不打断进行中会话（按进入时版本走完，新会话用新版本，AC-F02-06）；配图加载失败隐藏图位、文字独立完整 |
| LLM 全挂 | 转人工提交、排障卡片推进、固定入口均为确定性路径，不依赖 LLM 可用性；LLM 返回异常内容按常规拒答套呈现，不展示原始错误 |
| 客服模块故障隔离 | 任何故障（LLM 不可用、引擎超时）不影响宿主 App 其余功能（AC-F01-16 不变行为） |
| 会话历史极长 | 超阈值（建议值 200 条·终稿前确认）提示开新会话，旧会话可查但引导收敛 |

## 8. 业务规则与校验

### 8.1 字段定义

| 字段 | 说明 |
| :--- | :--- |
| 会话 ID | 会话唯一标识；转人工时随交接契约发出（用户可见部分为摘要 1–4 字段，归 PAGE-F03-01） |
| entry_source | 入口来源（会话级，进入时刻写死：固定入口/错误态入口/未知）；旧版本无字段归"未知"桶 |
| interaction_mode | 消息级交互方式（按钮组/自由输入/预置意图），会话内可多次切换 |
| 错误上下文类型 | 宿主注入（掉线/配对失败/扫码失败），决定开场确认场景；未结构化=不可判定 |
| 排障进度 | 流程标识 + 当前节点标识；与会话状态强一致（切回 App 必须恢复到正确步骤） |
| 连续拒答计数 | 会话级；成功事实性解答清零，豁免类消息不清零不累加 |
| 情绪会话标记 | 内部字段：关键词或分类器任一触发即置位；不向用户展示 |
| 消息级反馈 | 👍/👎 + 点踩原因（可空）；改选以最后一次为准 |
| 会话评分 | 解决确认（语义值 Yes/No，可见标签 Yes / Not yet）+ 可选星级；或服务体验分值（底线态） |

### 8.2 校验规则

| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 空输入 | 输入时 | 空/纯空白不可发送 | 发送按钮置灰，不产生消息 |
| 超长输入 | 输入时 | 超上限（建议值 1,000 字符）禁发 | 输入框计数提示；不截断静默发送 |
| 离线发送 | 发送时 | 本地网络不可用禁发 | 发送置灰 + C3 离线提示 |
| 语言检测 | 每条消息（步骤 0） | 非英语→兜底模板；混合语言按主要语言判定，不确定按英语处理 | 双语兜底消息 + 转人工按钮 |
| 事实性回答引用 | 服务端 | 无引用即拒答；来源标注与实际命中条目一致 | 拒答形态呈现，不暴露内部层级 |
| 消息去重 | 重发时 | 重发最多产生一条消息记录 | 不重复入流、不重复应答 |

### 8.3 特殊业务规则

- **决策总顺序写死**（AC-F01-20）：步骤 0 语言检测 → 关键词规则 → 意图分类（五类）→ 仅知识求解类进三层拒答 → 路由；本页只呈现用户可见结果，不暴露内部判定。
- **豁免防滥用**：闲聊/追问/共情/流程话术不得夹带无引用事实性内容。
- **拒答硬上限**：连续 ≤2 次；不存在第 3 次"我没把握"。
- **无死胡同**：排障任何分支终点 ∈ {解决确认, 转人工}；同一步骤二次到达附转人工提示条。
- **转人工全程可达**（REQ-F03-07）：任何会话状态下主动要求转人工均可达，无强制排障门槛。
- **评分节制**：评分卡每会话 ≤1 次；静默流失不追弹（不推送、不下次打开弹窗）；点踩原因可跳过。
- **不虚假承诺**：不出现硬编码固定时长、不出现"优先处理"类表述（承诺话术本体归 PAGE-F03-01）。
- **文案资源化**：全部用户可见文案与 prompt 模板从语言资源加载，不硬编码（F07 约束一）。

## 10. 数据需求

### 10.1 页面需要什么数据

| 数据 | 来源 | 用途 |
| :--- | :--- | :--- |
| 用户标识/凭证 | 宿主登录态注入（桥接契约） | 引擎 API 校验；无独立登录 |
| SN / 设备型号 | 宿主注入 | 转人工摘要预填（消费归 PAGE-F03-01）；缺失不阻塞 |
| 错误上下文类型 + entry_source | 宿主注入 | 开场确认场景选择；埋点分层 |
| 会话历史与状态 | 服务端会话流（唯一事实） | 恢复/接续/多设备一致展示 |
| 排障流程内容（步骤/分支/配图） | 引擎 API（结构化流程条目，渠道中立 schema） | 步骤卡渲染；进行中会话锁定进入时版本 |
| AI 回答与来源标注 | 引擎 API（流式） | 回答气泡 + "Source: {document title}" |
| 语言资源 | 可替换语言资源包 | 全部用户可见文案（F07 约束一） |

### 10.2 页面提交什么数据

| 数据 | 触发时机 | 用途 |
| :--- | :--- | :--- |
| 用户消息（文本） | 发送 | 引擎决策与应答 |
| 按钮操作（首屏按钮 / Done / It didn't work / 开场确认选择） | 点按 | 流程推进与路由；排障步骤推进埋点 |
| 消息级反馈（👍/👎 + 原因） | 反馈操作 | F05 回流；改选以最后一次为准 |
| 会话评分 / 服务体验分值 | 评分触达 | 严口径解决率输入；网络中断时本地暂存补报（用户见提交成功态） |
| 埋点事件（会话开始/意图结果/拒答/回答/步骤推进/反馈/结束等，公共属性含 entry_source、interaction_mode、app_version、channel） | 各事件时机 | F06 度量；客户端暂存补报，缺埋点的功能不算完成 |

### 10.3 明确排除的数据

- 不读取设备运行状态/日志（AC-F02-07 不变行为）。
- 不采集密码类信息；SN/邮箱/Wi-Fi 名称等敏感字段脱敏后才入分析库（页面不做展示外处理）。
- 不需要客服工作台数据（本期无客服侧界面）。
- 不需要看板聚合指标（归 PAGE-F06-01）。

## 11. 验收标准

> 验收注意（无障碍基线，REQ-F01-11 / NFR-001，本页全元素适用）：关键可点击元素（首屏按钮、Done / It didn't work、转人工大按钮、置顶卡按钮、发送、👍/👎）触达区域 ≥44pt；系统字体缩放至最大档不破版、不截断按钮文案；对话流、排障步骤卡通过基础 VoiceOver 走查（关键控件可被读出、可操作）。

### 11.1 功能验收

| 编号 | 验收点 | 通过标准（对应 AC） |
| :--- | :--- | :--- |
| F-01 | 首屏零打字进排障 | 点 "Pairing failed" 直接进入配对引导第一步；卡片仅 Done / It didn't work 两大按钮，转人工为次级入口每卡可达（AC-F02-01） |
| F-02 | Membership 预置意图 | 零打字进入会员问答，AI 先出会员开场提问（属追问澄清豁免，不计事实性解答）（AC-F01-01） |
| F-03 | 四类高频英文问答 + 来源标注 | 安装/联网/配对/会员四类各一场景：英文回答末尾可见 "Source: {document title}"，不输出编造步骤（AC-F01-02） |
| F-04 | 拒答四形态 | 第 1 次常规套+内联链接（AC-F01-03）；连续第 2 次极短句+大按钮、无第 3 次（AC-F01-04）；超范围用第③层专属文案（AC-F01-07）；情绪会话内为共情短语+大按钮 |
| F-05 | 情绪路径硬验收 | 命中关键词清单 v1 的消息不进拒答判定、不被技术追问；共情话术 + 双出口置顶常驻不随滚动消失（AC-F01-05） |
| F-06 | 非英语兜底 | 收到英文+该语言模板句 + 转人工入口；会话不中断（AC-F01-06）；无意义输入走追问澄清不计拒答（AC-F01-08） |
| F-07 | 排障无死胡同 | 任一步 It didn't work 均有替代分支或转人工出口（AC-F02-03）；末步 Done → 解决确认 + 评分入口（AC-F02-02）；排障中自由输入不脱轨（AC-F02-08） |

| F-09 | 版本一致性 | 内容更新/灰度切换不打断进行中会话（AC-F02-06）；界面不出现设备诊断承诺（AC-F02-07 不变行为） |
| F-10 | 消息级反馈 | 点 👎 出三选原因、可跳过且点踩保持选中、无论选否均入回流（AC-F04-01）；改选以最后一次为准 |
| F-11 | 评分触达分型 | 确认解决立即弹评分卡且每会话 ≤1 次；底线态转接仅服务体验反馈、不问"是否解决"（AC-F04-02）；静默流失不追弹 |
| F-12 | 决策顺序与开场披露 | 语言检测→关键词→意图分类→路由顺序可复现（AC-F01-20）；每个新会话首条可见 AI 身份披露（AC-F01-21） |

| F-14 | F08 到达行为（交叉，ID 归 PAGE-F08-01） | 错误态进入首条为对应开场确认、否认回首屏（AC-F08-01 对话页侧）；错误码未结构化降级落首屏（AC-F08-03 对话页侧）；旧版本纯文本分步引导路径完整（AC-F08-04 对话页侧） |
