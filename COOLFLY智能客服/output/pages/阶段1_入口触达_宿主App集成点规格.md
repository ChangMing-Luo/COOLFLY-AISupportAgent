## 2. 页面概述

### 2.1 一句话定位

把"用户遇到麻烦的那一刻"与客服对话页之间的距离压缩到最短：固定入口保证随时找得到，错误态入口保证故障现场一键带过去，RN 桥接契约保证宿主与客服模块之间的数据传递长期稳定。

### 2.2 存在理由

1. **入口不可见 = 引擎能力归零**：COOLFLY 自身差评称 App 导航为 "labyrinthian maze"（AC-M-11 场景背景，PRD §11.3）——对话引擎做得再好，用户找不到入口就等于没做。
2. **错误现场丢失 = 用户被迫复述**：差评 #6"掉线无任何指引"；没有携带上下文的错误态入口，最不会打字的中老年用户群要自己描述"我在配对时失败了"，流失在开口之前。
3. **桥接契约不稳 = 未来渠道全部返工**：宿主→RN 注入字段是未来所有入口形态（含阶段二语音）的接线底稿（蓝图 §4）；契约无版本化约束，任何一次宿主改动都可能击穿客服模块。

### 2.3 页面目标（可衡量）

| 目标维度 | 具体指标 |
| :--- | :--- |
| 入口可达性 | 新用户从 App 首页 ≤3 步到达固定客服入口（"步"=点击/页面跳转次数，不含滚动查找，AC-F08-02） |
| 错误态覆盖 | 错误态入口最低覆盖集合 = 设备掉线 / 配对失败（含卡死） / 扫码失败三类（REQ-F08-02） |
| 入口鲁棒性 | 任何降级场景下入口不消失、点击不无响应（AC-F08-03、REQ-F08-01 离线分支） |
| 覆盖率呈报 | 发版线覆盖率按 app_version 如实呈报，不并入引擎线 2 周灰度承诺（REQ-F08-03） |

### 2.4 不做什么（范围边界）

- **不做**对话页内部行为——开场确认消息的渲染、确认/否认后的路由执行属 PAGE-F01-01；本规格只负责把故障上下文与 entry_source 正确送达 RN 容器。
- **不做**错误码治理本身——客户端错误态是否结构化依 G2 查证结果如实呈报（PRD §9.6）；本规格只定义"就绪/未就绪"两种前提下的入口行为，不承诺治理工作量。
- **不做**全局悬浮窗/浮标类入口——Source IDs 只定义"设备页/我的页一级入口 + 错误提示旁按钮"两种位置，不扩充。
- **不做**阶段二语音等新渠道入口——桥接契约只做"版本化预留"，不在 MVP 预埋任何语音入口 UI（PAGE-F01-02 planned）。
- **不做**任何注册/登录界面——App 用户身份由宿主登录态注入，无新增账号体系（蓝图 §3，requirements 无对应 Source ID）。

## 3. 用户与场景

### 3.1 目标用户

| 维度 | 描述 |
| :--- | :--- |
| 角色 | COOLFLY 摄像头 C 端用户（含中老年占比高的群体）；间接消费者 = 宿主 App 原生开发（消费本规格的桥接契约与入口位规格） |
| 人数 | 单次使用 1 人 |
| 技术熟练度 | 偏低—中等；最不会打字的用户群是错误态入口的核心受益者 |
| 使用设备 | 手机（竖屏 375–430pt 基准，蓝图 §1） |
| 使用姿势 | 手持，常处于设备故障导致的挫败情绪中 |

### 3.2 核心使用场景

**场景 A：错误态一键求助（主场景）**
- 时机：摄像头掉线 / 配对失败 / 扫码绑定失败，错误提示出现的瞬间
- 前置：App 为含 F08 的新版本；该错误态错误码已结构化（G2 前提满足）
- 动作：点错误提示旁 "Get help" → 一键进入客服对话，首条即为携带该故障场景的开场确认 → 点 [Yes, help me] 直接进入对应排障流第一步，全程零打字、零复述
- 情绪：从挫败到"它知道我出了什么事"，被接住

**场景 B：新用户主动找客服（主场景）**
- 时机：新用户遇到问题，主动去找客服入口
- 前置：App 为新版本；无错误提示在场
- 动作：从 App 首页 ≤3 步（点击/页面跳转，不含滚动查找）到达设备页或我的页的一级 "Support" 按钮 → 进入客服对话页首屏（按钮组 + 自由输入）
- 情绪：不迷路、不翻菜单迷宫

**场景 C：错误码未结构化的降级进入（兜底场景）**
- 时机：用户在某错误提示旁点 "Get help"，但该错误态无结构化错误信息（G2 前提不满足）
- 前置：该错误态被列入降级清单（逐条呈报）
- 动作：点击后降级为通用进入——落客服对话页首屏（按钮组 + 自由输入，不落纯自由输入框）
- 情绪：虽未被自动识别故障，但入口没消失、点击有响应，仍有零打字按钮可选

**场景 D：旧版本用户（兜底场景）**
- 时机：未升级到含 F08 版本的用户需要客服
- 前置：旧版本客户端 + 新引擎共存（PRD §7.6 共存主形态）
- 动作：从原有存量固定入口进入 → 自由输入问答、三层拒答、转人工（含摘要）、非英语兜底全部可用；卡片 UI 缺失时排障以纯文本分步引导提供（每条消息一步 + 文字确认），开场消息附高频问题引导语替代按钮
- 情绪：功能降级但路径完整，不撞功能黑洞

### 3.3 用户核心诉求（优先级排序）

1. **找得到**：不需要在菜单迷宫里翻找，出错的地方就有求助按钮
2. **不复述**：故障现场自动带过去，确认一下就开始修
3. **不落空**：任何情况下（降级/离线/旧版本）点了都有响应
4. **不被误导**：上下文带错场景时能一键否认，不被锁死在错误引导流

## 4. 信息架构（按集成点归类——模板"页面区域划分"对集成规格降级为"集成点清单"）

### 4.1 集成点清单

1. 固定入口（原生，×2 位置：设备页、我的页）
2. 错误态入口（原生，×3 最低覆盖：设备掉线提示、配对失败页、扫码绑定失败页）
3. RN 容器桥接（原生 ↔ RN，注入契约）
4. push 深链（系统通知 → RN 容器对话页，仅 F03 目标态）

### 4.2 集成点内容

**1. 固定入口**
- 设备页、我的页各一处一级可见的 "Support" 按钮（常驻，无禁用条件）
- 点击进入客服对话页（F01 首屏：按钮组 + 自由输入），注入 entry_source=固定入口

**2. 错误态入口**
- 三类错误提示旁的 "Get help" 按钮（对应错误态出现时展示）
- 点击一键进入对话并自动携带故障上下文，注入 entry_source=错误态入口 + 错误上下文类型
- 错误码未结构化的错误态：按钮保留，点击走通用进入（不带上下文）

**3. RN 容器桥接**
- 宿主打开 RN 容器时注入字段清单（见第 8.1 节契约表）：用户标识/凭证、SN、设备型号、错误上下文类型、entry_source、app_version
- 契约版本化：只增补、不改义（详见 8.3）

**4. push 深链**
- 目标态下客服回复触达的 push，点击回到客服对话页同一会话（DEC-002）
- push 权限的场景化请求时机、被拒后的明示文案属 PAGE-F03-01 / PAGE-F01-01 范围，本规格只负责"点击通知 → 正确落回对话页"的宿主侧接线

## 5. 界面内容

### 5.1 元素清单

**固定入口按钮**
- 类型：一级入口按钮（≥44pt，PRD §5.9 边界数值）
- 文案："Support"（PRD §5.9 文案定稿）
- 数据来源：静态
- 显示条件：设备页/我的页常驻可见，无禁用条件；App 全局网络异常时仍展示，点击进入离线提示态（§7.1）

**错误态 "Get help" 按钮（×3）**
- 类型：错误提示内按钮（关键按钮 ≥44pt）
- 文案："Get help"（PRD §5.9 文案定稿）
- 数据来源：静态；携带的故障上下文来自该错误态的结构化错误码
- 显示条件：对应错误态出现时展示；错误码未结构化不隐藏按钮，仅降级行为

**携带上下文的开场确认（文案定稿照抄，PRD §5.9 唯一落点；渲染在对话页首条消息，本规格负责上下文正确送达）**

| 场景 | 定稿文案 |
| :--- | :--- |
| 掉线 | "I can see your camera just went offline. Want me to walk you through getting it back online?" [Yes, help me] [I have a different question] |
| 配对失败 | "Looks like pairing didn't go through. Want me to walk you through fixing it?" [Yes, help me] [I have a different question] |
| 扫码失败 | "Looks like the QR code scan didn't work. Want me to walk you through fixing it?" [Yes, help me] [I have a different question] |

- 显示条件：仅错误态入口携带可判定上下文进入时出现；固定入口进入时不出现；否认或不可判定 → 落首屏按钮组，入口不消失

### 5.2 辅助信息（降级说明）

本页型无页脚/帮助文案/版本号等页面级辅助信息——集成点寄生于宿主既有页面，不新增辅助内容。唯一辅助约束：灰度桶内外入口文案两版保持一致（REQ-F08-03，不因界面差异暴露分组）。

## 6. 交互流程

### 6.1 集成点初始化（模板"页面加载"对集成规格降级为"集成点就绪条件"）

- 固定入口：随设备页/我的页渲染即就绪，无异步依赖
- 错误态入口：随对应错误提示出现而出现；出现时即读取该错误态是否具备结构化错误码，决定点击后走携带上下文还是通用进入
- RN 容器：宿主在用户点击任一入口时打开 RN 容器并完成字段注入；对话页以注入的 entry_source / 错误上下文类型决定首屏形态
- push 深链：目标态回复 push 到达后，点击通知由宿主路由至 RN 容器对话页对应会话

### 6.2 核心操作流程（入口侧分流，对应 PRD §6.1 SRC→CTX/CFM 节点）

```
用户触达入口
    │
    ├─ 固定入口 "Support"（设备页/我的页）
    │       └→ 打开 RN 容器，注入 entry_source=固定入口
    │             └→ 对话页首屏（按钮组 + 自由输入，开场明示 AI 身份）
    │
    ├─ 错误态 "Get help"（掉线/配对失败/扫码失败）
    │       ├─ 错误码已结构化（G2 前提满足）
    │       │     └→ 注入 entry_source=错误态入口 + 错误上下文类型
    │       │           └→ 对话页首条：携带上下文的开场确认（CFM）
    │       │                 ├─ 用户确认 → 对应 F02 引导流第一步（零打字、零复述）
    │       │                 └─ 用户否认 → 回首屏按钮组（不锁死路由）
    │       └─ 错误码未结构化 / 上下文不可判定
    │             └→ 降级通用进入：落首屏按钮组 + 自由输入
    │                （降级项逐条列入覆盖清单呈报，入口本身不砍）
    │
    └─ push 通知（仅 F03 目标态回复触达）
            └→ 点击 → 回到对话页同一会话，查看客服回复
```

### 6.3 辅助操作

- App 全局网络异常时点击任一入口：仍打开对话页并进入离线提示态（§7.1），不出现按钮消失或点击无响应
- 旧版本客户端：无新入口，仅存量固定入口可用（进入后引擎线能力完整，见 7.2）

## 7. 状态与边界

### 7.1 集成点状态全景（模板 6 态对集成规格映射为入口视角状态）

| 状态 | 触发条件 | 表现 |
| :--- | :--- | :--- |
| 常态（固定入口） | 设备页/我的页正常展示 | "Support" 一级可见、可点击 |
| 错误态就绪 | 三类错误提示出现且错误码已结构化 | "Get help" 展示，点击携带上下文进入开场确认 |
| 降级态 | 错误态出现但错误码未结构化 | "Get help" 照常展示，点击通用进入（落首屏按钮组 + 自由输入） |
| 离线态 | App 全局网络异常 | 入口仍展示；点击进入对话页离线提示态（§7.1 状态矩阵） |
| 旧版本态 | 客户端未升级到含 F08 版本 | 无新入口；存量固定入口 + 引擎线全能力 + 排障纯文本降级 |
| 深链态 | 目标态 push 到达且被点击 | 宿主路由回对话页同一会话 |

### 7.2 边界与容错

| 边界场景 | 处理策略 |
| :--- | :--- |
| 错误码未结构化（G2 前提不满足） | 降级通用进入：落首屏按钮组 + 自由输入；入口不消失、点击不无响应；降级项逐条列入覆盖清单呈报，不因缺上下文砍入口（AC-F08-03） |
| 故障上下文带错场景（错误态误报） | 开场确认给否认出口 [I have a different question]，否认后回首屏按钮组，不把用户锁死在错误引导流（R2-裁决 3） |
| App 全局网络异常（错误态与客服入口同时故障） | 错误提示旁仍展示 "Get help"，点击进入离线提示态，不出现按钮消失或点击无响应（REQ-F08-01） |
| 旧版本客户端 + 新引擎共存 | 存量入口保全引擎线全能力（问答/三层拒答/转人工含摘要/非英语兜底）；卡片 UI 缺失时排障纯文本分步引导（每条消息一步 + 文字确认），路径完整不缺分支；开场消息附高频问题引导语替代按钮（AC-F08-04） |
| SN / 设备型号注入缺失 | 注入为空不阻塞进入对话与转人工；转人工摘要中显空可手补、多设备时选择涉事设备（衔接 PAGE-F03-01 规格，缺失不阻塞转接） |
| entry_source 缺失（旧版本流量） | 归"未知入口"桶单列呈报，不摊入固定/错误态分层（PRD §7.6，看板 §5.7 口径） |
| RN 容器与宿主工程兼容异常 | 兼容细节为 G2 盘点项（蓝图待确认 2）；本规格登记依赖，不自行发明降级行为，G2 结论回填后补充 |

## 8. 业务规则与校验

### 8.1 字段定义（RN 桥接注入契约 · DEC-001 · 版本化稳定契约）

宿主打开 RN 容器时注入以下字段（概念级清单，接口参数结构由技术方案落定）：

| 字段 | 说明 | 缺失时行为 |
| :--- | :--- | :--- |
| 用户标识 / 凭证 | 宿主 App 登录态签发；引擎 API 校验该凭证，无独立账号体系（蓝图 §3） | 无凭证不进入会话（宿主登录态为前置，本产品不新建门禁） |
| SN（设备序列号） | 宿主侧当前设备上下文 | 显空可手补，不阻塞对话与转人工 |
| 设备型号 | 同上 | 同上 |
| 错误上下文类型 | 枚举：设备掉线 / 配对失败（含卡死） / 扫码失败 / 不可判定；仅错误态入口进入时非空 | 不可判定或缺失 → 通用进入，落首屏 |
| entry_source | 枚举：固定入口 / 错误态入口；埋点侧另有"未知"桶承接旧版本缺失流量（§4.2 概念 schema） | 缺失归"未知"桶，看板分层单列 |
| app_version | 客户端版本，供发版线覆盖率按版本如实呈报（§7.6/§9.5） | 缺失随 entry_source 同归未知桶口径 |

### 8.2 校验规则

| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 凭证有效性 | 引擎 API 收到会话请求时 | 校验宿主签发凭证 | 由对话页按 §7.1 状态矩阵反馈，不在入口侧弹错 |
| 错误上下文可判定性 | 点击 "Get help" 时 | 有结构化错误码且可映射三类场景之一才判定成功 | 不可判定 → 通用进入（落首屏），无错误弹窗 |
| entry_source 完整性 | 埋点入库时 | 枚举外或缺失值不纠错、不伪造 | 归"未知"桶如实呈报 |

### 8.3 特殊业务规则

- **契约版本化（只增补、不改义）**：注入字段清单为版本化稳定契约——新增入口形态（含阶段二语音）只允许增补字段/枚举值，不允许修改既有字段语义或删除字段；它是未来全部入口形态的接线底稿（蓝图 §4 后续不可逆约束）。
- **灰度不暴露分组**：灰度分桶按用户维度；新版本客户端 + 未放量引擎（桶外）时入口与 UI 照常、对话走存量引擎，入口文案两版一致（§7.6）。
- **EAS Update 热更边界**：排障卡片 UI、按钮组、文案随 JS bundle 经 EAS Update 热更，不依赖发版；发版线覆盖率风险收窄到**原生入口本身**（设备页/我的页 Support、错误态 Get help、RN 容器接线）——只有这三样随 App 版本爬坡（蓝图 §1）。
- **覆盖率呈报口径**：发版线覆盖率随升级率爬坡、按 app_version 如实呈报，不并入引擎线 2 周灰度承诺；降级入口清单逐条呈报（§9.5/§9.6）。

## 9. 页面流转

### 9.1 流转图

```
宿主 COOLFLY App（原生）
├── 设备页 「Support」──────────────┐
├── 我的页 「Support」──────────────┤ entry_source=固定入口
├── 掉线提示 「Get help」───────────┤
├── 配对失败页 「Get help」─────────┤ entry_source=错误态入口
├── 扫码失败页 「Get help」─────────┤ （+错误上下文类型）
│                                   ▼
│                    [RN] 客服对话页（PAGE-F01-01）
│                      ├─ 固定入口/降级 → 首屏按钮组 + 自由输入
│                      └─ 携带上下文 → 开场确认 → 确认进 F02 / 否认回首屏
└── push 通知（目标态回复）──点击──→ 回到对话页同一会话
```

### 9.2 与其他模块的关系

- **关联**：客服对话页（PAGE-F01-01，唯一去向，开场确认与路由在其内执行）；转人工确认面板（PAGE-F03-01，消费注入的 SN/型号进摘要，push 权限与等待承诺在其范围）；内部效果看板页（PAGE-F06-01，消费 entry_source/app_version 做分层呈报）。
- **隔离**：与宿主 App 其他业务功能（设备控制、会员购买等）无耦合；本规格不触碰宿主既有错误提示的文案与逻辑，只在其旁增设按钮。

### 9.3 扩展预案

| 扩展方向 | 触发条件 | 改造点 |
| :--- | :--- | :--- |
| 阶段二语音渠道（PAGE-F01-02 planned） | MVP 引擎渠道无关约束保持、语音适配层立项 | 复用同一桥接契约，仅增补语音相关字段/枚举，不改既有字段义 |
| 错误态覆盖扩容（三类之外） | G2 错误态清单查证 + 错误码治理逐态就绪 | 新错误态按同一"结构化→携带上下文 / 未结构化→通用进入"规则接入，逐条更新覆盖清单 |
| 全渠道接入（PAGE-F01-03 planned） | 各渠道适配层逐个立项 | 引擎渠道无关（§3.7-1）；本契约作为 App 渠道的适配层实例沉淀 |

## 10. 数据需求

### 10.1 集成点需要什么数据

| 数据 | 来源 | 用途 |
| :--- | :--- | :--- |
| 宿主登录态（用户标识/凭证） | 宿主 App 会话 | 注入 RN 容器，引擎校验身份 |
| 当前设备 SN / 型号 | 宿主设备上下文 | 注入供排障与转人工摘要引用 |
| 结构化错误码 | 宿主错误态（G2 查证就绪的部分） | 映射错误上下文类型，驱动开场确认 |
| push payload 中的会话标识 | push 基建（目标态） | 深链定位回同一会话 |

### 10.2 集成点提交什么数据

| 数据 | 触发时机 | 用途 |
| :--- | :--- | :--- |
| 注入字段六项（8.1 契约表） | 用户点击任一入口打开 RN 容器时 | 对话页首屏路由 + 转人工摘要 + 埋点分层 |
| 入口点击埋点（含 entry_source、app_version，channel 默认 app） | 入口点击 | 看板分层呈报与覆盖率爬坡监控（§4.2 概念 schema） |

### 10.3 明确排除的数据

- 不注入密码类敏感信息（AI 不索取密码，§4.5/§7.7 红线；契约中无任何密码字段）
- 不注入设备运行日志/诊断数据（阶段二 F02 设备诊断的依赖，方案商接口目前不存在，PAGE-F02-01 planned，当前不预埋）
- 不注入用户详细资料（对话所需身份仅凭证 + 标识；其余引擎侧按需获取）

### 11.2 体验验收

| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| U-01 | 触控目标 | 固定入口与错误态 "Get help" 按钮 ≥44pt |

### 11.3 安全验收（产品层）

| 编号 | 验收点 | 通过标准 |
| :--- | :--- | :--- |
| S-01 | 凭证传递通道 | 用户凭证仅经桥接注入传递，不出现在 URL/深链参数明文中，不落不安全持久存储 |
| S-02 | 服务端校验 | 引擎 API 对每次会话请求校验宿主签发凭证，不信任客户端自声明身份 |
| S-03 | 上下文不含敏感信息 | 注入的错误上下文仅为类型枚举 + 设备标识，不含密码类信息（§4.5 红线） |
| S-04 | 深链参数最小化 | push 深链只携带定位会话所需标识，不携带会话内容明文 |
| S-05 | 数据不伪造 | entry_source/app_version 缺失时如实归"未知"桶，不补造字段值污染分层数据 |
| S-06 | 契约变更受控 | 桥接契约变更仅允许增补（新字段/新枚举值），不改既有字段语义——防旧版本客户端被新契约击穿 |
