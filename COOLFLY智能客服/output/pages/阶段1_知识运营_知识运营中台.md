## 2. 页面概述

### 2.1 一句话定位

让 RBAC 四角色在一个内部 Web 中台里完成知识的**生产（人工录入 + AI 对话挖掘）→ 统一过审 → 单向同步 Zendesk → 信号回流修订**全闭环；中台是知识唯一权威源，C 端体验全部由 Zendesk 承担，本台零 C 端界面。

### 2.2 存在理由

1. 无中台则知识散落飞书/Zendesk/客服个人口径，"每个客服一个说法"，口径事故直接流到线上（旅程 K3 的退款时限事故即此类）。
2. 无统一过审则 AI 起草与人工修改可绕过审核直接对外，政策口径（退款天数、审批额度）无人把关。
3. 无同步与 drift 治理则 Zendesk 端被直接改写后中台失去权威性，回到双源打架。
4. 无信号回流则知识"写完即死"——踩、flag、bot 转人工等信号无处沉淀，条目质量无法迭代。

### 2.3 页面目标（可衡量，口径唯一落点 PRD §8.2）

| 目标维度 | 具体指标 |
| :--- | :--- |
| 审核时效 | 提交 → 审结（通过/驳回）中位时长 ≤2 个工作日（建议值） |
| 同步成功率 | ≥99%；失败自动重试 3 次（建议值）后告警 |
| 挖掘消化率 | 候选 7 日内被处置（提交审核或丢弃）≥80%（建议值） |
| drift 处置时效 | 漂移检出 → 处置完成 ≤3 个工作日（建议值） |
| 翻译人工校验率 | 同步 Zendesk 的英文 100% 经人工校验（**铁律，非建议值**） |
| 复核按期率 | 复核到期条目按期完成复核 ≥90%（建议值） |

### 2.4 不做什么（范围边界）

- **不做**任何 C 端界面（问答对话、帮助中心、工单页）——C 端全部由 Zendesk 承担（D-10 拍板）。
- **不做**客服工作数据报表重建（工单量/首响/CSAT/人效）——Zendesk Explore 原生具备，视图⑦仅做口径说明与指向（AC-P-19）。
- **不做**飞书双向同步——飞书 120+ 篇一次性导入，此后中台为唯一权威源。
- **不做** Zendesk bot 行为配置界面——bot 配置属 Zendesk 侧运营（PRD §9.4）。
- **不做**任何绕过审核的发布路径——统一过审为铁律，本文档不得为任何角色增设直发能力。
- **不做**中台 UI 多语言切换——第一版仅简体中文资源（后置增强，文案不硬编码语言）。

### 3.2 核心使用场景（对齐 PRD §2.3 旅程 K1/K2/K3）

**场景 A · 知识生产与发布（主场景，旅程 K1）**
- 时机：条目被驳回后修改重提 → 审核 → 发布同步。
- 前置：王雯（知识管理员）登录；「会员退订与计费周期」被李骁驳回（理由：计费周期与财务口径不符，请附财务确认截图）。
- 动作：工作台「被驳回待改」看到该条 → 按意见补充财务确认与跨月退订示例 → 重新提交 → 李骁在审核中心看到重提条目与完整审核历史 → 通过 → 发布门禁三查全过 → 入同步队列 → 几分钟后帮助中心「会员计费」Section 文章更新、客服 Knowledge 面板同步可见；全程写操作日志。
- 情绪：驳回不挫败（理由具体可改），发布有确定感（门禁清单可见）。

**场景 B · AI 对话挖掘沉淀（主场景，旅程 K2）**
- 时机：每日批次自动拉取昨日 Zendesk 会话后。
- 前置：08-04 批次：37 个会话 → 6 条候选（邮件工单 21 · 在线聊天 16）。
- 动作：王雯打开 AI 对话挖掘 → 「喂鸟器在极寒天气下自动关机」频次 17 次/周、查重 0.42、缺口=未覆盖，三重准入通过 → 点「起草并提交审核」，AI 起草稿进审核中心；「太阳能板阴天充不满电」查重 0.88 ≥0.85（理由「均在描述阴天/弱光下太阳能板充电不足，KB-0155 已覆盖同一现象与处理步骤」）→ 不新建，「挂为 KB-0155 修订建议」。
- 情绪：候选证据齐全（频次/查重值与判定理由/缺口可见），处置一键到位且判定理由可复核。

**场景 C · 反馈回流修订与回滚（兜底场景，旅程 K3）**
- 时机：新版本上线后效果骤降。
- 前置：「退款政策」v2（退款 5 天）被踩 11 次、bot 引用后 18 次转人工；版本对比 v2 解决率 70% vs v1 的 90%。
- 动作：陈迪（AI 运营，只读）在反馈回流/数据看板发现 → 提交优化建议（建议回滚 v1）进审核队列 → 李骁比对 v1↔v2 diff → 确认回滚 → v1 重新生效、v2 标「已回滚」、历史指标保留、写日志并入同步队列 → Zendesk 文章同步回旧口径。
- 情绪：只读角色不越权也能推动修正；回滚后果弹窗列明，不慌。

**场景 D · drift 处置（兜底场景）**
- 时机：drift 周期检测发现 Zendesk 端文章被绕过中台直接修改。
- 前置：同步中心报警「检测到 2 篇文章在 Zendesk 端被直接修改（内容漂移）」（退款政策第 2 段被改写 · 08-03 21:40）。
- 动作：李骁二选一处置——以本台内容覆盖（Zendesk 端修改丢弃，留痕）或拉回进审核队列（作为待审来源）；两动作均写审计日志。
- 情绪：权威源不失守，处置路径明确。

### 3.3 用户核心诉求（优先级排序）

1. **口径不出事**：任何内容变更过审才生效，政策数字不被静默改掉。
2. **闭环推得动**：候选/驳回/失败都有明确下一步动作，不留死角。
3. **失败看得见**：同步失败、批次失败、翻译失败如实标注，不静默吞错。
4. **权责分明**：每个角色只能做矩阵允许的事，越权被禁用且有原因说明。
5. **可追责**：所有关键动作字段级留痕，可回查"谁改的、改了什么"。

## 5. 界面内容（十视图逐区；元素引用原型真实结构与示例数据语义，不复制全部数据）

### 5.1 视图① 我的工作台

- **四统计卡**：我的草稿 / 我提交待审 / 被驳回待改 / 待我审核——按当前账号与角色实时计数；「待我审核」含 AI 挖掘与人工提交合计；无审核权限角色显示「（无审核权限）」说明而非空报错。点卡片切换对应分组列表。
- **分组列表（四 tab，默认「我的草稿箱」）**：列 = 条目/状态/中英文状态/最近操作/**下一步动作**。下一步动作按状态与角色计算：草稿·编辑中→「继续编辑」；待审核→有审核权「去审核」、无审核权「查看进度」；已驳回→「按意见修改」（原型 nextOf 逻辑）。点行进入条目工作台对应条目。
- **新建条目按钮**（主按钮，常驻）：进入条目工作台新建草稿；无新建权限角色（AI 运营/系统管理员）禁用并说明。
- 空分组引导文案：如「当前角色没有待审任务（审核权限仅知识审核员）」。
- 数据语义（原型示例）：王雯的被驳回待改含 KB-0240「会员退订与计费周期」（带李骁驳回理由）。

### 5.2 视图② 知识库总览

- **知识库切换卡**（原型 LIBS）：政策与售后知识库 38 条（退款/退货/保修口径 · 含仅内部条目）/ 产品与使用知识库 46 条 / 客服话术库（仅内部）12 条——仅内部库带「不对外公开，仅挂客服 segment」说明。
- **结构树**（原型 TREE，**三级折叠树**：目录→章节→条目，UX/UI 以 v3 原型为准）：卡头副标「目录 → 章节 → 条目」+「仅已发布」徽章；顶部结构操作工具条（新建目录 / 新建章节 / 调整层级）；树体逐级缩进——目录行（caret + 文件夹图标 + 名称 + 右侧条目计数，如 售后政策 18）→ 章节行（caret + 名称 + 右侧 Zendesk 映射标识如 Sec 5101）→ 条目行（文档图标 + 标题，过长省略号截断，如 退款政策 / 退货运费承担规则）；行 hover 高亮，逐级可折叠展开；点条目进条目工作台、点章节筛选右侧条目列表。**重命名/删除**随行 hover 或选中显示（不常驻，防按钮换行挤压行宽）；无「管理目录与章节」权限时工具条与行内操作隐藏。**「调整层级」**：选中章节后弹窗选择目标目录，确认即改所属目录（结构深度恒为 2，不支持目录与章节互转；目标目录须为顶级目录）；变更即时生效并留痕，Zendesk 端 Section **实时同步**移动到目标 Category（08-05-2026：结构只在本台维护并直连同步，不再经同步中心批处理）。
- **结构映射说明条**（常驻只读）：「映射 Zendesk：知识库 → Help Center brand、目录 → Category、章节 → Section、条目 → Article、条目内锚点 → 文章内 anchor」（映射规则唯一落点 PRD §4.1）。
- **条目列表**（原型 ENTRIES，12 列）：标识/标题/路径/类型/可见性/版本/状态/英文状态/同步状态/解决率/复核到期/更新时间；按更新时间降序；低解决率标红（如 KB-0155 41%）；复核超期标红（KB-0240「复核已到期 12 天」）、临期标黄（KB-0188「剩 47 天」）。
- **搜索与筛选**：搜索框 + 筛选器（场景/状态/可见性/复核到期：全部/已到期/30 天内到期），即时过滤并标注归属路径。
- **一键批量导入**（有「新建/编辑知识条目」权限可见，08-05-2026 新增）：知识库卡片区右上「一键批量导入」按钮 → 三步面板。①**输入**：粘贴文档或选择 `.md`/`.txt` 文件；②**解析并预览**：按 `#`/`##`/`###` 标题切条目（一个标题 = 一条条目，标题下段落即正文、空行分段），`内部：`/`内部:`/`【内部】` 开头的段落自动标为内部段落且该条目可见性自动建议「对外公开 + 内部段落」；预览表逐条可改 标题 / 落点章节 / 可见性，并显示段落数与内部段数；预览区「AI 整理建议」按钮（08-05-2026 补齐，原 `suggestLabels` 定义了但全仓零调用）——一键请求 LLM 回填每条的 标签（≤5 个）/两级问题场景/章节归类 建议，逐条可改可忽略，建议态不强制采纳；LLM 不可用时标「AI 建议未生效」；③**一键导入**：二次确认后提交，结果分「成功条目清单」与「失败行号 + 原因」如实展示。**导入产物全部进审核队列（来源「批量导入」），无绕过审核的入库路径**；超过单次上限时拦截并提示拆分。
- **章节管理**（有「管理目录与章节」权限可见）：新建目录/章节、重命名、删除、调整层级（改所属目录）；变更即时反映并留痕，**实时同步 Zendesk**（新建目录→建 Category、新建章节→建 Section，挂接字段留空自动创建、填 id 挂接既有结构；改名/移动同步；08-05-2026 拍板：结构只在本台维护）；**含条目的章节不可直接删除（先移空）**，Zendesk 端 Section 仍有文章 / Category 仍有 Section 时同样拒绝删除（防连带删除线上文章）；无权限禁用。

### 5.3 视图③ 条目工作台

- **状态流转条**：草稿→编辑中→待审核→审核中→审核通过→已发布（异常支线：已驳回/已下线），当前态高亮、已过态打勾，旁附最近操作人与时间。
- **操作按钮**：保存中文草稿 / 提交审核 / 发布并同步 / **下线**——按权限矩阵与当前状态禁用；知识管理员「发布并同步」与「下线」**恒禁用**并提示统一过审铁律文案（文案定稿见 PRD §5.10）。
- **下线**（08-05-2026 补齐入口，仅知识审核员 + 仅「已发布」态）：二次确认弹窗列明四条后果——①置「已下线」但**不是删除**；②Zendesk 端归档 + 重定向不裸删，帮助中心不留死链；③版本历史、各版效果指标、审计日志全部保留可查；④重新编辑（自动回「编辑中」）→ 提交审核 → 通过 → 发布即再次上架。确认后写「归档 + 重定向」同步任务，同步中心可见。
- **门禁提示条**：实时显示阻断原因（英文未确认 / 英文标题缺失）或「门禁通过：正文已保存、英文已确认，可发布并同步。」（原型 gateMsg 三态：无发布权琥珀提示 / 阻断红 / 通过绿）。
- **页签 1 · 知识正文**：
  - **双语富文本编辑器**（08-05-2026 改版，取代原段落级纯文本编辑器）：**左中文（权威源）/ 右英文（同步 Zendesk）同屏逐行对齐**，一行 = 一个段落——之所以逐行而不是整块双栏，是因为内部段落标记与翻译对都是**段落级**，右栏必须和左栏同一段严格对齐。左格为 TipTap 富文本（加粗/斜体/删除线、H2/H3、有序与无序列表、引用块、图片）；行内标记存 `paragraph.html`，纯文本存 `paragraph.text`（版本 diff / 翻译 / 搜索 / drift 哈希的基准），`heading` 由块类型派生。
  - **共享工具条**：B / I / S｜H2 / H3｜列表 / 引用 / 图片｜**标为内部段落**｜上移 / 下移 / 删除段落 / + 新增段落。光标停在哪一段，工具条就作用于哪一段；移动段落后焦点跟随，工具条不失活。原「内部段落」「小标题」两个勾选框**已取消**——小标题由 H2/H3 承担；内部段落改为块级标记按钮，标记本身不可取消（可见性三档、发布门禁第②查、翻译剥离与内部口径零外泄全部以它为唯一承载）。内部段落行整行标琥珀色 + 角标「内部」，右格显示「内部段落不翻译、不同步到对外帮助中心」。
  - **标题中英对照卡**：标题不是段落进不了逐段对照，单独成卡（中文标题 / 英文标题 + 修订说明 + 保存）；英文标题缺失即阻断同步。只读角色（AI 运营）编辑器锁定并明示「只读模式」，任何编辑操作触发提示「当前角色（AI 运营）对编辑器只读，无法修改内容。」
  - 字段侧栏（对齐 PRD §4.1）：所属知识库/目录章节/两级问题场景（一级五类：售后与退款/安装与配网/设备使用/会员与账户/订单与物流 + 二级）/标签·同步 Zendesk labels/可见性三档/适用型号/复核周期/负责人。
  - **中英双语对照**：**标题对照卡**（实现回写 08-05：中文标题 / 英文标题输入框 + 修订说明 + 「保存英文标题」，英文标题为空时标红徽章「英文标题缺失 · 同步阻断」）——英文标题若缺失，Zendesk 的 en-us 译文会挂中文标题给英文用户看，故与正文同受人工校验约束；标题不是段落、进不了逐段对照，故独立成卡置于正文编辑区上方（实现回写 08-05：原挂在「英文视图」内，双语改为左右分栏后单列为 `EnTitleCard`）。卡下为正文逐段中英对照（原型 PAIRS），人工修订段落带修订标注（示例：「人工把 buyer's remorse 改为 change of mind，更贴近北美用户表述（陈迪 08-01）」）；内部段落显示「内部段落不翻译、不同步到对外帮助中心」。英文操作：生成/重新翻译、标记已确认、同步到 Zendesk——按钮随英文状态机与权限启停（「已确认」前同步禁用）。
  - **AI 摘要面板**（08-05-2026 取代原向量状态面板）：摘要正文（2–3 句中文）+ 生成时间 + 来源徽章（AI 生成 / 人工校正）+ 用途说明「只服务本台内部：AI 对话挖掘做语义查重的比对基准，与 Zendesk AI 索引无关」+ 「编辑摘要」按钮。摘要在条目**发布时**由 LLM 生成；人工改写后标「人工校正」，后续发布不再被 AI 覆盖；未发布过的条目显示「本条目尚未发布，摘要将在首次发布时生成」；LLM 不可用时保留上次摘要并如实标注生成失败，不阻塞发布。
- **页签 2 · 版本与回滚**（原型 VERSIONS/DIFF）：
  - 版本列表：版本号/变更说明/状态/生效区间/操作人/调用/命中率/解决率/采纳率（示例：v1 退款 7 天·解决率 90%·历史版本；v2 退款 5 天·70%·已发布；v3 补充跨境订单·待审核）。
  - 任选两版**对比 diff**：左右并排，删除行红底、新增行绿底（示例：「签收后 7 天内可退」→「签收后 5 天内可退」）。
  - **回滚建议条**：当前发布版解决率较历史版下降 ≥15pp（建议值·终稿前确认）时给出建议（示例文案见 PRD §5.10）。
  - **回滚**（仅审核员）：确认弹窗列明后果（目标版重新生效、当前版标「已回滚」、写入操作日志与同步队列、历史版本与指标不删除），确认后自动同步 Zendesk。
- **页签 3 · 效果指标**：当前版本四卡（调用次数/命中率/解决率·近似归因标注/采纳率）+ 各版本解决率对比条形 + 条目级反馈信号列表（文章被踩/bot 未解决转人工/客服 flag/文章投票，含原文摘录与次数）。
- **页签 4 · 操作日志**：本条目全量留痕时间线（含字段级前后值），数据面同 PRD §4.5。

### 5.4 视图④ AI 对话挖掘

- **抓取批次列表**（原型 BATCHES）：批次卡 = 抓取日期、来源会话数分渠道（「邮件工单 21 · 在线聊天 16」）、候选数、状态（完成/无新草稿/失败）；按日期降序。空批次示例「08-02 批次：无新候选 · 均未达频次阈值，如实标注」；失败批次示例「08-01 批次：拉取失败 · Zendesk API 429 限流 · 次日照常拉取」。点批次查看该批候选。**主题来源**（08-05-2026 修复）：由 LLM 依脱敏后的**真实**工单/聊天正文归纳合并主题与命中会话数，不使用固定演示样例——原实现只取会话计数、主题恒定输出 3 条固定样例，即使配上 Zendesk 凭据也不会变化，本轮已修复。
- **三重准入说明条**（常驻）：「沉淀判断三重准入：①频次达阈值 ②LLM 语义查重 ③缺口判定」；LLM 不可用时追加「语义查重未生效——当前按字面相似度粗判，结果仅供参考」。
- **候选卡**（原型 CANDIDATES）：类型徽章（新增/修订/合并）+ 标题 + 来源会话与渠道分布 + 频次 + 查重值 + **查重判定理由**（LLM 给出的自然语言理由 + 比中的条目标识，供审核员复核改判）+ 缺口判定 + AI 摘要 + 准入结论。查重 ≥0.85 高亮并注明「不新建，挂修订」（示例：太阳能板 0.88，理由「均在描述阴天/弱光下太阳能板充电不足，KB-0155 已覆盖同一现象与处理步骤」）；合并类注明「合并后另一条 Zendesk 归档并重定向」（示例：两条 Wi-Fi 配对条目 0.91）。
- **查重实现口径**（08-05-2026 变更，技术方案 §6.2）：两段式——先按 问题场景 + 标签交集 + 标题字面相似度 粗筛至多 5 条既有已发布条目，再把候选主题与来源摘要连同这些条目的 **AI 摘要** 交 LLM 判定，输出 `{条目标识, 相似度, 理由}` 取最高分；判定结果一次定分落库不重算（防 LLM 打分抖动使判定在阈值两侧翻转）。
- **候选处置按钮**（按类型）：起草并提交审核 / 挂为修订建议 / 发起合并（进审核）；次操作：丢弃（留痕，提示「已丢弃候选（留痕）：同主题再达阈值会重新出现」）。无提交权限角色降级为「提交优化建议」；AI 服务不可用时批次标失败、人工流程照常。**无任何候选直接入库路径。**

### 5.5 视图⑤ 审核中心

- **待审队列**（原型 QUEUE 四来源示例）：来源徽章（AI 挖掘·新增 / 人工录入 / 版本修订 / 反馈修订）+ 标题/频次/归属章节与建议可见性/版本说明/提交人/提交时间；待审计数在导航常驻可见并随提交实时 +1；按提交时间排序、AI 挖掘候选附频次。**点开即认领**（08-05-2026 补齐：条目状态「待审核」→「审核中」，附认领人与时间，其他审核员可见谁在审避免重复劳动；重复打开已认领条目不报错，原「审核中」态此前虽在状态机内合法但无任何入口可达）。
- **审核详情 · 变更摘要（第一层）**：只给大概摘要——一行总览（如「正文 3 处改动 · 字段 2 处改动」；新建条目为「新建条目 · 5 个段落」）+ 逐项一句话概述（如「退款时限：签收日起算 → 清关日起算」「新增段落：跨境订单说明」），不展开全文；另附正文全文 + 来源与频次证据。
- **审核详情 · 具体变更（第二层 · git diff 视图）**：点「查看具体变更」展开——按段落切分对齐的统一 diff：删除行 `-` 红底、新增行 `+` 绿底、未变更上下文行灰字且默认折叠（前后各留 1 行，可「展开全部」）；行首带变更前/变更后行号槽；字段变更以同形态键值行呈现；内部段落带「内部段落」标记。新建条目无「变更前」侧，diff 全为新增行。可「收起」回摘要层。
- **审核操作**：通过/驳回双按钮 + 门禁说明（「通过后自动跑发布门禁：静态检查 + 英文校验状态，全过才入同步队列」）。仅审核员可操作，其余角色「只能查看，不能通过或驳回」；**审核员可审核自己提交的条目**（原四眼原则 08-05-2026 取消，通过按钮不因提交人=本人而禁用；该次审核照常写审计日志，提交人与审核人同为一人的事实可查）。
- **驳回弹窗**：理由必填（输入占位「例如：计费周期与财务口径不符，请附财务确认截图」；空理由不可提交，校验提示「驳回理由必填——审核意见会回传给提交人并留痕。」）；确认后条目回提交人草稿箱、状态「已驳回」。
- **审核历史**：每条目时间线（驳回/重新提交/发布记录及理由，示例：李骁驳回→王雯重提「已补充财务确认截图与跨月退订示例」）。
- **发布门禁结果**（**三查清单**，08-05-2026 由四查收敛）：①格式与字段完整性（标题/章节/可见性/锚点/标签已填）②敏感信息与内部口径（内部段落已标记，不会进对外文章）③英文版本状态（未确认则同步将被阻断）。通过项打勾、警示项标黄；任一硬项不过→不入同步队列并展示原因。原第④查「代理评测」随向量能力删除退役，门禁与界面不再出现任何检索代理指标。

> **数据来源（08-05-2026 四轮补记）**：本视图三页签的统计**一律从工单快照 `zendesk_tickets` 重算**得出，不在拉取过程中直接写统计表（技术方案 §5.1「快照层」）。工单快照由定时增量拉取维护，游标持久化、断点续传。
>
> **口径缺陷待修（技术方案 §8.4.4 登记，本轮未修）**：①页签 1 的场景覆盖率**当前实现分母是本台已发布条目总数，不是工单场景分布**——与上文「覆盖率对照工单场景分布」的表述不符，且各场景恒加总 100%、「有工单无条目」的红条永远算不出来；修复前置=确定工单侧场景分类字段。②`bot 引用`/`agent 引用`/`客服 flag` 三列当前无有效数据来源（前者须本台埋点，中者依赖未经证实的 `KnowledgeLinked` 事件），界面应标「未接入」而非显示数值。③解决率为全库工单口径按条目分摊的近似归因，界面须标注。④搜索无结果关键词属 Zendesk Explore 能力、REST 不可得，界面须显式标「本渠道不可得」，**不得继续渲染种子假数据**。

### 5.8 视图⑧ 反馈回流

- **信号矩阵表**（原型 SIGNALS，四渠道行，数据面唯一落点 PRD §4.3）：场景/渠道/命中信号/解决信号/确定性档位——AI bot 自动回答（档位相关）、人工工单（工单必得/引用事件待核实）、用户自助浏览（投票必得/浏览待核实）、客服主动反馈（原生·必得）；档位如实标注，待核实信号核实前不进达标判定。**采集机制**（08-05-2026 补齐）：每小时自动从 Zendesk 拉取文章投票与工单解决信号写入信号事件与条目效果指标；页面右上「立即采集信号」按钮供手动补采，采集结果（成功条目数/信号数/缺口数/关键词数/场景数，含降级项）以提示条展示。原实现五张信号表只在初始化种子数据时被写入，服务端无任何采集代码，本轮已补齐。
- **修订候选队列（五来源）**（原型 REVISIONS）：来源徽章（客服 flag / 文章被踩 / bot 未解决 / 高频无覆盖 / 搜索无结果）+ 条目或主题 + 信号摘要与次数（示例：退款政策 v2 踩 11 次「5 天太短，与页面标注不一致」）+ 动作按钮「转为修订建议」（**统一单入口**：候选带条目→该条目进审核队列；候选无条目→服务端起草新条目再进队列；改标题与 labels 走条目工作台编辑后提交。全部进审核队列，来源标注「反馈修订」）；已处置候选显示处置徽章、不再提供动作。无 `suggestion.submit` 权限时按钮禁用并展示越权文案。
- 权限说明：AI 运营可提交建议（进审核队列），不可直接改库；处置动作全部留痕。

### 5.9 视图⑨ 操作日志

- **全量审计流**（原型 LOGS，schema PRD §4.5）：时间线行 = 时间/操作人（角色）/对象/动作徽章/字段级前后值（示例：「退款时限：7 天 → 5 天」「发布权限：允许 → 禁止」）/备注（含驳回理由、来源标注）。
- **四页签过滤**：全部 / 内容变更（保存/创建版本/修订/翻译/丢弃/拉回）/ 审核与发布（提交/通过/驳回/发布/回滚/同步）/ 权限与系统（角色/用户/启停）。
- 约束：只增不改不删、长期保留；知识审核员与系统管理员可查全量，其余角色可查与己相关记录（细则「建议值·终稿前确认」）。

### 5.10 视图⑩ 用户与权限（三页签）

1. **用户管理**（原型 USERS）：用户列表（姓名/邮箱/角色/知识库范围（全部或指定库，可授单库；只读范围如「只读 · 政策与售后」）/最后活跃/启用状态）；创建用户（仅系统管理员）：必须选择角色与权限范围，保存写审计日志，首次登录强制改密（账号体系=真实账号，建议值 邮箱+密码邀请制·终稿前确认）；禁用用户：会话即时失效、历史留痕保留、可再启用（提示「已禁用 {姓名}（会话即时失效，历史留痕保留）」）。
2. **角色管理**：四角色卡（人数/允许清单/禁止清单/角色定位说明——定稿文案见 PRD §5.10 视图⑩）。
3. **权限矩阵**：10 项 × 4 角色矩阵（见 §6.2 本文档）；仅系统管理员可点格修改，修改即写审计日志（toast「已更新权限矩阵（改动已写审计日志）」）；其余角色只读并提示「权限矩阵仅系统管理员可修改」。

### 5.11 辅助信息

- 顶栏常驻：当前视图标题、面包屑、当前用户与角色标识（如「王雯 · 知识管理员」）。原型的角色切换器为演示装置；真实系统中角色来自登录账号，不提供界面内切换。
- 全局 toast：动作反馈与越权提示统一以轻提示呈现（原型 say 机制，约 3.6s 自动消失）。
- 全部界面文案定稿唯一落点 = PRD §5.10 文案定稿表；本文档引用不复制。

角色切换（或以不同角色账号登录）后的界面差异（原型 perms 门控逐条对应）：

- **知识管理员**：「发布并同步」「回滚」「审核通过/驳回」「同步重试」「drift 覆盖」全部禁用并说明（如「发布权限仅知识审核员。」）；编辑/提交/章节管理/挖掘候选处置可用。

- **系统管理员**：仅用户与权限三页签 + 全量审计日志 + 查看数据可用；一切内容操作（含提交建议）禁用——管人不管内容。
- 权限变更即时生效：矩阵被修改后相关角色界面即时反映；被禁用账号会话即时失效。

### 6.3 核心操作流程

```
【生产→发布主链】
知识管理员 新建/编辑条目（保存中文草稿）
    │  中文变更联动：英文置「待重新校验」+ 同步阻断；已发布条目状态→「编辑中」
    ▼
提交审核 → 审核中心待审 +1（来源标注：人工录入/批量导入/AI 挖掘/版本修订/反馈修订）
    │
    ├─ 审核员驳回 → 理由必填弹窗（空理由不可提交）→ 条目回提交人草稿箱，状态「已驳回」，理由写审核历史
    │       └─ 提交人按意见修改 → 重新提交（审核历史含完整往返）
    │
    └─ 审核员通过（可自审，全程留痕）→ 发布门禁三查
            ├─ 任一硬项不过 → 阻断并展示原因（不入同步队列）
            └─ 全过 → 入同步队列 → 按可见性同步 Zendesk（对外文章 / 仅客服 segment / 混合剥离内部段落）
                    ├─ 成功 → 「已同步」
                    └─ 失败 → 自动重试（建议值 3 次）→ 告警 + 失败置顶 + 手动重试（仅审核员）

【挖掘链】每日批次拉取 Zendesk 会话 → 三重准入 → 新增/修订/合并候选 → 处置（起草提交审核/挂修订/发起合并/丢弃留痕）→ 全部进审核中心

【回流链】四渠道信号 → 五来源修订候选 → 转为建议/起草/改标题 labels → 审核队列（来源「反馈修订」）

【回滚链】版本页 diff 对比 + 回滚建议条 → 审核员确认弹窗（列明后果）→ 旧版重新生效、原版标「已回滚」、指标保留、写日志、自动入同步队列

【drift 链】周期检测（建议值 每小时）→ 漂移报警 → 审核员二选一：以本台覆盖（留痕）/ 拉回进审核队列
```

### 6.4 翻译工作流（条目工作台/同步中心横切）

- 状态机：未生成 → AI 翻译中 → 待人工校验 → 已确认 → 已同步（异常：翻译失败 / 待重新校验）。
- 铁律：①「已确认」前「同步到 Zendesk」禁用（人工校验后才同步，100%）；②中文变更即英文置「待重新校验」并阻断同步（提示「中文已变更 → 英文置为待重新校验，同步阻断」）；③英文允许人工独立修改表述但不得改变政策口径，修订留痕（原型 PAIRS 修订标注）；④内部段落不翻译、不同步；⑤翻译失败保留上一次英文内容、同步阻断、可重试，连续失败（建议值 3 次）告警。

### 6.5 辅助操作

- 统计卡/导航徽标点击 = 过滤直达（工作台四卡→分组列表；同步四卡→过滤任务列表）。
- 数据看板条目行 → 条目工作台效果页签直达；「去知识缺口」页签间直达。
- 危险动作（发布/回滚/drift 覆盖/驳回/禁用用户）一律二次确认弹窗并列明后果。

## 7. 状态与边界

### 7.1 页面状态全景（中台侧运营可见，对齐 PRD §7.1）

| 状态 | 触发条件 | 页面表现 | 出路 |
| :--- | :--- | :--- | :--- |
| 初始态 | 登录进入 | 视图①工作台，四卡按账号计数 | — |
| 编辑态 | 正文/字段变更 | 中文脏标记；英文→「待重新校验」、已发布条目→「编辑中」 | 保存草稿/提交审核 |
| 待审态 | 提交审核后 | 审核中心待审 +1，来源徽章可辨；提交人侧「查看进度」 | 通过/驳回 |
| 驳回态 | 审核员驳回（理由必填） | 条目回草稿箱标「已驳回」，理由在工作台与审核历史可见 | 按意见修改重提 |
| 门禁阻断态 | 三查任一硬项不过（如英文未确认） | 不入同步队列，阻断原因可见 | 完成整改后自动恢复入队 |
| 同步失败态 | Zendesk 接口异常/限流 | 失败置顶+原因；Zendesk 端上一版继续服务 | 自动重试（建议值 3 次）→告警→手动重试（仅审核员） |
| 同步阻断态 | 英文未校验/条目被驳回 | 状态「已阻断」+原因可见；不存在「阻断但已同步」中间态 | 完成校验/过审后恢复 |

| AI 摘要未生成/生成失败态 | 条目未发布过 / LLM 不可用 | 面板标注来源与状态；挖掘候选卡标「语义查重未生效」（会漏判重复建条，界面明示） | 下次发布时重新生成；不阻塞发布与人工流程 |
| 批次失败态 | Zendesk API 拉取失败（如 429） | 批次标「失败」+原因，不产生候选，无静默缺批次 | 次日照常拉取；人工录入不受影响 |
| 空批次态 | 会话均未达频次阈值 | 「无新候选：均未达频次阈值，如实标注」 | — |
| 样本积累态 | 条目引用数低于样本下限（建议值 10 次） | 效果列显示「样本积累中」，不显示误导性数值 | 样本达标后显示 |
| 复核三档态 | 复核周期计时 | 正常（倒计时，如「剩 114 天」）/ 临期标黄（30 天内，如「剩 47 天」）/ 超期标红（如「复核已到期 12 天」），可被「已到期/30 天内到期」筛选命中 | 完成复核后重新起算 |
| drift 报警态 | 检测到 Zendesk 端被直接修改 | 同步中心显著警示卡（文章/修改方/差异摘要/时间） | 覆盖或拉回（仅审核员，均留痕） |
| 权限拒绝态 | 越权操作 | 按钮置灰/禁用+原因说明，或明确拒绝 toast；导航无权视图置灰 | 走有权限角色流程（如提交建议代替直接修改） |
| AI 不可用态 | LLM 故障 | 建议卡隐藏并明示；人工路径全部照常 | 恢复后自动可用 |
| 账号禁用态 | 系统管理员禁用 | 会话即时失效；历史留痕保留 | 重新启用后恢复 |

### 7.2 边界与容错（对齐 PRD §5.10 异常场景 / §7.2）

| 边界场景 | 处理策略 |
| :--- | :--- |
| 并发编辑同一条目 | 后提交者收到冲突提示，改动不覆盖线上；基于最新版本重做，修订历史可回溯，不静默覆盖 |
| drift 与本台待发版本冲突 | 先处置 drift（覆盖或拉回）再放行同步，防相互覆盖丢内容 |
| 批量导入部分失败 | 成功条目进审核队列；失败条目逐条报告行号与原因，不整批静默失败 |
| Zendesk 限流（429） | 挖掘批次失败如实标注次日重拉；同步按重试策略退避；初始迁移 120+ 篇分批推送避开峰值（节奏建议值·终稿前确认） |
| 鉴权失效/权限不足 | 失败原因显式区分「凭据失效」，告警指向 owner（内部技术团队） |
| 结构映射失败（目标 Section 不存在/被删） | 同步失败并提示先在章节管理修复映射；结构由本台维护并同步，条目同步器不代建结构 |
| 含条目章节删除 | 不允许直接删除，须先移空（防孤儿条目） |
| 审核队列积压 | 候选按频次降序保持可操作；积压不影响已发布条目正常服务 |
| 信号待核实 | bot 锚点引用、面板引用、浏览行为等待核实信号核实前标「待核实」，不编造数据、不进达标判定 |
| 内部段落泄漏防线 | 发布门禁第②查强制核验内部段落标记；同步器按可见性拆分——任何「仅内部」内容不出现在对外文章与英文翻译中 |
| 下线条目 | Zendesk 端归档 + 重定向，不裸删 |
| 失败态总原则（写死） | 如实标注 + 保留上次可用内容 + 提供重试路径，不静默吞错、不带病上线 |

| 英文状态 | 未生成/AI 翻译中/待人工校验/已确认/已同步 Zendesk/翻译失败/待重新校验 |
| 同步状态 | 未同步/待同步/同步中/已同步/失败/已阻断/已归档 |
| AI 摘要 | 摘要正文 + 生成时间 + 来源（AI 生成 / 人工校正）；只服务本台内部（挖掘语义查重比对基准） |
| 审核信息 | 来源（AI 挖掘/人工录入/版本修订/反馈修订/批量导入）+ 提交人/时间 + 审核人/时间 + 驳回理由（必填留痕） |
| 审计日志行 | 时间/操作人+角色/对象/动作/字段级前后值/备注；只增不改不删 |

### 8.2 校验规则

| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 驳回理由必填 | 驳回确认时 | 理由为空不可提交 | 「驳回理由必填——审核意见会回传给提交人并留痕。」（弹窗内红显） |
| 发布门禁三查 | 审核通过后自动 | ①格式字段完整 ②内部段落标记 ③英文版本状态 | 任一硬项不过→不入同步队列并展示原因 |
| 英文同步前置 | 触发同步时 | 英文非「已确认」→同步阻断 | 阻断原因可见（如「英文待校验」） |
| 权限门控 | 全部动作 | 按 10×4 矩阵逐项判定 | 按钮禁用+原因说明，或明确拒绝提示 |
| 创建用户必填 | 保存用户时 | 必须选择角色与知识库范围 | 校验拦截；保存写审计日志 |
| 章节删除保护 | 删除章节时 | 含条目章节不可直接删除 | 提示先移空 |

### 8.3 特殊业务规则

- **统一过审铁律**：全部新条目/修订/挖掘候选/优化建议一律经审核中心，人工审核通过并过发布门禁后才生效同步；任何角色无绕过审核的发布路径。
- **单向同步**：中台→Zendesk 单向，Zendesk 端不是编辑入口；被直接改写=drift，报警处置。
- **中文权威**：结构/字段/口径以中文为准；英文人工校验率 100%（铁律）。
- **边界数值全部为「建议值·终稿前确认」**（唯一落点 PRD §5.10 边界数值节，本文档引用不复制不另造）：查重挂修订线 ≥0.85（v3 定稿）、查重粗筛上限 5 条既有条目（08-05-2026 定）、频次准入 ≥10 次/周、同步重试 3 次、翻译连败告警 3 次、复核周期 180 天（可选 90/365）、临期提醒 30 天、回滚建议线 ≥15pp、样本下限 10 次、低解决率标红线 60%、drift 扫描每小时、标签 ≤20 个、批量导入单文件 ≤500 条。
