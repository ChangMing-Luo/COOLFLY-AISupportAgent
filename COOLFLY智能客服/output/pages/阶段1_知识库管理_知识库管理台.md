## 2. 页面概述

### 2.1 一句话定位

知识库内容运营在此完成知识条目的录入、导入、AI 辅助整理、审核与发布——管理台是知识库的**唯一权威源**（飞书 120+ 篇一次性导入后不做双向同步），未经此处审核并通过发布门禁的内容，永远不会出现在 App 用户的回答里（US-F09-01/02/03）。

### 2.2 存在理由

1. 无管理台则飞书 120+ 篇存量文档无法结构化为可检索条目，F01 命中率目标（§8）失去内容供给侧支撑；条目的录入、修订、审核、发布无统一落点，口径分叉（这正是拍板"不做双向同步"要防的问题）。
2. 无审核队列则 F05 回流闭环断在"消化"环节——AI 聚类起草的草稿没有人工审核工作面，「无人审不生效」铁律（AC-M-15）无执行载体，周消化 Top 10 SLA（§5.6）无法落地。
3. 无发布门禁界面则评测集回归（§4.3 F09 条目发布门禁 🟩）的结果无处留痕呈现，"回归失败但条目已上线"的中间态无法被排除（AC-E-14）。

### 2.3 页面目标（可衡量）

| 目标维度 | 具体指标 |
| :--- | :--- |
| 审核铁律 | 未审核条目 100% 不进检索库、不被 F01 命中（AC-M-15） |
| 发布门禁 | 每次转入「已上线」100% 触发评测集回归且结果留痕；回归失败条目 0 生效（AC-E-14） |
| 发布时效 | 回归通过后条目生效（可被检索命中）≤24h（AC-M-13，§4.4 既有承诺） |
| AI 降级不阻塞 | AI 建议服务不可用时，人工录入/编辑/审核/发布 100% 照常可用（AC-E-13） |
| 留痕完整 | 每次修订与状态流转均有留痕（修订人/时间/变更摘要），历史版本可查（§5.10 交互逻辑 1） |
| 访问安全 | 无口令访问 100% 被拦截（建议值 Basic Auth·终稿前确认）；操作留痕审计（蓝图 §3） |

### 2.4 不做什么（范围边界）

- **不做**与飞书的双向同步——管理台是唯一权威源，飞书仅一次性迁移来源（08-04-2026 拍板，防口径分叉）；迁移完成后飞书侧变更不回流。
- **不做**多级权限/角色管理界面——内部工具面不做多级权限（蓝图 §3，阶段二随 Zendesk/多角色再议）；访问控制仅建议值口令（Basic Auth）+ 链接不公开。
- **不做**无人审的自动发布通道——不存在任何"AI 起草直接生效"路径，铁律写死（AC-M-15）；界面上不提供绕过审核的操作。
- **不做**与 F06 业务看板重复的会话/业务指标——F06 看会话与业务结果，本页效果看板（第 5 导航区，08-04-2026 第二轮拍板增补）只看**条目供给侧效果**，两者同源埋点聚合（§4.2 既有事件，零新增埋点）、呈报位置区隔，不重复建设（§5.10 交互逻辑 7）；命中率仍以评测集验收、§8 目标值不变（§5.10 交互逻辑 6）。
- **不做**知识条目内容中文化——条目内容第一版恒为英文并带语言字段（§4.1 F07 约束）；界面 100% 简体中文仅限管理台界面文案（**界面语言与内容语言分离**，08-04-2026 第二轮拍板强化）；管理台 UI 多语言切换为后续增强（复用 F07 文案资源加载约束，第一版仅中文资源）。
- **不做**多渠道客诉采集（应用商店评分/客服邮件）——阶段二范围（PAGE-F05-01 planned），本期审核队列来源仅 F05 四触发源回流。
- **不做**移动端适配承诺——桌面 1280+（与看板同体系）。

## 3. 用户与场景

### 3.1 目标用户

| 维度 | 描述 |
| :--- | :--- |
| 角色 | **知识库内容运营**（直接角色·内部工具，拍板 2 名单，现有人员兼任 2 名，§2.1 08-04-2026 增补）；**业务负责人**（管理台使用者之一，查看条目与审核动态） |
| 人数 | 单次使用 1 人；全量使用者固定小圈子（内部链接不公开） |
| 技术熟练度 | 中高（日常使用飞书文档与内部系统；非工程师，编辑器操作须直观） |
| 使用设备 | 桌面电脑 / 笔记本（1280+ 宽浏览器） |
| 使用姿势 | 初期集中整理存量导入内容；此后周度例行消化审核队列 Top 10 + 按需录入修订 |
| 数据边界 | 管理台全量知识条目与审核队列；来源会话仅脱敏后摘要/链接（§4.5 PII 规则）；无 App 用户明细数据 |

### 3.2 核心使用场景

**场景 A：周度审核消化（主场景，F05 消化工作面）**
- 时机：每周例行（周消化 Top 10 SLA，§5.6），或看到待审数量增长时
- 前置：F05 回流触发源会话累积，AI 已聚类起草条目草稿进审核队列（AC-M-14）
- 动作：口令进入 → 打开审核队列（按频次降序）→ 逐条打开草稿：查看正文、问题标签建议、来源会话链接/脱敏摘要、频次 → 三操作择一：「通过发布」（触发发布门禁回归）/「驳回」（必填原因）/「改后发布」（编辑后触发门禁）→ 处理完 Top 10
- 情绪：例行、求准——最在意"草稿质量如何、来源频次是否真实、发布后会不会答错"

**场景 B：存量迁移与整理（初始批量场景）**
- 时机：管理台上线初期，飞书 120+ 篇存量文档一次性迁移
- 前置：飞书文档已导出为可导入文件（或走批量导入入口直接迁移）
- 动作：进入「录入与导入」→ 批量导入（飞书迁移/Markdown/CSV）→ 全部进「待整理」队列、逐条看到导入结果 → 逐条打开：查看 AI 切条/问题标签/归类建议 → 逐项「采纳」「修改」「拒绝」→ 完善后走审核发布流程
- 情绪：任务量大但有 AI 辅助——在意"进度可见、失败条目别静默丢、建议别替我做主"

**场景 C：AI 不可用时的人工兜底（兜底场景，AC-E-13）**
- 时机：LLM 故障，AI 整理/起草服务不可用
- 前置：建议卡隐藏并明示"AI 建议暂不可用"
- 动作：照常手工录入/编辑条目 → 人工填写标签与归类 → 照常提交审核、发布（发布门禁回归照常执行）
- 情绪：可接受——AI 是增强不是依赖，我的工作不被卡住

**场景 D：发布回归失败处理（兜底场景，AC-E-14）**
- 时机：发布（含改后发布）触发评测集回归，回归失败
- 前置：条目未生效、状态回炉（回草稿）
- 动作：在发布门禁结果面板看到失败原因与失败用例 → 修订条目 → 重新发布 → 回归通过后生效
- 情绪：不慌——失败原因可见、有明确的修复路径，不存在"不知道为什么没上线"

### 3.3 用户核心诉求（优先级排序）

1. **不出错**：未审核的绝不生效、回归不过的绝不上线——出错的代价是 App 用户拿到错误答案
2. **可追溯**：谁改的、什么时候改的、为什么驳回、回归结果如何，全部留痕可查
3. **效率**：AI 建议帮我少打字、频次排序帮我抓重点、批量导入帮我搬存量
4. **可控**：AI 只是建议态，采纳/修改/拒绝由我定；AI 挂了我照常干活

## 5. 界面内容

### 5.1 元素清单（逐项对应 PRD §5.10 元素表，不增不减；界面文案照抄 §5.10 文案定稿）

**条目列表**
- 类型：表格（搜索框 + 筛选器：场景/型号/语言/状态/问题标签）
- 内容：条目标题、场景、型号、语言、状态、问题标签、更新时间
- 数据来源：管理台条目库（唯一权威源）
- 默认态：按更新时间降序展示全部条目；操作后：搜索/筛选即时过滤，点行进入编辑
- 状态列文案：「草稿」「已上线」「待改造」「已下线」（§5.10 状态枚举定稿）

**条目编辑器 · 问答型**
- 类型：表单（标题 / 场景 / 型号 / 语言 / 正文 / 问题标签，字段对齐 §4.1 schema）
- 默认态：新建为空 / 编辑载入现值；保存生成修订记录
- 显示条件：条目类型为问答型

**条目编辑器 · 排障流程型**
- 类型：结构化编辑器（步骤节点 + Done/It didn't work 分支，对齐 §4.1 排障流程 schema：每步仅两出口，终止节点只允许"确认解决/转人工"两类）
- 默认态：同上；保存时执行无死胡同图遍历校验（§3.6），不过不允许发布，编辑器内标出问题节点
- 显示条件：条目类型为排障流程型

**状态流转控件**
- 类型：状态操作（草稿 → 已上线 → 待改造 / 已下线）
- 默认态：显示当前状态；操作后：流转留痕；转入「已上线」须过发布门禁
- 禁用条件：未过审核/回归的条目不可流转为已上线（唯一带禁用条件的元素，§5.10 元素表）

**修订历史**
- 类型：时间线（修订人 / 时间 / 变更摘要）
- 默认态：每条目可查；可查看任一历史版本

**手工录入表单**
- 类型：表单入口，常驻
- 操作后：提交进「待整理」队列或存为草稿

**批量导入**
- 类型：文件上传（Markdown / CSV；飞书一次性迁移走同一入口），常驻
- 操作后：导入内容全部进「待整理」队列，逐条报告结果
- 结果文案：「导入完成：{n} 条进入待整理队列；{m} 条失败（逐条原因见下）。」（§5.10 定稿）

**AI 整理建议卡**
- 类型：建议卡（切条建议 / 问题标签建议 / 场景与型号归类建议）
- 默认态：对录入/导入内容自动生成，**建议态**；运营逐项采纳/修改/拒绝后方生效
- 操作按钮文案：「采纳」「修改」「拒绝」（§5.10 定稿）
- 隐藏条件：AI 服务不可用时隐藏并明示（AC-E-13，见第 7 节）

**会话提炼审核队列**
- 类型：队列列表（AI 起草草稿：正文 + 问题标签建议 + 来源会话链接/脱敏摘要 + 频次），按频次降序
- 默认态：常驻，待审数量可见；单条打开后三操作
- 三操作文案：「通过发布」「驳回」「改后发布」（§5.10 定稿）
- 驳回原因输入占位文案：「填写驳回原因（必填），供起草复盘」（§5.10 定稿）

**发布门禁结果面板**
- 类型：面板（评测集回归结果 + 留痕记录）
- 默认态：发布动作后展示；回归通过→条目生效；失败→条目回炉并展示失败用例
- 回归失败提示文案：「评测集回归未通过，条目未生效——查看失败用例后修订重发。」（§5.10 定稿）

**周清单导出**
- 类型：导出按钮，常驻
- 操作后：导出任意周区间待补清单（字段同 §4.4：原始问题/命中文档/会话链接/频次）

**效果看板 · 场景覆盖卡**（08-04-2026 第二轮拍板增补，下同）
- 类型：统计卡（管理台第 5 导航区「效果看板」）
- 内容：已上线条目数按场景分布（小条形图）+ 覆盖场景数，对照 G1 咨询分布场景集
- 口径：引用 §8.2「知识条目效果」行·场景覆盖，本页不复制定义
- 操作：只读
- 降级：G1 前按 §4.1 现有场景分类展示并标注「场景集待 G1 回填」（见第 7 节）

**效果看板 · 使用频率卡**
- 类型：统计卡（同上导航区）
- 内容：条目被检索命中次数，周趋势
- 口径：引用 §8.2 同行·使用频率；操作：只读

**效果看板 · 引用采纳卡**
- 类型：统计卡（同上导航区）
- 内容：条目被实际引用进回答的次数，周趋势；**与命中分列——命中未被采纳的差值可见**
- 口径：引用 §8.2 同行·引用采纳（「回答消息」事件引用条目标识列表计数，零新增埋点）；操作：只读

**效果看板 · 知识库准确率卡**
- 类型：统计卡（同上导航区）
- 内容：知识库整体条目准确率 + 周趋势；双口径（宽/严，随解决率口径）与消息级近似归因性质如实标注
- 口径：唯一落点 §8.2「知识条目效果」行，本页引用不复制；操作：只读

**效果看板 · 条目效果列表**
- 类型：表格（逐条目：命中数 / 引用数 / 点踩数 / 「试了没用」数 / 条目准确率；「试了没用」单列，不并入普通点踩，口径引用 §8.2）
- 默认态：按条目准确率升序（最差条目浮顶）；可切换排序列
- 操作后：点击条目行跳转该条目详情（既有编辑器与修订历史，不新增编辑入口）
- 标黄：条目准确率 < 标黄线「建议值 60% · 终稿前确认」标黄提示优先修订（与 F05 回流联动：标黄条目即修订候选）
- 样本不足：引用数低于「建议值 10 次 · 终稿前确认」的条目准确率列显示「样本积累中」（AC-E-15，见第 7 节）

**并发编辑冲突提示**
- 类型：提示（后提交者提交时出现）
- 文案：「该条目已被他人更新，请基于最新版本重新修改（你的改动未覆盖线上内容）。」（§5.10 定稿）

### 5.2 辅助信息

- 待审数量提示：顶部常驻（§5.10"待审数量可见"）
- 队列名文案：「待整理」「审核队列」（§5.10 定稿）

- 页脚：内部工具标识 / 版本号（不含任何公开链接）

## 6. 交互流程

### 6.1 页面加载与初始化

- 访问内部链接 → 口令校验（建议值 Basic Auth · 终稿前确认，与 F06 看板同机制）→ 未通过 100% 拦截，无内容泄露
- 通过 → 默认落条目库列表（按更新时间降序）；顶部显示待审数量
- **空库初始态**（design-derived: DEC-012——上游未定义空库形态）：条目库为空（飞书迁移尚未执行）时，列表区展示引导——说明管理台为唯一权威源，引导先执行批量导入（飞书一次性迁移入口），不展示空表格裸奔

### 6.2 核心操作流程

**流程一：录入/导入 → 整理 → 审核 → 发布（AC-M-13 闭环主链）**

```
手工录入表单 / 批量导入（飞书迁移·Markdown·CSV）
    │
    ├─ 导入部分失败 → 成功条目照常进队列，失败条目逐条报告行号+原因（不整批静默失败）
    │
    ▼
「待整理」队列（一律先进队列，不直接上线）
    │
    ├─ AI 可用 → 建议卡自动生成（切条/标签/归类，建议态）
    │      │
    │      └─ 运营逐项「采纳」/「修改」（按修改内容生效）/「拒绝」（不生效，AC-E-13）
    │
    ├─ AI 不可用 → 建议卡隐藏+明示，人工直接编辑（不受阻，AC-E-13）
    │
    ▼
条目完善（问答型/排障流程型编辑器；排障型保存时无死胡同校验，不过则标出问题节点、不允许发布）
    │
    ▼
状态流转 → 转入「已上线」→ 触发发布门禁：评测集回归（§4.3，结果留痕）
    │
    ├─ 回归失败 → 条目不生效、回炉（回草稿）；面板展示失败原因+失败用例（AC-E-14）→ 修订后重发
    │
    └─ 回归通过 → 条目生效、索引更新（≤24h）→ F01 可检索命中、来源标注一致（AC-M-13）
```

**流程二：会话提炼审核（AC-M-14/15，F05 消化工作面）**

```
F05 回流四触发源会话累积（§4.4）
    │
    ▼
AI 聚类起草条目草稿（正文+问题标签建议+来源会话链接/脱敏摘要+频次）
    │
    ▼
审核队列（按频次降序；待审数量顶部可见）——草稿未审核期间：不进检索库、不被 F01 命中（AC-M-15 铁律）
    │
    ├─ 「通过发布」→ 进发布门禁（同流程一）
    ├─ 「驳回」→ 必填驳回原因（供起草复盘）→ 草稿不生效
    └─ 「改后发布」→ 编辑器修改 → 进发布门禁（同流程一）
```

**流程三：条目状态流转（§5.10 交互逻辑 1）**

```
草稿 ──(过审核+发布门禁)──▶ 已上线 ──▶ 待改造 / 已下线
每次流转留痕（操作人/时间/变更摘要）；未过审核/回归的条目不可流转为已上线（控件禁用）
```

### 6.3 辅助操作

- 修订历史：条目详情内打开时间线，可查看任一历史版本（只读）
- 周清单导出：选择任意周区间 → 导出待补清单文件（字段同 §4.4；可补导历史周区间，§5.6）
- 标签管理：集中确认视图逐项处理 AI 建议态标签（DEC-011）；确认后标签成为 F01 检索信号（扩充召回+过滤，§5.10 交互逻辑 6）
- 效果看板浏览（§5.10 交互逻辑 7，08-04 第二轮增补）：四卡与条目效果列表均**只读**；列表默认准确率升序、可切换排序列；点条目行跳转条目详情（条目库既有编辑器与修订历史，不新增编辑入口）；数据与 F06 看板同源埋点聚合，零新增埋点
- 看板互跳（可选，DEC-013）：顶部链接跳转 PAGE-F06-01，反向同理；不构成任一流程的必经步骤

## 7. 状态与边界

### 7.1 页面状态全景

| 状态 | 触发条件 | 页面表现 |
| :--- | :--- | :--- |
| 权限口令态 | 访问链接未通过口令校验 | 100% 拦截，仅口令输入，无任何条目内容泄露；通过后进入管理台 |
| 空库初始态 | 条目库为空（迁移前） | 引导先导入：说明唯一权威源 + 指向批量导入/飞书迁移入口（DEC-012），不展示空表格 |
| 条目库常规态 | 有条目 | 列表按更新时间降序；搜索/筛选即时过滤 |
| 导入进行中 | 批量导入文件已提交、处理未完成 | 进度可见，期间不阻塞其他分区操作；完成后出结果报告 |
| 导入部分失败 | 文件内部分条目格式错误/字段缺失 | 「导入完成：{n} 条进入待整理队列；{m} 条失败（逐条原因见下）。」成功条目照常入队，失败条目逐条列行号+原因；不整批静默失败、不静默丢行 |
| 导入失败 | 文件整体不可解析/超单文件上限（建议值 500 条） | 显式失败原因，可修正后重传；不产生半截数据 |
| AI 建议加载中 | 录入/导入内容提交后建议生成中 | 建议卡占位加载态；人工编辑不等待、不被锁 |
| AI 建议态 | 建议生成完成 | 建议卡展示切条/标签/归类建议，逐项「采纳」「修改」「拒绝」；未处理前建议一律不生效 |
| AI 不可用降级 | LLM 故障（AI 整理/起草服务不可用） | 建议卡隐藏并**明示 AI 建议暂不可用**；手工录入、编辑、审核、发布全部照常可用——AI 为增强不是依赖（AC-E-13，与 §7.5 降级原则同源） |
| 审核队列空态 | 无待审草稿 | 空态说明（回流草稿到达后自动出现在此），待审计数为 0；不误导为故障 |
| 审核队列积压态 | 待审草稿量大 | 按频次降序保持可操作；周消化 SLA（Top 10）照常按队列数据判定（§5.6）；积压不影响已上线条目正常服务 |
| 发布门禁回归中 | 条目转入「已上线」动作已触发、回归未完成 | 结果面板展示回归进行中；条目保持未生效（不存在"回归中已上线"中间态） |
| 发布回归失败 | 评测集回归未通过 | 「评测集回归未通过，条目未生效——查看失败用例后修订重发。」条目回炉（回草稿），失败原因与失败用例在结果面板可见（AC-E-14） |
| 发布回归通过 | 评测集回归通过 | 条目状态变「已上线」、回归结果留痕可查；索引更新，生效 ≤24h（AC-M-13） |
| 并发冲突态 | 后提交者提交时条目已被他人更新 | 「该条目已被他人更新，请基于最新版本重新修改（你的改动未覆盖线上内容）。」不静默覆盖，修订历史可回溯 |
| 排障校验不过态 | 排障流程型保存时图遍历校验失败（死胡同/非法环） | 不允许发布；编辑器内标出问题节点（与 §3.6 同一规则） |
| 效果看板数据回补中 | 埋点上报延迟 | 延迟数据标注「数据回补中」，不静默缺数（与 F06 看板同口径，§5.7；08-04 第二轮增补，下同） |
| 效果看板 G1 前降级 | G1 咨询分布场景集未回填 | 场景覆盖卡降级为按 §4.1 现有场景分类（安装/联网/配对/会员/其他）展示分布，并标注「场景集待 G1 回填」；不编造场景集 |
| 效果看板样本积累中 | 条目引用数低于样本量下限（「建议值 10 次 · 终稿前确认」） | 该条目**不计算、不显示准确率数值**，准确率位置显示「样本积累中」；命中数/引用数/点踩数/「试了没用」数照常展示——不显示误导性准确率（AC-E-15） |

### 7.2 边界与容错

| 边界场景 | 处理策略 |
| :--- | :--- |
| 并发编辑同一条目 | 后提交者收到冲突提示（文案见 7.1），须基于最新版本重做；不静默覆盖，修订历史可回溯（§5.10 异常场景） |
| 批量导入超单文件上限 | 上限「建议值 500 条 · 终稿前确认」；超限显式拒绝并提示拆分，不截断静默导入 |
| 问题标签超上限 | 「建议值 每条目 ≤20 个 · 终稿前确认」；超限时拦截并提示，不静默丢弃标签 |
| 飞书一次性迁移失败 | 走 §9.2 兜底：人工从飞书导出文件经批量导入入库；迁移失败不阻塞管理台其余能力（§5.10 异常场景） |
| 网络异常/提交失败 | 显式失败提示可重试；编辑中内容不因提交失败丢失；不出死屏 |
| AI 起草草稿质量差 | 运营用「驳回」（必填原因供起草复盘）或「改后发布」兜底；AI 输出永远不绕过人工审核（AC-M-15） |
| 审核队列洪水期（拒答激增） | 频次降序保持 Top 优先可操作（§5.6 触发量激增同理）；激增本身由 F06 拒答率预警承接，不在本页处理 |
| 24h 生效窗口内用户复问 | 得到旧答案属预期行为，不计缺陷（§5.6 异常场景）；管理台内条目状态已如实为「已上线」 |

## 8. 业务规则与校验

### 8.1 字段定义（对齐 PRD §4.1 概念 schema，不新增字段）

| 字段 | 说明 |
| :--- | :--- |
| 条目标识 | 唯一、稳定，系统生成；供回答引用与回流清单关联 |
| 标题/问题描述 | 用户语言的问题表述（内容运营填写） |
| 场景分类 | 安装/联网/配对/会员/其他（与 G1 咨询分布口径对齐，G1 后可调） |
| 适用设备型号 | 可多值；空 = 全型号通用 |
| 语言字段 | F07 约束，第一版恒为英文，字段必须存在（缺失可被校验发现，AC-C-06） |
| 正文内容 | 事实性解答内容（英文），F01 第②层引用对象 |
| 来源与版本 | 初始导入来源标识（飞书一次性迁移）+ 更新时间，支撑 ≤24h 生效追踪 |
| 问题标签 | 多值（用户问法变体）；AI 建议 + 人工确认后生效；确认后作为 F01 检索信号（扩充召回+过滤） |
| 审核信息 | 草稿来源（人工录入/批量导入/会话提炼）+ 审核人/审核时间；未审核条目不进检索库 |
| 状态 | 草稿/已上线/待改造/已下线（枚举文案见 §5.10 定稿） |
| 排障型附加：步骤节点/分支/终止节点 | 每步仅两出口（Done→下一节点；It didn't work→分支节点）；默认禁止环，确需回指的环上必须有转人工出口；终止节点只允许确认解决/转人工两类（§4.1） |

### 8.2 校验规则

| 校验项 | 时机 | 规则 | 失败反馈 |
| :--- | :--- | :--- | :--- |
| 排障流程完整性 | 排障型保存时 | 无死胡同图遍历校验（§3.6：每节点可达终止节点，终止节点仅两类，环上须有转人工出口） | 不允许发布，编辑器内标出问题节点 |
| 发布门禁 | 条目转入「已上线」（含改后发布）时 | §4.3 评测集回归必须通过 | 回归失败提示（§5.10 定稿文案）+ 条目回炉 + 失败用例可见 |
| 驳回原因必填 | 审核「驳回」提交时 | 原因非空 | 占位提示「填写驳回原因（必填），供起草复盘」，空值不提交 |
| 导入文件校验 | 批量导入时 | 格式可解析、字段完整、单文件 ≤ 建议值 500 条 | 部分失败逐条报告行号+原因；整体不可解析显式拒绝 |
| 问题标签上限 | 编辑/确认标签时 | 每条目 ≤ 建议值 20 个 | 超限拦截提示 |
| 并发版本校验 | 条目提交时 | 基于最新版本提交 | 冲突提示（§5.10 定稿文案），不静默覆盖 |
| 语言字段存在性 | 条目保存时 | 语言字段必须存在（第一版恒英文） | 缺失可被校验发现（AC-C-06），拦截保存 |

### 8.3 特殊业务规则

- **无人审不生效（铁律）**：未经审核的草稿/待整理条目不进检索库、不被 F01 命中、不出现在任何回答引用中；只有审核通过并过发布门禁的条目进入检索库（AC-M-15，08-03-2026 拍板确立、08-04-2026 随 F09 提前落地）。界面上不存在任何绕过路径。
- **唯一权威源**：条目的录入、修订、审核、发布全部在管理台完成；不做与飞书的双向同步（08-04-2026 拍板，防口径分叉）。
- **AI 建议态非门槛**：AI 切条/标签/归类建议须人工采纳/修改/拒绝后方生效；拒绝不阻塞人工直接编辑发布（AC-E-13）。
- **全程留痕**：每次修订与状态流转记录修订人/时间/变更摘要；回归结果留痕可追溯；操作审计留痕（蓝图 §3/§9：时间/操作者/动作）。
- **生效时限**：回归通过后发布生效、索引更新 ≤24h（§4.4 既有承诺不变）。
- **检索联动不改指标**：人工确认后的问题标签作为 F01 检索信号；命中率仍以评测集验收，§8 目标值不变、不新增指标（§5.10 交互逻辑 6）。
- **界面语言 100% 简体中文（08-04-2026 第二轮拍板强化）**：全部界面元素（导航/按钮/标签/提示/占位文案）简体中文，不残留英文装饰性文案（品牌词 "COOLFLY" 允许保留）；**界面语言与内容语言分离**——知识条目内容保持英文并带语言字段；管理台 UI 多语言切换为后续增强（复用 F07「文案不硬编码语言」约束，UI 文案从语言资源加载，第一版仅中文资源）。
- **效果看板口径引用不复制（08-04-2026 第二轮拍板增补）**：四卡与条目效果列表全部指标口径唯一落点 §8.2「知识条目效果」行，本页逐项引用不复制定义；数据粒度=周；标黄线=「建议值 60% · 终稿前确认」、条目准确率样本量下限=「建议值 引用 10 次 · 终稿前确认」；全部只读、零新增埋点，与 F06 业务看板同源聚合不重复建设。

### 11.1 功能验收

| 编号 | 验收点 | 通过标准 |

| F-06 | 回归失败回炉（AC-E-14） | 发布时回归失败：条目不生效（不进检索库、状态回炉），管理台内可见回归失败原因与失败用例；修订后可重新发布 |
| F-07 | 批量导入进待整理 | 导入（飞书迁移/Markdown/CSV）内容 100% 先进「待整理」队列，不直接上线；部分失败时成功条目照常入队、失败条目逐条报告行号与原因 |

| F-10 | 组合筛选与搜索 | 列表支持场景/型号/语言/状态/问题标签组合筛选与搜索，即时过滤；默认按更新时间降序 |

| F-12 | 驳回原因必填 | 「驳回」操作原因为空时不可提交；占位文案与 §5.10 定稿一致 |
| F-13 | 效果看板四卡与条目效果列表（AC-M-16，08-04 第二轮增补） | 打开效果看板（第 5 导航区）：四卡可见——场景覆盖（已上线条目场景分布+覆盖场景数）/使用频率（检索命中周趋势）/引用采纳（实际引用进回答周趋势，**与命中分列——命中未被采纳可见**）/知识库准确率（整体+趋势）；条目效果列表逐条目可见命中数/引用数/点踩数/「试了没用」数/条目准确率，可按准确率升序排列（最差条目浮顶）；全部指标口径与 §8.2「知识条目效果」行一致 |
| F-14 | 样本不足不显示误导准确率（AC-E-15，08-04 第二轮增补） | 条目引用数低于样本量下限（「建议值 10 次 · 终稿前确认」）时：不显示准确率数值，准确率位置显示「样本积累中」；其余指标（命中数/引用数/点踩数/「试了没用」数）照常显示 |
