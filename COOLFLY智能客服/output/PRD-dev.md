## 1. 项目一句话 + 转向声明

COOLFLY 智能客服自研范围 = **知识运营中台**：独立内部 Web（桌面 1280+，简体中文，十视图五组，RBAC 四角色真实账号）+ 三类无界面服务端能力（中台→Zendesk 单向同步与 drift 检测／Zendesk 会话每日批次挖掘／中→英 AI 翻译管道）。C 端体验（帮助中心、AI bot 在线聊天、邮件与转人工工单）与客服工作报表全部由 Zendesk 承担——**零 C 端界面、零对话运行时**。

**转向声明（必读）**：08-04-2026 D-10 拍板后，原 F01–F08 自研对话线（RN 对话页/SSE 流式/意图分类/三层拒答/排障卡片流/埋点看板）**整体废止**——不要给这些线写任何新代码。功能标准 = 用户自制 v3 原型 `output/pages/知识运营中台v3.dc.html`。App 侧本期完全不动。retired ID 永不复用（PRD §0.4/§12.4：F×8、FR×8、US×23、AC×55 已登记承接方）。

**三条权威原则（铁律，服务端构造保证，不是 UI 约束）**：

1. **中台 = 知识唯一权威源**：录入/修订/审核/发布全在中台，中台→Zendesk **单向同步**；Zendesk 端被直接改写 = drift，检测报警并处置（覆盖/拉回）。飞书 120+ 篇一次性导入为初始数据，不做双向同步。
2. **统一过审**：全部新条目/修订/挖掘候选/优化建议一律经审核中心 + 发布门禁后才生效同步——无人审不生效，任何角色无绕过审核的发布路径（发布路径唯一 = /review 门禁成功路径，API 层强制，UI 禁用只是表象）。
3. **中文 = 内容权威源**：结构、字段、口径以中文为准；英文经 AI 翻译 + 人工校验（**100% 铁律**）后才可同步；内部段落不翻译、不对外。

**异常原则（写死，PRD §5.1）**：任何失败态（同步/翻译/向量/批次）**如实标注 + 保留上次可用内容 + 提供重试路径**，不静默吞错；不存在「阻断但已同步」类中间态。

**MVP 完成定义（PRD §0.2）**：

1. 十视图全部可用：§8 索引的 AC-P 全部 P0 项验收通过（权限矩阵生效、统一过审、驳回理由必填、同步阻断、版本回滚、drift 报警、翻译人工校验后才同步）。
2. 知识初始迁移完成：飞书 120+ 篇经批量导入→人工过审→同步至 Zendesk 对应 Section（对外）或仅客服 segment（内部）。
3. RBAC 与账号体系生效：四角色真实账号可登录，权限矩阵约束全部界面动作，全量操作写审计日志。
4. 回流闭环有数据：四渠道信号在反馈回流视图可见，AI 对话挖掘每日批次正常产出（含空批次如实标注）。

## 4. RBAC 权限矩阵（唯一落点 PRD §5.10 · 10 项 × 4 角色）

| 权限项 | 知识管理员 | 知识审核员 | AI 运营 | 系统管理员 |
|--------|-----------|-----------|---------|-----------|
| 新建 / 编辑知识条目 | ✓ | ✓ | — | — |
| 提交审核 | ✓ | ✓ | — | — |
| 审核通过 / 驳回 | — | ✓ | — | — |
| 发布到 Zendesk | — | ✓ | — | — |
| 版本回滚 | — | ✓ | — | — |
| 管理目录与章节 | ✓ | ✓ | — | — |
| 查看效果与缺口数据 | ✓ | ✓ | ✓ | ✓ |
| 提交优化建议 | ✓ | ✓ | ✓ | — |
| 用户与角色管理 | — | — | — | ✓ |
| 查看全量审计日志 | — | ✓ | — | ✓ |

- **四眼原则（硬约束）**：审核员自己提交的条目须另一名审核员通过——审核通过接口内校验提交人 ≠ 当前用户（AC-P-23）；审核员至少 2 人为最低人数前提（PRD §9.4）。
- **实现**：权限中间件覆盖全部写路由（每路由声明所需权限点，preHandler 查矩阵，越权 403 带原因文案 key）；矩阵存库 + 进程内缓存写时失效；权限变更即时生效、禁用账号会话即时失效（AC-P-22/24）。
- 角色定位：知识管理员=生产主力无发布路径；审核员=审核/发布/回滚/drift 处置唯一执行者；AI 运营=只读+建议（编辑器锁定明示只读）；系统管理员=管人不管内容（职责分离）。

## 5. 核心数据模型（七域，概念对齐 PRD §4，物理要点见技术方案 §5.1）

| 域 | 表（概念） | 要点 |
|----|-----------|------|
| 知识域 | 知识库 / 章节（两级自引用，深度≤2，含条目或子章节禁删=外键 RESTRICT+应用层前置校验）/ 条目 | 条目：KB-xxxx 标识、类型（FAQ 政策型/FAQ 型/操作流程型/内部口径）、可见性三档、两级问题场景、标签≤20、适用型号、复核到期、负责人、乐观锁版本号；行携英文/同步/向量三从属状态 |
| 版本域 | 条目版本（内容快照=TipTap JSON+规范化文本、变更说明、生效区间、操作人、状态现行/历史/已回滚）/ 版本效果聚合（版本×周：调用/命中/解决/采纳，近似归因标注） | 两版 diff 由快照规范化文本实时计算（diff 9）；**回滚=以旧版内容建新修订走审核发布链**；历史与指标永不删除（AC-P-06） |
| 翻译域 | 翻译对（条目×段落级：中文段/英文段/人工修订标注/内部段落跳过位）+ 条目英文状态机字段 | 中文保存钩子：英文置「待重新校验」+同步阻断+向量置「待重建」（AC-P-04）；翻译失败保留上次英文 |
| 同步域 | 同步映射（条目↔Article、章节↔Section、目录↔Category、**已发布内容哈希**）/ 同步任务（动作/目标/状态/重试计数/失败原因）/ drift 记录（文章/修改方/差异摘要/检出时间/处置动作与处置人） | 同步任务唯一写入源=发布 API 成功路径；哈希是 drift 比对基准 |
| 挖掘域 | 抓取批次（日期/来源会话数分渠道/候选数/状态：完成·无新草稿·失败+原因）/ 候选（类型新增·修订·合并/频次/查重值/缺口判定/AI 摘要/来源会话脱敏摘要/处置状态与留痕） | 三重准入结果落候选行；丢弃留痕、同主题再达阈值重现；无直接入库路径 |
| 信号域 | Zendesk 信号事件（渠道/条目或主题/信号类型：bot 引用·工单 solved·reopen·CSAT·文章投票·客服 flag·搜索无结果/**确定性档位**/原始摘要/发生时间）/ 条目效果聚合视图（条目×周，node-cron 刷新） | 档位落库（必得/档位相关/待核实）；样本下限与标红线为展示层参数不入库硬编码 |
| 治理域 | 用户（邮箱/argon2 哈希/角色/知识库范围/启用状态/首改密标记）/ 会话（服务端表，禁用即删）/ 角色×权限矩阵（10 项权限点）/ 审计日志（append-only：时间/操作人+角色/对象/动作/字段级前后值/备注） | 审计只增不改不删长期保留；矩阵修改仅系统管理员且写审计 |

- **审核队列非独立表**：待审 = 条目/候选状态机「待审核/审核中」态 + 来源标注（AI 挖掘/人工录入/版本修订/反馈修订/批量导入），防双源漂移。
- **脱敏管道（PII 义务落点）**：挖掘拉取的原始会话不落中台库——内存中脱敏（邮箱/SN/Wi-Fi SSID/电话，正则规则集版本化）→ 仅脱敏摘要随候选落库；纯函数模块，真实中英文样本单测覆盖。

3. **状态机守卫**：四条状态机（§8）合法流转表内聚领域层，非法流转 409——「无人审不生效」「已确认前不同步」由构造保证。

## 7. Zendesk 集成四面（零 SDK：Node 24 原生 fetch + API token，技术方案 §4.4）

1. **同步推送（Guide API）**：发布→按映射推送。映射（规则唯一落点 PRD §4.1）：知识库→Help Center brand、目录→Category、章节→Section、条目→Article、标签→label_names、仅内部→客服 user segment（user_segment_id）、英文→Article Translation（locale en-us）、条目内锚点→文章内 anchor。动作三类：更新正文+labels / 创建（待过审后）/ 归档+重定向（下线条目不裸删）。推送前按可见性拆分（混合条目剥离内部段落后生成对外 HTML）；英文非「已确认」整条阻断（中英同发策略建议值）。目标 Section 不存在→同步失败并提示先修复映射，**不自动创建未经确认的 Zendesk 结构**。批量迁移 120+ 篇分批推送避开限流。
2. **挖掘拉取（Support API + 在线聊天导出）**：node-cron 每日批次（业务时区低峰）增量拉取昨日邮件工单与在线聊天会话（start_time 游标推进）；在线聊天导出端点依订阅形态（Live Chat vs Messaging）**列核实清单实现期核验**（PRD §0.6）。失败（429/网络）→批次表标「失败」+原因，次日照常拉取，不静默缺批次。拉取内容先过脱敏管道再进挖掘。
3. **drift 检测（轮询为主）**：每篇已同步 Article 持「已发布内容规范化哈希」；周期扫描（建议值每小时）先比 updated_at 缩小面、再比正文哈希→差异写 drift 表（文章/修改方/差异摘要/时间）→同步中心报警+飞书机器人推送→审核员双处置：**覆盖**（推送中台版本，Zendesk 端修改丢弃留痕）或**拉回**（作为待审来源进审核中心）。Webhook 为降低延迟的升级位（事件覆盖面核验后启用），轮询兜底不撤。drift 与本台待发版本冲突：先处置 drift 再放行同步。
4. **信号采集（只读）**：工单 solved/reopen/CSAT、文章投票、客服 flag 随批次/周期拉取落信号表，带确定性档位；bot 锚点引用、Knowledge 面板引用等**待核实信号**核实通过前标「待核实」、不进达标判定；**Explore 不集成**——客服工作数据页签只做口径说明与链接指向（AC-P-19）。

集成层统一处理：认证头（subdomain + email/API token，deployment-secret）、429 退避（读 Retry-After，指数退避封顶）、错误分类（凭据失效单列告警指向 owner=内部技术团队）。

## 8. 状态机与发布门禁

**四条状态机（合法流转表内聚领域层，非法流转 409）**：

- **条目**：草稿 → 编辑中 → 待审核 → 审核中 → 审核通过 → 已发布（支线：已驳回→按意见修改重提；已下线=Zendesk 端归档+重定向）；修改已发布条目=生成新版本草稿重走全链；版本级另有「历史版本」「已回滚」（流转图 PRD §6.2）
- **英文翻译**：未生成 → AI 翻译中 → 待人工校验 → 已确认 → 已同步（异常：翻译失败 / 待重新校验）；**「已确认」前同步禁用；中文变更即置「待重新校验」并阻断（服务端强制）**；翻译失败保留上次英文可重试，连续 3 次（建议值）告警
- **同步**：未同步 / 待同步 / 同步中 / 已同步 / 失败 / 已阻断 / 已归档
- **向量**：未向量化 / 向量化中 / 已向量化 / 待重建 / 向量失败；内容变更置「待重建」；失败/待重建条目不参与查重与代理评测且界面明示；发布前待重建须先重建（门禁提示条）

**发布门禁四查（/review/:id/publish 执行链，含「改后发布」与回滚产生的新修订，技术方案 §6.6）**：

```text
①格式与字段完整性（标题/章节/可见性/标签已填）
②敏感信息与内部口径（内部段落已标记，剥离产物核验不含内部内容——双保险，AC-P-14）
③英文版本状态（未「已确认」→ 阻断并展示原因）
④代理评测（本台向量检索召回验证：真实问法能否召回本条目；
  结果留痕，固定标注「代理指标不等于 Zendesk AI 真实表现」）
→ 全过：状态置「已发布」+ 写同步任务（同事务收口，不存在「门禁不过但已入队」中间态）
→ 不过：阻断并展示原因，条目留在审核通过态待整改
```

**翻译管道（技术方案 §6.5）**：中文权威源→触发翻译（按权限）→段落级拆分（内部段落跳过，标记随 TipTap 节点）→ Claude sonnet 档逐段翻译（generateObject 段落对齐输出）→「待人工校验」→逐段校验（可修正表述不得改政策口径，修订留痕）→「已确认」→随同步任务推 en-us translation→「已同步」。

**挖掘管道（技术方案 §6.4）**：每日批次（低峰）→拉取昨日会话→脱敏→fastembed+pgvector 语义聚类计频（英文侧：Zendesk 英文会话 vs 条目英文版；英文未生成的条目以标题+标签 FTS 兜底并如实标注覆盖面）→三重准入（①频次 ≥10 次/周 ②查重 ≥0.85 挂修订不新建 ③缺口判定对照场景覆盖）→ sonnet 档起草（新增/修订/合并三类候选）→候选落库→视图④处置→全部经审核中心。切条/标签/场景/章节归类建议（haiku 档）同为建议态，运营逐项采纳。冷启动语料=原 G1 历史数据导出（保留项，PRD §9.3）。

6. 翻译管道 + 批量导入（飞书解析→审核队列，haiku 建议态）+ 挖掘批次骨架 + drift 检测
