## 1. 项目一句话 + 转向声明

COOLFLY 智能客服自研范围 = **知识运营中台**：独立内部 Web（桌面 1280+，简体中文，十视图五组，RBAC 四角色真实账号）+ 三类无界面服务端能力（中台→Zendesk 单向同步与 drift 检测／Zendesk 会话每日批次挖掘／中→英 AI 翻译管道）。C 端体验（帮助中心、AI bot 在线聊天、邮件与转人工工单）与客服工作报表全部由 Zendesk 承担——**零 C 端界面、零对话运行时**。

**转向声明（必读）**：08-04-2026 D-10 拍板后，原 F01–F08 自研对话线（RN 对话页/SSE 流式/意图分类/三层拒答/排障卡片流/埋点看板）**整体废止**——不要给这些线写任何新代码。功能标准 = 用户自制 v3 原型 `output/pages/知识运营中台v3.dc.html`。App 侧本期完全不动。retired ID 永不复用（PRD §0.4/§12.4）。

**三条权威原则（铁律，服务端构造保证，不是 UI 约束）**：

1. **中台 = 知识唯一权威源**：录入/修订/审核/发布全在中台，中台→Zendesk 单向同步；Zendesk 端被直接改写 = drift，检测报警并处置（覆盖/拉回）。
2. **统一过审**：全部新条目/修订/挖掘候选/优化建议一律经审核中心 + 发布门禁后才生效同步——无人审不生效，任何角色无绕过审核的发布路径（发布路径唯一 = /review 门禁成功路径，API 层强制）。
3. **中文 = 内容权威源**：英文经 AI 翻译 + 人工校验（100% 铁律）后才可同步；内部段落不翻译、不对外。

**异常原则（写死，PRD §5.1）**：任何失败态（同步/翻译/向量/批次）**如实标注 + 保留上次可用内容 + 提供重试路径**，不静默吞错；不存在「阻断但已同步」类中间态。

|--------|-----------|-----------|---------|-----------|
| 新建 / 编辑知识条目 | ✓ | ✓ | — | — |
| 提交审核 | ✓ | ✓ | — | — |
| 审核通过 / 驳回 | — | ✓ | — | — |
| 发布到 Zendesk | — | ✓ | — | — |
| 版本回滚 | — | ✓ | — | — |

| 用户与角色管理 | — | — | — | ✓ |
| 查看全量审计日志 | — | ✓ | — | ✓ |

- **四眼原则（硬约束）**：审核员自己提交的条目须另一名审核员通过——审核通过接口内校验提交人 ≠ 当前用户（AC-P-23）。
- **实现**：权限中间件覆盖全部写路由（每路由声明所需权限点，preHandler 查矩阵，越权 403 带原因文案 key）；矩阵存库 + 进程内缓存写时失效；权限变更即时生效、禁用账号会话即时失效（AC-P-22/24）。
- 角色定位：知识管理员=生产主力无发布路径；审核员=审核/发布/回滚/drift 处置唯一执行者；AI 运营=只读+建议；系统管理员=管人不管内容（职责分离）。

## 6. Zendesk 集成四面（零 SDK：Node 24 原生 fetch + API token，技术方案 §4.4）

1. **同步推送（Guide API）**：发布→按映射推送。映射：知识库→brand、目录→Category、章节→Section、条目→Article、标签→label_names、仅内部→客服 user segment、英文→Article Translation（en-us）。动作三类：更新正文+labels / 创建 / 归档+重定向（下线不裸删）。推送前按可见性拆分（混合条目剥离内部段落）；英文非「已确认」整条阻断（中英同发建议值）。目标 Section 不存在→失败并提示修复映射，**不自动创建 Zendesk 结构**。批量迁移 120+ 篇分批推送避开限流。
2. **挖掘拉取（Support API + 在线聊天导出）**：node-cron 每日批次增量拉取昨日会话（start_time 游标）；在线聊天导出端点依订阅形态（Live Chat vs Messaging）**列核实清单实现期核验**。失败→批次表标「失败」+原因，次日照常，不静默缺批次。拉取内容先脱敏再进挖掘。
3. **drift 检测（轮询为主）**：每篇已同步 Article 持「已发布内容规范化哈希」；每小时（建议值）先比 updated_at 缩小面再比正文哈希→差异写 drift 表→报警（同步中心+飞书机器人）→审核员双处置：覆盖（推送中台版本留痕）或拉回（进审核中心）。Webhook 为升级位（事件覆盖面核验后启用），轮询兜底不撤。drift 与待发版本冲突：先处置 drift 再放行同步。
4. **信号采集（只读）**：工单 solved/reopen/CSAT、文章投票、客服 flag 周期拉取落信号表，带确定性档位；bot 锚点引用等待核实信号核实前标「待核实」不进达标判定；**Explore 不集成**（页签只做口径说明与指向，AC-P-19）。

统一处理：认证头、429 退避（读 Retry-After 指数退避封顶）、错误分类（凭据失效单列告警指向 owner=内部技术团队）。

## 7. 状态机与发布门禁

**四条状态机（合法流转表内聚领域层，非法流转 409）**：

- **条目**：草稿 → 编辑中 → 待审核 → 审核中 → 审核通过 → 已发布（支线：已驳回→修改重提；已下线=Zendesk 归档+重定向）；版本级另有「历史版本」「已回滚」（流转图 PRD §6.2）
- **英文翻译**：未生成 → AI 翻译中 → 待人工校验 → 已确认 → 已同步（异常：翻译失败 / 待重新校验）；**「已确认」前同步禁用；中文变更即置「待重新校验」并阻断（服务端强制）**；翻译失败保留上次英文可重试，连续 3 次（建议值）告警
- **同步**：未同步 / 待同步 / 同步中 / 已同步 / 失败 / 已阻断 / 已归档
- **向量**：未向量化 / 向量化中 / 已向量化 / 待重建 / 向量失败；内容变更置「待重建」；失败/待重建条目不参与查重与代理评测且界面明示；发布前待重建须先重建

**发布门禁四查（/review/:id/publish 执行链，技术方案 §6.6）**：

```text
①格式与字段完整性（标题/章节/可见性/标签已填）
②敏感信息与内部口径（内部段落已标记，剥离产物核验不含内部内容）
③英文版本状态（未「已确认」→ 阻断并展示原因）
④代理评测（本台向量检索召回验证；固定标注「代理指标不等于 Zendesk AI 真实表现」）
→ 全过：置「已发布」+ 写同步任务（同事务收口）
→ 不过：阻断展示原因，条目留在审核通过态待整改
```

**翻译管道**：中文权威源→段落级拆分（内部段落跳过）→ Claude sonnet 档逐段翻译（generateObject 段落对齐）→ 待人工校验 → 逐段校验（可修正表述不得改口径，修订留痕）→ 已确认 → 随同步任务推 en-us。

**挖掘管道**：每日批次（低峰）→ 拉取昨日会话 → 脱敏 → fastembed+pgvector 语义聚类计频（英文侧）→ 三重准入（①频次 ≥10 次/周 ②查重 ≥0.85 挂修订不新建 ③缺口判定）→ sonnet 档起草（新增/修订/合并三类候选）→ 候选落库 → 视图④处置 → 全部经审核中心。冷启动语料=原 G1 历史数据导出。
