## 拆解结论（实体-视图分析先行）

1. **单对话页承载多功能（PRD 写死，不拆）**：排障由会话流承载，步骤卡/追问卡/情绪置顶卡/转人工提示条均为会话流内消息元素，「不做独立全屏模式或浮层页面」（PRD §5.3 R5-S1）。因此 F01/F02/F04 的全部会话内交互归属同一页面，会话流内消息卡**不拆**为独立页面。
2. **全屏级抽屉单列**：转人工确认面板为对话页内底部抽屉（全屏级模态，蓝图 §4 已确认），按「全屏级模态/抽屉=独立页面」规则单列一行。
3. **CRUD 拆解不适用**：本产品无面向用户的业务对象列表页/详情页/表单页（唯一表单=面板内 Add details 单字段，属面板页范围）；看板为单页+维度切换、无分页（蓝图 §5）。
4. **认证门禁不补页**：requirements 无注册/登录 Source ID——App 用户身份由宿主登录态注入 RN 容器，看板与知识库管理台为 Basic Auth 口令（蓝图 §3，管理台与看板同访问体系），**不生成任何账号页面**。
5. **异常/隐性状态全部为页面内状态**：空态（新会话开场）、响应中/流式、超时重试、流式中断、LLM 降级、离线、发送失败、已转接等待（目标/底线）、24h 过期、旧版本降级（PRD §7.1/§7.6）均不出独立页面，逐项列入对应页面「功能范围描述」。
6. **无界面功能如实登记**：F05 回流消化工作面=F09 管理台审核队列承接（PAGE-F09-01，08-04 拍板；周度导出保留为导出能力）、F07=两条约束、F06 容量预警=飞书机器人推送；F05 导出物/F07/F06 推送无页面部分登记于「无界面功能归属」表，不造页面。
7. **planned 页面只登记**：后续阶段条目仅记 `planned + 前置依赖 + 与 MVP 关系 + 功能范围`，本轮不出施工任务、不创建文件（蓝图 §4）。
