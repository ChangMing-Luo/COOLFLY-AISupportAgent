## 0. 系统定位与三条铁律

| 项 | 内容 |
|---|---|
| 产品定位 | 运行时 = Zendesk（帮助中心 / AI bot / 工单 / Explore）；**本台 = 知识唯一权威源**（生产 → 审核 → 发布同步 → 反馈回流 → 对话挖掘 → 效果统计） |
| 品牌与语言 | 界面 100% 简体中文（仅品牌词 `COOLFLY` 与技术标识例外）；文案集中在 `@kb/contracts` 的 `zhCN`，前端不硬编码中文业务文案 |
| 铁律① 统一过审 | 全部新条目 / 修订 / 挖掘候选 / 批量导入 / 反馈建议一律经审核中心；**发布 API 是同步队列的唯一写入源**，任何角色无绕过审核的发布路径 |
| 铁律② 人工校验 100% | 英文（标题 + 正文）未「已确认」不可同步 Zendesk；中文一改，英文自动置「待重新校验」并阻断同步 |
| 铁律③ 审计不可变 | 操作日志只增不改不删、长期保留（数据库层禁 UPDATE/DELETE） |

所有登录后页面共用一套外壳，代码：`app/web/src/App.tsx`。

│ 知识运营中台                                    │        右侧：身份徽章 / 待审 N /   │
│ 运行时 = Zendesk · 本台 = 唯一权威源             │              同步失败 N            │
│                                                ├────────────────────────────────────┤

│ 知识生产      · 知识库总览 [徽标]                │        content 视图内容区          │

### 1.1 全局元素规格

| 元素 | 规格 |
|---|---|
| 品牌区 | 三行：`COOLFLY` / `知识运营中台` / `运行时 = Zendesk · 本台 = 唯一权威源` |
| 导航分组 | 5 组固定顺序：工作台、知识生产、质量与发布、数据、治理 |
| 导航徽标 | 来自 `GET /api/nav/counts`：`kb`（条目总数）、`review`（待审核+审核中）、`sync`（失败/阻断，红色 `--alert`）、`mine`（待处置候选）、`feedback`（待处置修订候选）；值为 0 时不显示 |
| 权限门控导航 | `数据看板`/`反馈回流` 需 `metrics.view`，`用户与权限` 需 `rbac.manage`；无权限时按钮 `disabled` + title「当前角色无此视图权限」，点击弹 toast「当前角色（AI 运营/本角色）无「X」权限」 |
| 顶栏 | 左：面包屑（`zhCN.crumbs`，如「知识生产 / 知识库总览 / 条目」）+ H1 页面标题；右：`<姓名> · <角色>` 强调徽章、`待审 N`、`同步失败 N`（>0 时红色） |
| 身份区 | `当前身份：<姓名> · <角色标签>` + `退出登录` 按钮（`POST /api/auth/logout` → 回登录页） |
| 视图切换 | 单页应用内 `goto(view, entryId?)`，不走 URL 路由；进入 `条目工作台` 不带 id = 新建（会清空上次条目 id） |
| toast | 全局唯一，所有成功/失败/越权提示统一走它 |
| 加载与错误 | 统一 `加载中…` 空态块 与 `note note--bad` 错误条；启动时先 `GET /api/auth/me`，未登录直接渲染登录页 |

### 1.2 通用组件

| 组件 | 说明 |
|---|---|
| `StatusPill` | 状态徽章，6 档语义色：`ok` 绿 / `warn` 黄 / `bad` 红 / `info` 中性 / `accent` 强调 / `plain` 无色 |
| `ConfirmModal` | 二次确认弹窗，统一结构：标题 + **后果清单（逐条列明）** + 可选表单插槽 + `取消` / 确认按钮（危险动作红色） |
| `GatedButton` | 权限门控按钮（条目工作台专用）：禁用态仍可点外层容器并弹出「禁用原因」toast，兼顾恒禁用与明示原因 |
| `useAsync` | 数据加载 hook，返回 `{data, loading, error, reload}`；每个数据区块独立 loading/error |
| 表格交互 | 行可点（`row--click`）→ 跳详情；告警行 `row--alert` 红底、临期行 `row--warn` 黄底；宽表 `table--wide` + 横向滚动容器 |

### 1.3 通用状态与徽章口径（`@kb/contracts`）

| 维度 | 取值 → 中文标签 |
|---|---|
| 条目状态（8） | `draft` 草稿 / `editing` 编辑中 / `pending_review` 待审核 / `reviewing` 审核中 / `approved` 审核通过 / `published` 已发布 / `rejected` 已驳回 / `offline` 已下线 |
| 条目状态合法流转 | draft→(draft,editing,pending_review)；editing→(editing,draft,pending_review)；pending_review→(reviewing,approved,rejected)；reviewing→(approved,rejected,pending_review)；approved→(published,editing)；published→(editing,offline)；rejected→(draft,editing,pending_review)；**offline→editing**（可重新上架）。非法流转服务端 409 |
| 英文状态（7） | `none` 未生成 / `translating` AI 翻译中 / `pending_human` 待人工校验 / `confirmed` 已确认 / `synced` 已同步 Zendesk / `failed` 翻译失败 / `stale` 待重新校验；**仅 confirmed/synced 允许同步** |
| 同步状态（7） | `none` 未同步 / `queued` 待同步 / `running` 同步中 / `synced` 已同步 / `failed` 失败 / `blocked` 已阻断 / `archived` 已归档 |
| 可见性（3） | `public` 对外公开 / `internal` 仅客服内部 / `mixed` 对外公开 + 内部段落 |
| 审核来源（5） | `mining` AI 挖掘 / `manual` 人工录入 / `revision` 版本修订 / `feedback` 反馈修订 / `import` 批量导入 |
| 版本状态（4） | `current` 已发布 / `history` 历史版本 / `rolled_back` 已回滚 / `pending` 待审核 |
| 批次状态（3） | `completed` 完成 / `empty` 无新草稿 / `failed` 失败 |
| 候选类型（3） | `new` 新增 / `revision` 修订 / `merge` 合并 |
| 信号确定性（3） | `certain` 原生 · 必得 / `tier_dependent` 档位相关 / `unverified` 待核实（**不进达标判定**） |

## 3. 登录 / 首次改密（`views/Login.tsx`）

### 3.1 布局
居中单卡（`login__card`），无侧栏无顶栏。

### 3.2 字段与按钮

| 状态 | 字段 | 校验 | 按钮 |
|---|---|---|---|
| 登录态 | 邮箱（`type=email`，必填，autocomplete=username）；密码（`type=password`，必填，autocomplete=current-password） | 浏览器原生必填 + 服务端 `loginSchema`（邮箱格式 / 密码必填） | `登录`（占满宽度，提交中文案「登录中…」并禁用） |
| 首次改密态 | 新密码（`type=password`，必填，`minLength=8`） | 至少 8 位（前端 + 服务端 `changePasswordSchema`） | `设置新密码并进入` |

### 3.3 交互行为
1. 卡头三行：`COOLFLY` / `知识运营中台` / `运行时 = Zendesk · 本台 = 唯一权威源`。
2. 提交 → `POST /api/auth/login`；若 `user.mustChangePassword=true`，**不进主界面**，切换为「首次登录请修改密码」卡（副标题显示账号邮箱 + 「首次登录强制改密（账号安全前置）」）。
3. 改密 → `POST /api/auth/change-password`（带当前密码 + 新密码）→ 成功后 `GET /api/auth/me` 拿最新会话进入主界面；`ok=false` 时在卡内显示红色错误条。
4. 失败一律以卡内 `note note--bad` 呈现（不用 toast）。
5. 登录接口带**限流**（默认 10 次/分钟，`LOGIN_RATE_MAX` 可配）。

## 4. 视图规格

### 4.1 ① 我的工作台（`views/Workbench.tsx`）

**目标**：登录第一屏，按「我」的待办分组收敛，四卡 = 四分组的双入口。数据源 `GET /api/workbench`。

#### 4.1.1 布局
```
[我的草稿]  [我提交待审]  [被驳回待改]  [待我审核]      ← 四张可点统计卡（点击=切分组）
┌───────────────────────────────────────────────────────────────┐
│ 页签：我的草稿箱(N) 我提交的(N) 被驳回(N) 待我审核(N)          │
│                              分组提示语 …    [新建条目]        │
│ 表格：条目 / 所属结构 / 状态 / 中文·英文 / 最近操作 / 下一步动作 │
└───────────────────────────────────────────────────────────────┘
┌── 你的角色能做什么（RBAC 生效范围）：10 个权限徽章 + 角色说明 ──┐
```

#### 4.1.2 统计卡

| 卡 | 数值 | 提示语 | 特殊态 |
|---|---|---|---|
| 我的草稿 | `cards.drafts` | 未提交，仅自己可见 | — |
| 我提交待审 | `cards.submitted` | 等待审核员处理 | — |
| 被驳回待改 | `cards.rejected` | 带审核意见回退 | — |
| 待我审核 | `cards.toReview` | 含 AI 挖掘与人工提交 | 无 `review.decide` 时数值显示 `—`，提示语改「（无审核权限）审核属于知识审核员」 |

卡片选中态 `stat--active` 与页签联动（同一 `group` 状态）。

#### 4.1.3 表格字段

| 列 | 内容 |
|---|---|
| 条目 | 标题（加粗）+ 条目号（等宽小字）；`status=rejected` 且有理由时下方红条「驳回理由：…」 |
| 所属结构 | `path`（目录 → 章节） |
| 状态 | 条目状态徽章（语义色） |
| 中文 / 英文 | `中文 已保存 / 英文 <英文状态标签>` |
| 最近操作 | `MM-DD HH:mm` |
| 下一步动作 | 服务端计算的动作文案按钮（点击进条目工作台，`stopPropagation` 防重复触发） |

#### 4.1.4 按钮

| 按钮 | 位置 | 权限/禁用 | 行为 |
|---|---|---|---|
| 四张统计卡 | 顶部 | 无 | 切换当前分组 |
| 四个页签 | 卡头左 | 无 | 切换当前分组（标签带条数） |
| `新建条目` | 卡头右（主按钮） | 需 `entry.write`，否则禁用 + title「当前角色对编辑器只读，无法修改内容。」 | `goto('entry')` 进新建态 |
| 行 / `下一步动作` | 表格 | 无 | 进入该条目工作台 |

#### 4.1.5 空态与提示
- 分组无数据：`这个分组暂无条目` + 分组专属副文案（待我审核用服务端 `emptyHint`，默认「待审队列已清空——当前没有等待你处理的条目。」）。
- 分组提示语：草稿「草稿仅本人可见，提交后进审核中心」/ 我提交的「提交后由知识审核员处理，可在此看进度」/ 被驳回「按审核意见修改后可重新提交」/ 待我审核「状态与下一步动作由 RBAC 决定」。
- 底部 RBAC 卡：10 个权限逐项 `可 X`（绿）/`禁 X`（红）+ 当前角色定位说明（`ROLE_NOTES`）。

### 4.2 ② 知识库总览（`views/KbOverview.tsx`）

**目标**：多库并行 + 三级结构树（目录 → 章节 → 条目）+ 条目列表五筛选；结构维护与批量导入的入口。

#### 4.2.1 布局（左固定 240–260px / 右自适应）
```
┌── 左列 ──────────────────┐ ┌── 右列：条目列表 ─────────────────────────────┐
│ 知识库（多库并行）        │ │ 条目列表 · <库名>（共 N 条）                    │
│  [一键批量导入]          │ │ （若选中章节）已按章节「X」筛选（N 条）[清除]    │
│  ▣ 库卡片×N（条数/说明）  │ │ 筛选行：搜索框 / 场景 / 状态 / 可见性 / 复核到期 │
├──────────────────────────┤ │ 宽表 12 列（横向滚动）                          │
│ 结构树  [仅已发布]        │ │ 尾注：点任意行进入条目工作台…                   │
│ 工具条：新建目录 新建章节 │ └─────────────────────────────────────────────────┘
│         调整层级          │
│ ▾ ▣ 目录（计数）[重命名][删除]
│   ▾ 章节  Zendesk 5407…（计数）[重命名][移动][删除]
│     ▤ 已发布条目（点击进工作台）
│ 结构映射说明 / 删除防护说明
└──────────────────────────┘
```

#### 4.2.2 知识库卡片（`GET /api/kb/libraries`）
字段：库名、`N 条`、说明（`note`）；`internalOnly=true` 追加徽章「不对外公开，仅挂客服 segment」。首个库默认选中；切库同时清空章节筛选。

#### 4.2.3 结构树（`GET /api/kb/tree?libraryId=`）

| 层级 | 图标/控件 | 显示 | 行内操作（需 `structure.manage`） |
|---|---|---|---|
| 目录（root） | `▾/▸` caret + `▣` | 名称（加粗）+ 条目计数 | `重命名`（行内输入 + 保存/取消）、`删除`（红） |
| 章节（child） | caret（无条目时显示 `·`） | 章节名（按钮，点击=按章节筛选，可再点取消）+ `Zendesk <id>` 或 `Section 未映射` + 计数 | `重命名`、`移动`、`删除`（红） |
| 条目（leaf） | `▤` | **仅已发布条目**标题（超长省略），点击 → 条目工作台 | — |

默认展开首个目录及其首个章节；树头右侧常驻徽章 `仅已发布`。

#### 4.2.4 条目列表（`GET /api/kb/entries?libraryId&status&visibility&due&q`）

筛选：
| 控件 | 取值 | 侧 |
|---|---|---|
| 搜索框（`type=search`） | 标题 / 标识 / 标签 | 服务端 |
| 问题场景 | 从当前结果集去重生成 | 前端 |
| 状态 | 8 档条目状态 | 服务端 |
| 可见性 | 3 档 | 服务端 |

#### 4.3.3 状态流转条
主链路 6 态按序展示：已过步骤 `✓ 绿`、当前步骤 `● 强调`、未到 `无色`，中间用 `›` 连接；`rejected` / `offline` 不在链路上，右侧单独红徽章 `⚠ 已驳回 / ⚠ 已下线`。右端显示「最近操作：<人>（<角色>） · <动作> · <时间>」或「暂无操作记录」。

#### 4.3.4 门禁提示条（`GET /api/review/:id/gate`，`core/gate.ts` 三查）

| 情形 | 呈现 |
|---|---|
| 无 `publish` 权限 | 黄条：发布权限仅知识审核员…（统一过审铁律） |
| 新建未保存 | 中性条：保存并提交审核后才会跑发布门禁（三查：格式与字段完整性 / 敏感信息与内部口径 / 英文版本状态） |
| 有硬阻断 | 红条：「发布门禁未通过（N 项硬阻断），不入同步队列：」+ 逐条 `<检查名>——<明细>` |
| 全过 | 绿条：「门禁通过：正文已保存、英文已确认，可发布并同步。」 |

三查明细口径：
1. **格式与字段完整性**：标题 / 章节 / 可见性 / 标签缺一即阻断，明细列出缺失字段。
2. **敏感信息与内部口径**：混合可见性必须已标内部段落；剥离产物不得含内部段落原文；剥离后对外正文不得为空。
3. **英文版本状态**：英文状态须 `confirmed`/`synced`，且**英文标题非空**，否则阻断（明细分别为「英文未确认——同步将被阻断（人工校验 100% 铁律）」/「英文标题缺失——译文会挂中文标题，同步将被阻断」）。

#### 4.3.8 页签②③④

**② 版本与回滚**
- `版本列表`（副标题「效果指标绑定到版本；历史版本与指标只增不删」）10 列：版本号 / 变更说明 / 状态 / 生效区间（`起 → 至今`）/ 操作人 / 调用 / 命中率 / 解决率（<60% 红）/ 采纳率 / 操作；当前版行黄底。
- 行操作 `回滚到此版本`（危险小按钮）：仅非 `current`/`pending` 行出现，需 `version.rollback`（原因「版本回滚仅知识审核员可执行。」）→ **危险弹窗**「回滚到 vN（说明）」后果四条（目标版正文重新生效并以新版本号对外发布 / 当前版标记「已回滚」/ 写操作日志与同步队列（分钟级推送 Zendesk）/ 历史版本与各版指标不删除可再比对）→ `POST /api/review/:id/rollback`。
- 回滚建议条（黄）：当前版解决率较历史最高版跌幅 ≥15pp 时出现，给出具体 pp 与建议动作。
- `内容 Diff 对比`：左右版本下拉 + 逐行 LCS 对齐 diff（红底删除行 / 绿底新增行 / 灰同行）；版本不足两个显示「版本不足两个，无法比对。」
- 新建条目：`新建条目尚无版本记录。`

**③ 效果指标**
- 四统计卡：调用次数（近 30 天 · bot + 人工引用合计）/ 命中率（检索到本条目 / 相关提问）/ 解决率（引用后会话判解决 · 近似归因（非因果）；`sampleShort` 时显示「样本积累中」并注「引用不足 10 次，不做达标判定」，<60% 红字）/ 采纳率（bot 引用后真正写进回答）。
- `各版本解决率对比`：横条图，<60% 红条。
- `条目级反馈信号`（副标题「待核实档位的信号不进达标判定」）4 列：渠道 / 信号类型 / 原文摘录 / 确定性（徽章）；底部聚合计数「bot 引用 N · 客服引用 N · 被踩 N · 客服 flag N」。

**④ 操作日志**
时间线（时间 / 操作人（角色）· 动作 / 字段改前→改后（红→绿底）/ 备注），标题「条目日志」，副标题「本条目全量留痕 · 与全局操作日志同源 · 操作日志只增不改不删、长期保留」；空态「本条目暂无留痕记录。」

|---|---|---|---|
| 回滚确认 | 版本行 `回滚到此版本` | 见上（4 条） | `确认回滚`（危险） |
| 下线确认 | 头部 `下线` | ①状态置「已下线」，不再对外提供——但不是删除 ②Zendesk 端文章归档 + 重定向，不裸删，帮助中心不会留死链 ③版本历史、各版效果指标、审计日志全部保留可查 ④需要再次上架时：重新编辑（自动回「编辑中」）→ 提交审核 → 通过 → 发布 | `确认下线`（危险）→ toast「已下线：Zendesk 端文章归档 + 重定向；版本历史与效果指标保留，重新编辑并过审即可再次上架」 |

#### 4.3.10 并发与异常交互
- **乐观锁冲突**：保存返回 409 → 红条显示服务端冲突文案 + 按钮 `放弃本地改动，载入最新版本`（重新灌表单）。
- 表单在载入完成 / 保存成功后按 `lockVersion` 重新灌入（避免脏值覆盖）。
- 条目加载失败：整页红条「条目加载失败：<原因>」。
- 驳回理由（红条）/ 同步阻断原因（黄条）常驻在门禁条下方。

| 按钮 | 出现条件 | 行为 |

### 4.5 ⑤ 审核中心（`views/Review.tsx`）

**目标**：统一过审的唯一入口；两层变更对照（摘要层 + git diff 详情层）+ 门禁三查 + 通过/驳回/发布。

#### 4.5.1 布局（左右等宽两栏）
```
顶部说明条：统一过审：全部新条目 / 修订 / 挖掘候选 / 优化建议一律经本中心…
┌── 待审 N 条 ───────────────┐ ┌── 审核详情 · <标题> ────────────────────┐
│ 表：来源 / 条目 / 版本 /    │ │ 徽章：条目状态 · 来源：X                  │
│     提交人 / 提交时间       │ │ 变更摘要 [+N −M ~K]      [查看具体变更]   │
│ （点行选中，行黄底）        │ │ 摘要列表（+ / − / ~ 三色）               │
│                            │ │ （展开）git diff 视图：行号|行号|符号|文本│
│                            │ │ 正文全文（内部段落带黄徽章）              │
│                            │ │ 发布门禁三查（✓/✗ + 明细）               │
│                            │ │ [通过][驳回][发布并同步][打开条目工作台]  │
└────────────────────────────┘ └─────────────────────────────────────────┘
```

#### 4.5.2 待审队列（`GET /api/review/queue`）
列：来源（强调徽章，五类）/ 条目（标题 + `编号 · 章节路径 · 可见性`）/ 版本 / 提交人 / 提交时间；默认选中首行；点行切换详情并**收起 diff**。空态「当前没有待审条目」。

#### 4.5.3 变更对照两层
- **摘要层**（随队列返回）：`变更摘要` + 总量徽章（`diffTotal`）+ 逐条摘要（`+` 新增 / `−` 删除 / `~` 修改，三色）；无差异显示「（无差异记录）」。
- **详情层**（按需 `GET /api/review/:id/diff`）：`查看具体变更` / `收起` 切换；git diff 视图，每行 = 变更前行号 | 变更后行号 | 符号 | 文本（内部段落前置黄徽章「内部段落」）；头部标注新建条目「新建条目（无变更前侧）」；脚注「红底 − 为删除、绿底 + 为新增、灰字为未变更上下文。」

#### 4.5.4 正文全文与门禁
- `正文全文`：逐段展示，内部段落带「内部段落」黄徽章，小标题加粗。
- `发布门禁三查`：每查一行 `✓/✗` 徽章 + 检查名 + 明细（同 §4.3.4）。

#### 4.5.5 按钮

| 按钮 | 权限/禁用 | 行为 |
|---|---|---|
| `通过`（主） | `review.decide`，否则禁用 + title「审核权限仅知识审核员。」 | `POST /api/review/:id/approve` → toast「已通过「X」，可执行发布并同步」 |
| `驳回`（危险） | 同上 | 打开驳回弹窗（4.5.6） |
| `发布并同步` | 需 `publish` 且状态 = `approved`（否则 title「需先审核通过」） | `POST /api/review/:id/publish`；成功 toast「已发布「X」并写入同步队列」，被挡 toast「发布被门禁阻断：<各硬阻断明细分号连接>」 |
| `打开条目工作台` | 无 | 跳条目工作台 |

提示条：
- 自提交条目：中性条「这条由你本人提交——四眼原则已取消，你可以直接通过；该次审核会在操作日志中留痕（提交人 = 审核人）。」
- 无决策权限：黄条「当前角色只能查看，不能通过或驳回。」
- 常驻尾注：「通过后自动跑发布门禁：静态检查 + 英文校验状态，全过才入同步队列。」

#### 4.5.6 驳回弹窗
危险弹窗「驳回「X」」：后果三条（条目回提交人草稿箱并标「已驳回」/ 驳回理由回传提交人并写入审核历史 / 提交人按意见修改后可重新提交）；表单：`驳回理由（必填）` 文本域（placeholder「例如：计费周期与财务口径不符，请附财务确认截图」）；空理由点确认 → 内联红条「驳回理由必填——审核意见会回传给提交人并留痕。」；确认 `确认驳回` → `POST /api/review/:id/reject`。

### 4.10 ⑩ 用户与权限（`views/Rbac.tsx`）

**目标**：用户管理 / 角色管理 / 权限矩阵；系统管理员「管人不管内容」。

无 `rbac.manage` 时页顶黄条：「当前角色只读本页：创建用户、启停账号与修改权限矩阵仅系统管理员可执行（管人不管内容）。」

#### 4.10.1 页签①「用户管理」

**用户列表**（`GET /api/rbac/users`）7 列：姓名 / 邮箱 / 角色（强调徽章）/ 知识库范围 / 最后活跃 / 状态（启用绿 / 已禁用红）/ 操作；禁用行整行半透明。
尾注：「禁用用户会话即时失效，其历史操作日志与已发布内容全部保留；权限范围按知识库粒度授权（可授单库）。」

| 按钮 | 权限 | 行为 |
|---|---|---|
| `禁用`（危险，小） | `rbac.manage`，否则禁用 + title 只读说明 | 打开禁用确认弹窗 |
| `启用`（小） | 同上 | 直接 `POST /api/rbac/users/:id/toggle {enabled:true}` → toast 用服务端返回文案 |

**创建用户表单**（`POST /api/rbac/users`）：

| 字段 | 控件 | 校验 |
|---|---|---|
| 姓名 | 文本，必填（placeholder「例如：周凛」） | 服务端 `姓名必填` |
| 邮箱 | `type=email`，必填（placeholder「例如：zhoulin@coolfly.com」） | 邮箱格式；重复 → 409「该邮箱已存在」 |
| 角色 | 下拉四角色 | — |
| 初始密码（至少 8 位） | `type=password`，必填，`minLength=8` | 前端内联错误「初始密码至少 8 位」 |
| 知识库范围（必选至少一个） | 多选 checkbox 药丸（来源 `/api/kb/libraries`） | 未选 → 内联错误「知识库范围必选至少一个（可授单库）」 |

提交按钮 `创建用户`（提交中「创建中…」）+ 旁注「创建即写审计日志；新用户首次登录强制改密。」；成功 toast「已创建用户（首次登录强制改密）」并清空表单。

**禁用确认弹窗**：危险，标题「禁用「X」」，后果三条（该账号当前会话即时失效，需重新登录才能继续操作 / 历史操作日志与已发布内容全部保留（审计只增不改不删）/ 可随时重新启用，账号数据不丢失），确认 `确认禁用`。

#### 4.10.2 页签②「角色管理」（`GET /api/rbac/roles`）
四张角色卡（两列）：角色名 + `N 人` + 角色定位说明 + `允许`（绿药丸列表）+ `禁止`（红药丸列表）；无项显示「无」。
尾注：「角色定位：知识管理员管生产不管发布、知识审核员是审核发布回滚的唯一执行者、AI 运营只读加建议、系统管理员管人不管内容。」

#### 4.10.3 页签③「权限矩阵」（`GET /api/rbac/matrix`）
标题「权限矩阵 · 10 项 × 4 角色」（可管理时追加小字「点格子切换，改动即写审计日志」）；只读角色顶部黄条「权限矩阵仅系统管理员可修改」。
表格：行 = 10 项权限（中文标签），列 = 4 角色；单元格：可管理时为按钮（`✓` 主色 / `✗` 红），title「<角色>：<权限> — 点击切换为允许/禁止」，点击 `PUT /api/rbac/matrix` → toast「已更新权限矩阵（改动已写审计日志）」并重载；只读时为徽章。
尾注硬约束（**不可通过矩阵放开**）：①提交人不能审核自己提交的版本；②任何角色都不能跳过审核直接同步 Zendesk；③AI 运营始终不可写内容。
> 口径提示：①在 08-05-2026 拍板中已实际取消（审核中心允许自审并留痕），此尾注与代码行为存在文案残留，见 §8。

## 5. 角色与权限矩阵（默认值）

| 权限点（中文标签） | 知识管理员 | 知识审核员 | AI 运营 | 系统管理员 |
|---|---|---|---|---|

| 版本回滚 `version.rollback` | ✗ | ✓ | ✗ | ✗ |

| 查看全量审计日志 `audit.viewAll` | ✗ | ✓ | ✗ | ✓ |

矩阵存 DB（`permission_matrix`），改动即时生效并写审计；越权拒绝文案与接口共用同一 key（`PERMISSION_DENIED_TEXT`）。

角色定位：
- **知识管理员**：录入/编辑/结构维护/处置挖掘候选/提交审核；不能审核通过、不能发布、不能回滚。
- **知识审核员**：审核、发布、同步、回滚的唯一执行者；可审核自己提交的条目，全部动作写审计日志。
- **AI 运营**：编辑器只读，禁审核/发布/回滚/同步；可看数据并提交优化建议。
- **系统管理员**：仅用户与权限 + 审计日志，不参与内容审核发布。

## 7. 关键流程（界面动线）

```
新建闭环：
我的工作台[新建条目] → 条目工作台（填字段+写中文正文）
  → [保存中文草稿] → [生成英文翻译] → 人工逐段校验 + 英文标题
  → [标记已确认] → [提交审核]
  → 审核中心（选条目 → 看变更摘要/具体变更 → 三查全绿）→ [通过]
  → [发布并同步] → 同步中心（待同步 → 已同步）→ Zendesk 帮助中心

批量迁移：
知识库总览[一键批量导入] → 粘贴/上传 → 解析预览（改标题/章节/可见性）
  → [一键导入] → 全部进审核队列（来源「批量导入」）→ 审核中心逐条过审

挖掘闭环：
AI 对话挖掘（批次 → 三重准入）→ [起草并提交审核 / 挂为修订建议 / 发起合并 / 丢弃]
  → 审核中心（来源「AI 挖掘」）

反馈闭环：
数据看板·知识缺口[起草/挂修订] → 跳转反馈回流 → [转为修订建议]
  → 审核中心（来源「反馈修订」）

下线与回滚：
条目工作台[下线] → Zendesk 归档+重定向（可重新编辑上架）
条目工作台·版本与回滚[回滚到此版本] → 目标版重新生效 + 写同步队列
```
