# 设计决策蓝图（已与用户逐轮确认 · 08-03-2026）

> 上游契约：PRD详细版.md（1424 行）+ requirements.md（revision 1，REQ×37 / AC×54 / NFR×5 / US×20）。PRD 已把界面元素、状态矩阵、文案定稿、边界数值写死——本蓝图只记录 PRD 之上的设计/技术拍板与落地骨架，行为规格一律以 PRD 为准，不复制。

## 1 盘子

- **端形态**：客服模块嵌入现有 COOLFLY App（原生双端）；**本次客户端前台用 RN Expo 开发**，brownfield 集成进两个原生工程（RN 容器页 + 导航桥接）。（用户拍板 08-03-2026）
- **热更通道**：EAS Update——排障卡片 UI、按钮组、文案随 JS bundle 热更；PRD §9.5「发版线覆盖率爬坡」风险收窄到**原生入口本身**（设备页/我的页 Support 入口、错误态 Get help 按钮、RN 容器接线）。旧版本纯文本降级路径（§7.6/AC-C-04）仍保留，服务"未装 RN 容器的旧版本"。
- **响应式**：手机竖屏为唯一目标形态（375–430pt 宽基准）；看板为桌面 Web（1280+ 宽），不做移动适配承诺。
- **工作台**：App 用户无工作台（直达对话页）；业务负责人的"工作台"= 内部效果看板页。

## 2 信息架构 & 站点地图

- **导航模式**：App 内为"入口 → 单对话页"的扁平结构，无子导航；对话页顶部会话菜单（转人工 / 重看首屏按钮 / 结束会话，PRD §5.2）。看板为单页 + 维度切换器。
- **站点地图（MVP 调用关系骨架）**：

```text
宿主 App（原生，集成点规格）
├── 设备页/我的页 「Support」固定入口 ──┐
├── 错误态「Get help」×3（掉线/配对失败/扫码失败）─┤ 携带故障上下文
│                                        ▼
│                              [RN] 客服对话页（核心页，承载 F01/F02/F04/F08 到达点）
│                                ├── 首屏按钮组 / 自由输入 / 排障步骤卡（会话流内嵌）
│                                ├── 情绪出口置顶卡 / 非英语兜底 / 全部故障态（§7.1）
│                                └── 转人工确认面板（底部抽屉，F03）
│                                      └── 已转接等待态（目标态/底线态双形态）
└── push 通知（目标态回复触达）→ 回到对话页

[Web] 内部效果看板页（F06：双口径/拒答分层/转人工量+预警线/语言分布等）

```

## 3 角色 & 权限

- **认证**：无新增账号体系（PRD 无注册/登录 REQ）。App 用户身份由**宿主 App 登录态注入 RN 容器**（用户标识/凭证/SN/型号/错误上下文/entry_source，经桥接契约传入）；引擎 API 校验宿主签发的凭证。
- **看板访问**：内部只读——「建议值 口令（Basic Auth）+ 访问链接不公开 · 终稿前确认」；使用者=业务负责人+运营三岗。无 onboarding/settings/admin 配置页（外部能力全部 deployment-secret，见 requirements 外部配置表）。
- **同页角色差异**：无（单直接角色产品；客服/业务负责人均为间接接收方，不进 App 界面）。

## 4 页面地图与设计深度

- **MVP 页面（出施工图，pages/*.md + *.html）**：
  1. `阶段1_客服对话_客服对话页`——F01/F02/F04/F08 到达点全承载；空/加载/错误/离线/降级/已转接等待全状态按 §7.1 状态矩阵落卡；文案全部引用 §5 定稿。
  2. `阶段1_人机衔接_转人工确认面板`——底部抽屉形态（摘要预览/ Add details / Send & connect / Not now），等待承诺目标态+底线态双形态、提交失败/连续失败兜底态。
  3. `阶段1_效果度量_内部效果看板页`——§5.7 元素表全落：双口径趋势（entry_source 分层切换）、拒答率分层+区间标红、转人工量+预警线、语言分布/解决时长/满意度/沉默放弃率图卡、"数据回补中/预警线待 G1 回填"降级态。
  4. `阶段1_入口触达_宿主App集成点规格`——非独立页面，输出集成规格文档+入口示意 HTML：固定入口位、三类错误态 Get help、RN 容器桥接契约（注入字段清单）、push 深链回对话页。
- **后续 planned 页面（只登记，不出施工图）**：语音渠道适配层（阶段二首个新渠道）、AI 生成型知识库审核台（F05 演进）、完整多语言、设备诊断、全渠道接入、Zendesk 工作台映射——前置依赖与边界见 PRD §0.1。
- **后续不可逆约束（现在就锁）**：§3.7 五条演进约束；评测集=供应商无关行为契约；channel/entry_source/app_version 埋点第一天就位；交接契约 6 字段顺序固定；**RN 桥接注入契约（本次新增）**：宿主→RN 注入字段（用户凭证/SN/型号/错误上下文类型/entry_source）设计为版本化稳定契约，只增补不改义——它是未来所有入口形态（含阶段二语音）的接线底稿。

## 5 通用交互范式

- **反馈**：会话内联消息为主（成功/失败都是会话流的一部分）；评分致谢用轻 Toast；不用弹窗打断（情绪场景禁打断）。
- **表单**：仅 Add details 单字段（500 字符建议值上限+计数）；无草稿/离开拦截需求（内容随摘要即时提交）。
- **列表**：看板为周粒度图卡+维度切换，无分页/无限滚动需求；回流清单为导出文件不做界面。

## 6 视觉风格锚点

- **来源**：贴合现有 COOLFLY App（用户拍板，将提供截图/品牌色素材）；素材到位前 tokens 用**自然绿主色占位**，到位后仅校准色值、不动结构。
- 明暗：**浅色单模式**（中老年高对比可读性优先）；深色跟随主 App 能力后置。
- Category：C 端移动 · 支持对话（客服场景）；看板=B 端数据页（同一 tokens 派生）。
- 情绪基调：**冷静、安抚、可靠**——用户是带着挫败进来的，界面不能兴奋、不能花哨。
- 交互哲学：**色彩响应**（全站统一）：按下变色/状态变色，无阴影提升、无物理位移动效堆叠。
- 字体：系统字体栈（SF Pro / Roboto）；正文基准 17pt、步骤卡大字 20pt+，系统字号缩放最大档不破版（AC-C-01 硬验收）。
- 设计签名：品牌自然绿 + 来源标注小徽章（"Source: Setup Guide"）+ 步骤卡的大按钮双选（Done / It didn't work）节奏——截图可识别。

## 7 数据与集成

- **核心实体**：会话 / 消息 / 排障进度 / 知识条目 / 排障流程条目 / 埋点事件 / 回流条目 / 评测题（概念 schema 见 PRD §4，本蓝图不复制）。
- **外部对接**：飞书知识库 API（导出+定期增量重建索引，≤24h 生效）；LLM API；push 基建（目标态）；人工客服通路（G3 正/反向查证定目标态/底线态）；飞书机器人（预警推送）。
- **API vs 直连**：RN 前台与看板都只走**引擎 REST API**（引擎渠道无关，§3.7-1）；看板读埋点聚合视图，不直连业务表写路径。
- **同步策略**：飞书→索引=定期增量（≤24h）；埋点=客户端暂存补报、看板最终一致（按周呈报）。
- **方案前置能力**（照抄 requirements）：飞书知识库 ready；历史数据可导出 ready；LLM API committed（DPA 硬条件）；G1–G4 committed（硬窗口 ≤2 周，回退规则写死）。

## 8 技术栈 & 架构 & 部署

- **前台**：RN Expo（brownfield 双端嵌入）+ EAS Update 热更。（用户拍板）
- **看板**：轻量 Web 单页（与引擎同仓部署、直连埋点聚合）。（用户拍板）
- **服务端**（架构建议，拍板 1 形态无关约束下的"选 A 重建"推荐形态；选 B 时行为规格不变、集成点按 G2 对照表适配）：Node.js/TypeScript 单体服务 + PostgreSQL（含 pgvector 检索）+ 渠道适配层（RN/H5 为第一渠道实例）；具体框架与版本号在技术方案中实测后写定。
- **LLM**：Anthropic Claude 方向（对话 Sonnet 档、意图分类/语言检测 Haiku 档；DPA+零留存为签约硬条件；更换供应商须评测集回归通过）。（用户拍板方向，技术负责人终确认）
- **部署**：跟随现有 App 后端所在云的海外区域（具体云/区域列入 G2 盘点确认）；容器化交付保持云中立；管理控制台国内可达无障碍。（用户拍板）
- **文件存储**：排障配图等静态资源随服务/对象存储由现有云能力决定（G2 后定），不预先引入新对象存储。

## 9 安全 & 运维

- 认证安全：复用宿主登录态，引擎校验注入凭证；无独立密码体系；LLM 密钥等全部 deployment-secret。
- 脱敏：会话日志打码后入分析库；F05 导出清单与评测题同规则；AI 不索取密码类信息（§4.5/§7.7）。
- 备份：托管 PostgreSQL 自动每日备份 +「建议值 PITR 7 天 · 终稿前确认」。
- 审计/日志：回流清单导出与看板访问留痕（轻量：时间/操作者/动作）；评测集回归结果留痕（§9.8 技术债第 1 条）。
- 操作可逆：全系统对用户无删除面；知识条目状态化（草稿/已上线/待改造）天然可回退；灰度远程开关即时回滚（§7.8）。
