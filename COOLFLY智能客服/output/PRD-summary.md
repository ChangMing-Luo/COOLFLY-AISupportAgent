## 1. 这是什么（一句话）

在 COOLFLY App 内重建/升级智能客服，让用户几分钟内自助解决安装/联网/配对/会员高频问题，解决不了时顺畅转人工、零复述、不干等。

## 2. 为什么做（核心痛点）

差评里一半是"装不上连不上"——正好是智能客服最能吃掉的问题；现状退货率约 11%（目标 ≤5%），65% 受访者曾因装机挫败退掉无缺陷电子产品（TechSee），退货率每降 1 个点，一年就是 1,000 台不用退（详见 PRD详细版 §1）。

## 3. 给谁做

- **决策者**: 企业家 / COOLFLY 业务线负责人
- **使用者**: App 用户（主力北美、英文；典型状态"刚拿到设备，卡在安装/联网/配对"；中老年占比高、打字意愿低）
- **不是谁**: 客服员工（本期不做任何客服侧工具，未来 Zendesk）；邮箱/社媒/官网渠道用户；非英语主力市场用户

## 4. 怎么解决（3 句话）

1. 基于飞书知识库（120+ 篇）的智能问答 + 三层拒答：有依据才答、没把握主动转人工，不编造。
2. 三大高频场景一步一屏引导排障（Done / It didn't work 两个大按钮），零打字、无死胡同。
3. 转人工零复述（摘要+SN+型号自动交接），配双口径解决率看板、容量预警与知识回流闭环。

## 5. 第一步先做什么（MVP）

> 与企业家确认过的 MVP 边界（详见 PRD详细版 §0）。

- **MVP 先做**: F01 智能问答、F02 引导式排障（三场景）、F03 人机衔接、F04 双层反馈、F06 效果度量与预警、F08 入口与场景化触达；F05 回流机制与 F07 两条零成本预留约束随 MVP 上线但不卡验收；F09 知识库管理台随 MVP 上线、不卡验收（同 F05 待遇，08-04-2026 拍板增补）
- **做完用户能**: 错误提示旁一键 "Get help"、首屏零打字按钮组、一步一屏排障引导、答不准主动转人工且零复述、转人工后知道去哪等回复
- **要验证**: 高频问题自助解决体验能否达及格线——高频类严口径解决率目标 60% / 底线 45%（3 个月）
- **MVP 完成定义**: F01/F02/F03/F04/F06/F08 六项全部达到及格线完成标准（含离线评测集验收通过 + 双口径看板可用）即 MVP 完成
- **先不做（后置）**: 设备状态诊断与自动解决方案（第二阶段王牌）、邮箱/社媒/官网全渠道、Zendesk 客服工作台、完整多语言、语音/无屏交互渠道（接口已预留，零额外开发）、知识库多渠道采集扩展（应用商店/邮件采集进 F09 审核队列；会话提炼与管理台已随 F09 进 MVP）

## 6. 关键功能（六项及格线）

| # | 功能 | 所属阶段 | 解决什么 |
|---|------|---------|---------|
| F01 | 智能问答会话（意图分类先行 + 三层拒答） | 阶段一(MVP) | 答得准、不编造 |
| F02 | 引导式排障（安装/联网/配对，一步一屏） | 阶段一(MVP) | 零打字自助解决装机杀手问题 |
| F03 | 人机衔接（摘要+SN+型号三件套） | 阶段一(MVP) | 转得顺、零复述、出得去门 |
| F04 | 会话反馈（消息级 👍/👎 + 会话级评分） | 阶段一(MVP) | 答错的地方被发现被修正 |
| F06 | 效果度量与预警（双口径、分层、容量预警线） | 阶段一(MVP) | 投入是否值得可验证 |
| F08 | 入口与场景化触达（固定入口 + 错误态 Get help） | 阶段一(MVP) | 找得到门，告别"迷宫"导航 |
| F09 | 知识库管理台——录入/导入、AI 整理与标签、会话提炼审核、发布门禁、效果看板 | 阶段一(MVP) | 知识库唯一权威源，持续答得准、修哪条有数据依据（不卡及格线验收） |

（F05 知识库回流、F07 多语言两条约束、F09 知识库管理台随 MVP 上线，不卡验收，详见 PRD详细版 §0.3）

## 7. 成功长什么样（北极星 + 价值账）

| 指标 | 当前 | 3 个月目标 |
|------|------|-----------|
| 高频类自助解决率（严口径） | 基线待 G1 回填 | 60%（底线 45%） |
| 自助解决时长 | 人工回复 1–2 小时 | ≤10 分钟 |
| 转人工首响 | 现状水平 | 不劣于现状 |

**价值账（拍板 4 已确认口径）**: 中性约 **¥120–130 万/年，两年稳超 ¥200 万**。披露：①省人力与③撑增长基于同一份释放容量，同表相加有重复计算风险，剔除后可复算口径为 ¥99–123 万/年，企业家知晓仍拍板保留原口径；"两年稳超 ¥200 万"以 G1 通过 A-005 检验（退货用户中曾咨询比例 ≥30%）为前提（详见 PRD详细版 §1.2）。

## 8. 交付约束

- 实现方式: Coding Agent
- 人类责任: G1–G4 数据导出与查证、拍板 1/3 决策、运营三岗名单（拍板 2）、LLM 密钥配置、合规前置（DPA/隐私政策）、部署上线
- 关键依赖: LLM API（DPA 且不用于训练为硬条件）；飞书知识库 API；**G1–G4 前置门槛**（并行总窗口 ≤2 周，超期回退规则写死，详见 PRD详细版 §9.10）

## 9. 最大风险（3 个）

1. 🔴 知识库质量不足（A-001 第一命门）→ 拒答率高企、目标击穿 — 缓解: 三场景上线前结构化改造 + 回流闭环 + 评测集命中率 ≥80% 为灰度放量前置条件
2. 🟠 拒答洪水砸向 3 人客服团队 — 缓解: 意图豁免 + 连续拒答 ≤2 + 灰度门禁 + 容量预警线（G1 实测月处理量 ×80%）
3. 🟡 拍板 1 选"升级现有系统"后旧架构落不了地 — 缓解: F01–F08 完成标准为形态无关硬验收，达不成的项逐条摆回企业家桌面重拍，不许静默缩水
