## P4: 一年 ¥120–130 万的价值账，算法与前提全部摊开
> L7-Table

### 视觉/图表设计指令
主体三行价值表；下方"口径披露"灰底框两条；底部金句横幅。

### 页面内容布局

| 视觉/结构区 | 详情/文案区 |
| :--- | :--- |
| **价值账（中性合计约 ¥120–130 万/年，两年稳超 ¥200 万）** | ② 减退货损失：退货率降 3pp 中归功一半 × 10 万台/年 × $50 客单 × 70% 损失率 ≈ **¥75 万**（区间 36–136 万）｜ ③ 撑增长不加人：销量涨 2–3 倍时自助解决 50%+，客服维持 3–4 人、避免新增 4–5 人 ≈ **¥24–48 万** ｜ ① 省现有人力：客服工作量减半 + 技术定位省来回 ≈ **¥12–17 万** |
| **口径披露（与结论同页呈现）** | 1）价值块①与③基于同一份被释放的客服容量，为两种情景下的两种计法，同表相加存在重复计算风险；剔除后可复算中性口径为 ②+③ = ¥99–123 万/年。决策者知晓该风险，仍确认对外保留 ¥120–130 万/年原口径。2）"两年稳超 ¥200 万"为中性情景结论，以数据基线查证通过"退货用户中曾咨询比例 ≥30%"为前提，未通过则重算重述。 |
| **最锋利的一句话** | 差评里一半是"装不上连不上"——这正好是智能客服最能吃掉的问题；退货率每降 1 个点，一年就是 1,000 台不用退。（另有未入账弹性：店铺评分回升对转化的拉动未计入本账） |

## P5: 三条旅程接住用户从卡住到解决的全部去向
> L2-Process

### 视觉/图表设计指令
三条横向泳道流程：旅程 A（自助解决）、旅程 B（转人工兜底）、旅程 C（情绪安抚）；每条泳道末端标注出口；A 泳道加"8 分钟、零打字"标签。

### 页面内容布局

| 视觉/结构区 | 详情/文案区 |
| :--- | :--- |
| **旅程 A · 自助解决（主路径）**：配对失败页一键 Get help → 开场确认 → 一步一屏引导（每步只选 Done / It didn't work）→ 确认解决 → 轻量评分 | 主力用户中老年占比高、打字意愿低，且正处于网络故障中——为此设计：首屏零打字按钮组；切出 App 改路由器设置、24 小时内回来自动恢复到原步骤；示例用户全程 8 分钟、零打字零等待。 |
| **旅程 B · 转人工兜底**：两轮自查失败 → 系统主动给转人工 → 摘要（已试步骤/SN/型号/卡点）可见可补充 → 按真实通路告知回复渠道与预计时间 | 人工客服首条回复直接引用摘要，用户不复述；等待承诺取近期实际响应的滚动值，界面禁止硬编码固定时长、禁止无法兑现的"会通知你"。 |
| **旅程 C · 情绪安抚（退货率的直接来源）**："this thing is garbage, I want a refund" → 不追问技术细节，先共情 → 转人工与退货政策入口置顶常驻 → 用户愿意时再给"最后试一步" | 退款/愤怒词触发为确定性规则，100% 可复现验收；用户气头上时绝不出现"我没把握"式模板话术。 |

## P6: 宁可承认不会，也不编造答案
> L2-Process

### 视觉/图表设计指令
横向判定链流程图：语言检测 → 退款/愤怒词规则 → 意图五分类 → 三道核验 → 回答/转人工；三道核验用竖排三闸门图示；右下角"防跑偏"警示框。

### 页面内容布局

| 视觉/结构区 | 详情/文案区 |
| :--- | :--- |
| **每条消息的判定链**：① 语言检测——非英语直接给双语说明+转人工，不被无声忽略；② 退款/愤怒词规则——命中直入情绪安抚；③ 意图五分类——只有事实性提问进核验，共情/追问/闲聊不误触拒答 | **三道核验（事实性回答专用）**：找不到可靠依据 → 承认不会并给转人工；答案必须有知识出处，回答末尾向用户标注来源（用户看到的来源=系统实际引用的条目）；敏感或超范围 → 说明能力边界并转人工。 |
| **耐心保护**：同一会话连续 2 次答不上 → 直接呈现转人工大按钮，不存在第 3 次"我没把握" | **防跑偏**：高频问题误拒率设上限并入离线评测验收，防止"全拒答刷指标"；情绪会话中触发核验时改用共情式短语+大按钮，不用常规拒答措辞。 |

### 页面内容布局

| 视觉/结构区 | 详情/文案区 |
| :--- | :--- |
| **知识修正流**：拒答/无命中 ＋ 点踩与"没起作用" ＋ 转人工会话 ＋ 48h 复问 → 按频次聚合的周度待补清单（原始问题/命中文档/会话链接/频次）→ 每周消化 Top 10 → 修订 24 小时内生效 → 发版前离线评测回归把关 | 用户的每次不满意都自动变成修正任务：点踩、"It didn't work"、转人工、复问四类信号全部回流，知识缺口按频次排队，不靠人肉巡检。 |

## P8: 行为规格先行——无论重建还是升级，对外表现一致
> L3-Architecture

### 视觉/图表设计指令
三层架构图（知识资产层／对话决策层／数据度量层）+ 右侧竖排"五条演进约束"清单；顶部横幅标注"能力以可观察行为定义，与实现形态解耦"。

### 页面内容布局

| 视觉/结构区 | 详情/文案区 |
| :--- | :--- |
| **知识资产层**：问答条目 + 结构化排障流程（每步两出口，全部路径终点只有"确认解决"或"转人工"，机器自动校验无死胡同）；知识与流程均渠道中立、带语言标记 | "重建 vs 升级现有系统"待查证后决策——全部能力以形态无关的可观察行为定义硬验收，选哪条路都不许缩水；达不成的项逐条摆回决策桌面重拍。 |
| **数据度量层**：数据采集与功能同步交付、同步验收（缺数据的功能不算完成）；离线评测集（真实咨询+差评原话出题，含应拒答、引用不忠实、豁免滥用、怒气样本四类陷阱题），命中率 ≥80% 为放量门禁 | **五条演进约束（零成本现在写，两年后免还债）**：对话核心不绑定 App 来源；数据自带渠道标记；转人工交接 6 字段契约固定（兼作未来 Zendesk 对接底稿）；文案与模板不硬编码语言；界面呈现由适配层映射——未来全渠道/多语言只加适配层，不重写核心。违反任一条按缺陷处理。 |
