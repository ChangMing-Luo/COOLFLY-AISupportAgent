# COOLFLY 知识运营中台 · PRD（重构版 v2.0）

> 生成时间：08-05-2026 17:15
> 定位：**面向 AI 直接生成后台原型**的产品需求文档。旧版 `PRD-界面规格版.md`（v1.0）是对现役实现的 as-is 快照，本文是 **to-be 重设计**——菜单层级、页面骨架、交互范式全部重来。
> 设计基调：**傻瓜式**。用户不需要懂状态机、不需要懂 Zendesk、不需要记流程；系统主动派活，AI 先填人只改，一屏一个主按钮。
> 拍板依据（08-05-2026）：交互范式 = 混合式（收件箱 + 向导 + 看板）；流程 = **固定五步流水线**，不可配置，但每步「谁来做」可指派；角色精简为 3 个 + 单人模式。

## 0. 给 AI 的生成约束（读这一节就能开工）

生成原型时必须遵守，违反即视为不合格：

| # | 约束 | 说明 |
|---|---|---|
| G1 | **一级菜单只有 4 项，禁止出现二级菜单** | 见 §4.1。任何"分组 → 子项"结构都不允许 |
| G2 | **每屏只有一个主按钮（Primary）** | 主按钮文案必须是动词短语，禁止用「保存 / 提交 / 确认 / 下一步」这类无信息量词（向导内的「下一步」除外，且必须带内容提示，如「下一步：补齐信息」） |
| G3 | **禁止渲染 disabled 按钮** | 条件不满足时不画灰按钮，改画「还差 N 件事」清单卡，每条带跳转修复入口 |
| G4 | **界面禁止出现技术术语** | 黑名单：状态机、门禁、drift、乐观锁、同步队列、幂等、locale、payload、schema、API。用 §3.3 术语对照表的中文替换 |
| G5 | **五步进度条是全局强制组件** | 任何展示单个知识条目的地方（卡片、抽屉、详情页、通知）都必须带它 |
| G6 | **非危险动作不弹二次确认** | 直接执行 + 底部「已完成 X，撤销」条（10 秒）。只有 §8 法则 4 列出的 4 个动作弹确认 |
| G7 | **空态必须给出下一步动作** | 禁止只写「暂无数据」，必须是「一句话解释 + 一个主按钮」 |
| G8 | **每页必须画出 4 种状态** | 正常 / 空 / 加载（骨架屏）/ 出错（含重试按钮） |
| G9 | **配色遵循 §5.1 语义色**，不引入第五种强调色 | 绿=已完成、黄=等你处理、红=出问题、蓝紫=AI 产出 |
| G10 | **宽度基线 1440px**，侧栏 220px 固定，内容区最大 1180px 居中；<1024px 侧栏收成图标条 | 移动端只需支持「今日待办」与「审核」两页（§6.7） |

## 1. 产品定位与三条铁律

### 1.1 一句话定位
**COOLFLY 客服知识的唯一生产地。** 知识在这里写、在这里审、在这里翻译、从这里一键上线到 Zendesk 帮助中心，上线后的效果再回流到这里指导下一次修改。

### 1.2 边界（用户会问的三个问题，界面要能自己回答）
| 问题 | 答案（写进界面引导文案） |
|---|---|
| 客户在哪看到这些内容？ | Zendesk 帮助中心 + Zendesk AI 客服机器人。本台负责生产，不负责接客 |
| 工单量、客服人效在哪看？ | Zendesk Explore。本台只看**知识的效果**（有没有被引用、有没有解决问题） |
| 能不能直接在 Zendesk 改文章？ | 能，但不该。改了本台会检测到并提醒你「有人在外面动了这篇」 |

### 1.3 三条铁律（产品硬约束，不可通过任何配置绕开）

| 铁律 | 用户能感知到的表现 |
|---|---|
| **① 都得过审** | 任何内容——手写的、AI 挖的、批量导进来的、从 Zendesk 拉回来的——都必须走「审」这一步才能上线。界面上不存在任何「直接发布」入口 |
| **② 英文必须人看过** | 英文没人点过「校对完成」，「上线」这一步的按钮就不会出现（改为显示「还差：英文没人校对」+ 跳转） |
| **③ 一切留痕** | 谁、什么时候、改了什么、改前改后，全部记下且**任何人不能删**。界面上没有删除日志的入口 |

## 2. 角色与权限（3 + 1）

### 2.1 三个角色

| 角色 | 一句话定位 | 能做 | 不能做 |
|---|---|---|---|
| **编辑**（Editor） | 写知识的人 | 写 / 改 / 建目录 / 处理 AI 建议 / 送审 / 校对英文 | 审核、上线、回滚、下架 |
| **主编**（Publisher） | 把关和上线的人 | 编辑的一切 + 审核 + 上线 + 回滚 + 下架 + 处理 Zendesk 冲突 | 管成员 |
| **管理员**（Admin） | 管人和看账的人 | 管成员 + 看全量留痕 + 看数据 + 系统设置 | 不参与内容审核与上线（可看不可动） |

> 设计取舍：旧版 10 个权限点 × 4 角色的矩阵对用户是纯认知负担。新版**取消权限矩阵界面**，角色写死；成员管理页只需选三选一的角色卡。

### 2.2 单人模式（Solo Mode）
- 场景：团队只有 1–2 人，主编就是编辑本人。
- 开关位置：`运营中心 → 设置 → 团队规模`，选「就我一个人 / 小团队（2–5 人）/ 分工明确（6 人以上）」。
- 选「就我一个人」时：**审这一步不消失，但允许自审**，界面提示「你既是作者也是主编，这次审核会记在留痕里」。**铁律①不破**。
- 选「分工明确」时：可在设置里给「审 / 译 / 发」三步各指派默认负责人，待办自动派到人。

### 2.3 界面权限表现（G4 的补充）
- 不能做的功能**直接不出现在界面上**（不是置灰）。
- 唯一例外：审核相关按钮对编辑显示为**信息条**「这一步等主编 <姓名> 处理，已通知」，让编辑知道卡在哪。

## 3. 核心心智模型：五步流水线

### 3.1 五个字
```
  写  ─────▶  审  ─────▶  译  ─────▶  发  ─────▶  盯
 起草内容    主编把关    英文校对    推上 Zendesk   看效果·到期复核
  编辑        主编        编辑        主编         系统 + 全员
```

- 五步**固定不可配置**，用户只需记住这五个字。
- 每步的「谁来做」可指派（§2.2）。
- **异常不是第六步**，而是贴在卡片上的两枚贴纸：`被退回`（审这一步没过）、`已下架`（发过又撤了）。
- 「盯」这一步是**常驻的**——上线后条目永远处在「盯」，直到被改动重新进入「写」。

### 3.2 五步进度条组件（全局强制，G5）
```
 ①写 ━━●━━ ②审 ────  ③译 ────  ④发 ────  ⑤盯
 └ 已完成    └ 进行中（等主编 王琳 · 已等 2 天）
```
规格：
- 已完成步：实心绿 + `✓`；进行中步：实心蓝紫 + 脉冲点；未开始步：空心灰。
- 进行中步下方一行小字：**「等谁 · 等了多久」**（超过 3 天变黄，超过 7 天变红并自动生成催办待办）。
- 有异常贴纸时，进度条右端追加红/灰贴纸，点击展开原因。
- 组件三种尺寸：`lg`（详情页顶部）/`md`（看板卡片）/`sm`（列表行内，只显示 5 个点）。

### 3.3 术语对照表（G4 强制，界面只准用右列）

| 内部概念 | 界面必须这么说 |
|---|---|
| draft / editing | 写作中 |
| pending_review / reviewing | 等待审核 |
| approved | 审核通过，待上线 |
| published | 已上线 |
| rejected | 被退回 |
| offline | 已下架 |
| en_status = pending_human | 英文待校对 |
| en_status = stale | 中文改过了，英文要重看 |
| en_status = confirmed | 英文已校对 |
| sync_status = queued/running | 正在推送到 Zendesk |
| sync_status = failed | 推送失败（附人话原因 + 重试按钮） |
| sync_status = blocked | 暂时不能推（附「差什么」） |
| 发布门禁 | 上线体检 |
| gate check 未通过 | 还差 N 件事 |
| drift（内容漂移） | 有人在 Zendesk 上改过这篇 |
| 乐观锁冲突 409 | 这篇刚被别人改过，你的改动可能会覆盖他 |
| 语义查重 | 重复检查 |
| 挖掘候选 | AI 发现的新话题 |
| 知识缺口 | 客户在问、我们没写 |
| 复核到期 | 该体检了 |
| 审计日志 | 操作留痕 |
| RBAC / 权限矩阵 | 成员与分工 |

## 5. 设计系统（原型元件库）

### 5.1 语义色（G9，只有 4 种强调色）

| 语义 | 用途 | 建议色值 |
|---|---|---|
| **绿 · 完成** | 已完成步骤、已上线、体检通过 | `#10B981` |
| **黄 · 等你** | 等待处理、快到期、需要注意 | `#F59E0B` |
| **红 · 出问题** | 被退回、推送失败、已过期、效果差 | `#EF4444` |
| **蓝紫 · AI/进行中** | 主按钮、进行中步骤、AI 产出内容 | `#6366F1` |
| 中性灰阶 | 文字/边框/背景 | `#0F172A` → `#F8FAFC` 六档 |

**AI 产出内容统一视觉**：浅蓝紫底 + 左侧 2px 竖线 + 右上角 `✨ AI` 小标，且必须配一个 `采纳` / `我改改` 双按钮。用户一眼分得清「这是机器写的」。

### 5.2 组件清单（原型必须包含）

| 组件 | 说明 |
|---|---|
| `StepBar` | 五步进度条，三尺寸（§3.2） |
| `TaskCard` | 待办卡：图标 + 标题 + 一句话说明 + 一个主按钮 + `稍后` |
| `KnowledgeCard` | 看板卡：标题 + StepBar(md) + 负责人头像 + 停留天数 + 效果小徽章 |
| `AIBlock` | AI 产出块（浅蓝紫 + ✨ + 采纳/我改改） |
| `MissingList` | 「还差 N 件事」清单：每行 = 红叉 + 人话描述 + `去处理 →` |
| `UndoBar` | 底部撤销条（10s 倒计时进度线） |
| `DangerDialog` | 危险确认弹窗：标题 + 后果 3 条 + 输入确认（仅回滚/覆盖需输入条目名）+ 红按钮 |
| `EmptyState` | 插图 + 一句话 + 一个主按钮（G7） |
| `Skeleton` | 骨架屏（列表 5 行 / 卡片 3 张 / 详情三段） |
| `ErrorState` | 「出错了 + 人话原因 + 重试」 |
| `PersonPicker` | 指派人选择（头像 + 姓名 + 当前手上几件活） |
| `DiffView` | 改动对照：左右分栏 + 逐行红绿高亮 + 「只看改动/看全文」切换 |
| `BilingualEditor` | 中英逐段对照编辑器（左中右英，行对齐） |
| `HealthCheck` | 上线体检卡：3 项检查，每项 ✓/✗ + 人话 + 修复入口 |

### 5.3 文案规范

| 场景 | 规则 | 例 |
|---|---|---|
| 主按钮 | 动词 + 宾语，≤6 字 | ✅「送去审核」❌「提交」 |
| 空态 | 「一句话现状 + 一句话建议」 | 「还没有待办 —— 去看看 AI 发现的 12 个新话题？」 |
| 报错 | 「发生了什么 + 你能做什么」，不出现错误码 | 「推送到 Zendesk 失败了：对方服务暂时没响应。可以点重试，或等 5 分钟系统自动再试一次。」 |
| 阻塞 | 「还差什么 + 去哪补」 | 「还差 1 件事：英文还没人校对 → 去校对」 |
| 危险确认 | 后果写具体，不写「此操作不可撤销」这种空话 | 「下架后：客户搜不到这篇了；Zendesk 上会归档不会删；历史和数据都还在；想再上线，改完重新走一遍审核即可。」 |

## 6. 页面规格

#### 6.1.2 区块规格

#### 6.1.3 待办卡（`TaskCard`）统一结构

```

- 处理完成后卡片**原地淡出** + 底部撤销条。

#### 6.1.4 九类待办的生成规则（详见 §9）
等你审 / 被退回 / 英文待校对 / 中文改过英文要重看 / 推送失败 / Zendesk 冲突 / 复核到期 / 效果掉队 / 指派给你的活。

#### 6.3.7 页签「改动历史」
- 时间线卡片，每张：`v3 · 王琳 · 3 天前 · 上线` + 一句话改动摘要（AI 生成，如「补充了退货运费的承担方说明」）+ `看改了什么` / `回到这个版本`（主编）。
- 点 `看改了什么` → DiffView，默认「只看改动」，可切「看全文」。
- 当前版本卡片绿边高亮，标「客户现在看到的就是这版」。
- **效果数据挂在版本上**：卡片右侧显示该版的解决率，跌幅 ≥15pp 时红字「比上一版差了 18%」+ `考虑回到上一版`。

#### 6.3.8 页签「效果」
- 四个大数字卡：被引用次数 / 命中率 / 解决率 / 采纳率，每个带一句人话解释（如「客户问相关问题时，有 78% 的情况找到了这篇」）。
- 样本 <10：整块替换为「刚上线不久，数据还不够，再等等」+ 已积累样本数。
- 解决率 <60%：顶部红条「这篇效果不太好」+ 三条 AI 给的可能原因（内容太长 / 没覆盖客户真正问的 / 标题不好搜）+ `照建议修改`。
- 「客户反馈原声」列表：被踩、客服标记、追问原文摘录（每条带来源渠道）。

#### 6.3.9 审核模式（主编点 `去审核` 后进入）
不是新页面，而是详情页的**审核浮层**：
```
┌── 审核《摄像头离线了怎么办》──────────────────────────────┐
│ 李娜 提交 · 2 小时前 · 这是第 3 版                          │
│ AI 摘要了这次改动：补充了固件升级导致离线的排查步骤          │
│ [只看改动 ▾]  逐行 diff（红删绿增，内部段落带 🔒）           │
│ ─────────────────────────────────────────────────────────  │
│ 上线体检：✓ 信息填全了  ✓ 内部内容标好了  ✗ 英文还没校对    │
│ ─────────────────────────────────────────────────────────  │
│              [通过]        [退回改改]                       │
└─────────────────────────────────────────────────────────────┘
```
- `通过`：直接过 + 撤销条；若体检全绿且我有上线权，通过后**顺手问一句**「要现在就上线吗？」`马上上线` / `待会儿再说`。
- `退回改改`：展开理由输入（**必填**，placeholder 给范例）+ 可选「勾出有问题的段落」（在 diff 上直接圈选，退回后作者能看到高亮）→ 退回后自动生成作者的待办。
- 自审时（单人模式）：顶部一行「这是你自己写的，直接过也行，会记在留痕里」。

│ │ AI 判断：库里没有类似内容（最接近的《太阳能板安装》只有 0.31 相似）│   │
│ │ 客户原话（3 条，展开看全部 ▾）                                   │   │
│ │  · "阴天的时候摄像头两天就没电了，是不是板子坏了"                │   │
│ │  · "太阳能板冬天完全充不进去电"                                  │   │
│ │                                                                  │   │
│ │ ✨ AI 已经起好草稿了（4 段，含排查步骤）        [看看草稿 ▾]      │   │
│ │                                                                  │   │
│ │            [用这个草稿开写]        [不用了]                      │   │
│ └────────────────────────────────────────────────────────────────┘   │
│ ┌────────────────────────────────────────────────────────────────┐   │
│ │ 🔧 该改现有的                                     被踩 8 次      │   │
│ │ 《会员退款政策》可能过时了                                       │   │
│ │ AI 判断：12 通对话里客户提到"7 天"，但文章写的是"15 天"          │   │
│ │            [去改这篇]              [不用了]                      │   │
│ └────────────────────────────────────────────────────────────────┘   │
│ ┌ 🔍 标题不好搜：客户搜「电池」找不到《供电与续航说明》…            ┐  │
│ │            [改个好搜的标题]        [不用了]                       │  │
└──────────────────────────────────────────────────────────────────────┘
```

#### 6.4.2 建议卡三类

| 类型 | 触发来源 | 主按钮 | 采纳后 |
|---|---|---|---|
| 📝 **该写新的** | 对话里高频出现（≥10 次）且库里查不到相似内容 | `用这个草稿开写` | 带 AI 草稿进入 W1 向导第 2 步，来源标记「AI 发现」 |
| 🔧 **该改现有的** | 文章被踩 / 客服标记 / 对话里出现与文章冲突的说法 / 解决率跌破 60% | `去改这篇` | 打开该条目详情并进入「写」，AI 意见以批注形式挂在相关段落旁 |
| 🔍 **标题不好搜** | 帮助中心搜索无结果关键词，但库里其实有对应内容 | `改个好搜的标题` | 打开条目，AI 建议的新标题与「客户会怎么问」预填在侧栏，一键采纳 |

#### 6.4.3 卡片必备三要素（可信度设计）
1. **AI 为什么这么判断**——必须写清依据（被问了多少次、相似度多少、跟哪句话冲突）。
2. **客户原话**——至少 2 条真实摘录，可展开全部，点击可跳 Zendesk 原工单。
3. **一键可用的产物**——不是只给结论，要给草稿/新标题/改动建议，用户点一下就能用。

#### 6.4.4 交互规则
- `不用了` = 直接消失 + 撤销条；**同一话题下次达到阈值会再出现**（卡片底部小字注明，避免用户以为永久删了）。
- 采纳率统计显示在页头（「你采纳了 68% 的建议」），低于 30% 时页头出现一行：「建议不太准？告诉我们哪里不对 →」收集反馈。
- AI 不可用时（模型没配/失败）：**整页顶部诚实告知**——「AI 分析暂时不可用（<原因>），下面是按关键词粗略统计的结果，仅供参考」，不假装正常。
- `重新分析`：手动触发，按钮上标注上次分析时间；执行中显示进度「正在读取 47 通对话… 12/47」。

#### 6.4.5 四态
- 空：「AI 还没发现值得做的事——说明现有知识覆盖得不错 👍」+ 副行「下次分析：今晚 6 点」+ 次按钮 `立即分析`。
- 空（从未跑过）：「还没连上客服对话数据」+ `去设置里连接 Zendesk`（管理员）/「让管理员配置一下」（其他角色）。
- 加载：3 张骨架卡。
- 出错：错误态 + 重试 + 「上次成功的结果（3 天前）」入口。

- 导出 CSV（管理员）。

## 7. 向导规格

### 7.0 向导通用规范

| 规则 | 说明 |
|---|---|
| 形态 | 居中模态 880px（W3 上线向导 640px），遮罩不可点关闭（防误触丢内容） |
| 顶部 | 步骤条（`①说清楚 ─ ②写内容 ─ ③补信息 ─ ④送审`）+ 右上 `×`（关闭时若有内容，问「存成草稿还是丢掉？」） |
| 底部 | 左 `上一步`（文本按钮）/ 右主按钮（**必须带下一步内容**，如 `下一步：写内容`）；最后一步主按钮是终态动词 |
| 随时可退出 | 任何一步都自动存草稿，退出后在「知识资产 › 写」列能找到 |
| 键盘 | `Enter` 下一步、`Esc` 询问退出 |
| 不做的事 | 不在向导里做复杂编辑（正文只做粗稿，精修去详情页）；不在向导里问用户答不上来的问题 |

### 7.1 W1 · 新建知识向导（4 步）

**入口**：`+ 新建知识 → 我自己写 / 让 AI 帮我写`、AI 建议卡 `用这个草稿开写`、目录页 `在这里新建`。

#### 步骤 ① 说清楚要写什么
```
你想写什么？
┌────────────────────────────────────────────────────┐
│ 客户会怎么问这个问题？                              │
│ [ 太阳能板阴天充不满电怎么办                      ] │
│ 💡 用客户的话，别用内部术语。比如写「摄像头没电了」 │
│    而不是「电源模块异常」                          │
└────────────────────────────────────────────────────┘
✨ 检查了一下：库里没有类似内容，可以放心写
   （若有相似）⚠️ 库里已经有《太阳能板安装》和这个有点像 —— 
              [看看那篇] [还是新建一篇] [改那篇就行]

                                    [下一步：写内容 →]
```
- **只问一个问题**，输入即标题。
- 实时**重复检查**（防呆核心）：相似度 ≥0.85 时**不给直接新建**，强制三选一，避免重复建条目。
- 检查不可用时如实说「重复检查暂时用不了，可能会撞车」，不阻塞。

#### 步骤 ② 写内容
```
[✨ 让 AI 先起个草稿]  ← 大按钮，点了 3 秒出草稿
或者直接自己写：
┌────────────────────────────────────────────────────┐
│  富文本编辑器（工具条含 🔒 仅客服可见）             │
│  ✨ AI 草稿会以浅蓝底出现，逐段带 [用这段] [删掉]   │
└────────────────────────────────────────────────────┘
💡 写不下去？试试回答这三个问题：为什么会这样 / 怎么解决 / 什么情况要联系客服
                          [← 上一步]  [下一步：补信息 →]
```
- AI 起草：按标题 + 相似条目 + 客户原话生成 3–5 段，**逐段可采纳可删**，不是一坨全塞。
- 引导问句随条目类型变化（问题排查类 / 政策说明类 / 操作步骤类，由 AI 判断）。
- 空内容不允许进下一步，提示「至少写点什么，哪怕一句话也行」。

#### 步骤 ③ 补信息（AI 全预填）
```
我帮你填好了，看看对不对：
  放在哪    [售后与退款 › 退货政策 ▾]        ✨ AI 建议
  谁能看    ( ) 所有人  (•) 大部分公开，少数内部  ( ) 只有客服
            ↑ AI 发现你有 1 段标了「仅客服可见」，所以选了这个
  客户会怎么问  [太阳能充电慢 ×] [阴天没电 ×] [板子坏了 ×] [+ 加一个]  ✨
  适用型号  [全型号 ▾]        多久体检一次  [180 天 ▾]
                          [← 上一步]  [下一步：送审 →]
```
- **全部预填，用户只做确认**（G3 精神）。每个 AI 填的项带 ✨ 并说明理由。
- 不做必填校验轰炸：缺项时在字段旁一行黄字提示，不拦截；真正拦截发生在「上线体检」。

#### 步骤 ④ 送审
```
准备好了吗？
  ✓ 内容写了 5 段（含 1 段仅客服可见）
  ✓ 信息填全了
  · 英文：送审通过后系统会自动翻译，到时候需要你校对一下

  这篇会交给 [王琳 ▾] 审核，大概 1 天内有结果

     [先存草稿，待会儿再说]        [送去审核]
```
- 展示**清单式确认**，不是空白确认。
- 审核人可改（默认走分工设置）。
- 点 `送去审核` → 关闭向导 → 回到「今日待办」→ 顶部绿条「已送审，等王琳处理」+ 撤销条。

### 7.2 W2 · 批量导入向导（3 步）

| 步 | 内容 |
|---|---|
| ① 把文档给我 | 大拖拽区「把 Word / Markdown / txt 拖进来，或点击选择」+ 「也可以直接粘贴文字」文本域。支持多文件。说明一句：「我会自动按标题切成一篇一篇，一次最多 500 篇」 |
| ② 看看切得对不对 | 左侧切出来的条目列表（可勾选/取消），右侧预览选中条目；每行可改标题、改放哪（**AI 预填目录**）、改谁能看；顶部统计「切出 23 篇 · 其中 4 篇疑似重复 [只看重复]」；重复项默认**不勾选**并标注「库里已有《XX》」 |
| ③ 导进来 | 确认条「23 篇会全部进审核队列，需要人过一遍才会上线」+ 主按钮 `导入 19 篇`（只导勾选的）；执行进度条；结果页：成功清单 + 失败清单（带原因和原文片段）+ `去审核这批` / `再导一批` |

- 导入产物**一律进「审」这一步**（铁律①），结果页明确写出来。
- 失败不影响成功项，逐条报原因。

### 7.3 W3 · 上线向导（3 步，主编）

```
① 体检                    ② 英文确认              ③ 上线
✓ 信息填全了              左中右英对照最终稿       将要发生：
✓ 内部内容标好了          [英文没问题，上线]       · 客户 3 分钟内能搜到
✓ 英文已校对                                       · 中英文各推一篇
  全部通过 ✅                                      · 内部段落不会推出去
                                                   [确认上线]
```
- 若体检有不通过项：向导**停在第 ① 步**，展示 MissingList，每条带 `去处理`；不显示「下一步」。
- 第 ② 步是**最后一道人工闸**（铁律②的界面落点），必须人点一次。
- 第 ③ 步执行后：进度反馈（「正在推送… 中文 ✓ / 英文 推送中」），成功后给 `在 Zendesk 上看看 →` 直达链接。
- 推送失败：不回滚状态，转为待办「推送失败」并给人话原因 + `重试`。

### 7.4 W4 · 定期复核向导（2 步）

**入口**：待办卡「《XX》该体检了」。

| 步 | 内容 |
|---|---|
| ① 还准不准？ | 左：文章正文；右：**AI 体检报告**——「这篇上线 180 天，被引用 234 次，解决率 78%；发现 2 处可能过时：①提到的『15 天退款』与最近 12 通对话里客户说的『7 天』不一致 ②引用的固件版本已经过时」。三个大按钮：`还准，继续用` / `要改，我来改` / `过时了，下架` |
| ② 确认 | 选「还准」→ 复核期重置 180 天 + 留痕，一步完成；选「要改」→ 进详情页「写」；选「下架」→ 危险确认弹窗 |

|---|---|---|
| 1 | **一屏一个主按钮** | 详情页并排「保存/提交/发布/下线」四个按钮 → 只留当前该做的那一个，其余收进 `⋯` |
| 2 | **按钮说人话** | 「提交」→「送去审核」；「同步」→「上线到帮助中心」 |
| 3 | **不给灰按钮，给清单** | 灰掉的「发布」+ tooltip → 「还差 1 件事：英文没人校对 [去校对]」 |
| 4 | **撤销优于确认** | 每个动作都弹确认框 → 直接执行 + 10 秒撤销条。**仅 4 个动作保留确认**：下架、回滚版本、覆盖 Zendesk 上别人的修改、停用成员 |
| 5 | **AI 先填，人只改** | 空白表单 8 个必填 → AI 预填全部，人做确认题；每个 AI 填的项带 ✨ 和填写理由 |
| 6 | **系统主动派活** | 用户自己去各页面巡检 → 9 类事件自动生成待办进收件箱（§9） |
| 7 | **零术语** | 「同步状态：blocked」→「暂时不能推送到 Zendesk：英文还没人校对」 |
| 8 | **进度永远可见** | 用户不知道条目卡在哪 → 五步进度条 + 「等谁 · 等多久」全局强制 |
| 9 | **防呆前置** | 建完才发现重复 → 建之前就查重并强制三选一 |
| 10 | **错误给出路** | 「操作失败」→「推送失败了：Zendesk 暂时没响应。[重试] 或等 5 分钟系统自动再试」 |
| 11 | **默认值能跑** | 让用户先配一堆才能用 → 所有设置都有推荐默认值，不配也能完成全流程 |
| 12 | **诚实标注降级** | AI 挂了却装作正常 → 「AI 分析暂时不可用，下面是粗略统计，仅供参考」 |

## 9. 待办自动生成规则（P1 的数据来源）

| # | 待办 | 触发条件 | 派给谁 | 分区 | 主按钮 |
|---|---|---|---|---|---|
| 1 | 等你审 | 条目进入「审」 | 指定审核人（默认主编） | 📋 | 去审核 |
| 2 | 被退回要改 | 审核退回 | 提交人 | 📋 | 按意见修改 |
| 3 | 英文等你校对 | 翻译完成待人工确认 | 译负责人（默认作者） | 📋 | 去校对 |
| 4 | 中文改了，英文要重看 | 已确认英文的条目中文被改 | 译负责人 | 📋 | 重新校对 |
| 5 | 推送失败 | 自动重试 3 次仍失败 | 主编 | 🔥 | 看看怎么回事 |
| 6 | Zendesk 上被人改了 | 漂移检测命中 | 主编 | 🔥 | 对比一下 |
| 7 | 该体检了 | 距上次上线 ≥ 复核周期 | 条目负责人 | 📋 | 去体检 |
| 8 | 这篇效果不好 | 引用 ≥10 次且解决率 <60%，**每条目每 30 天最多提醒一次** | 条目负责人 | 📋 | 去改改 |
| 9 | 有人指派给你 | 手动指派 | 被指派人 | 📋 | 去处理 |

**防打扰规则**：
- 同类待办合并：3 篇推送失败 = 1 张卡「3 篇文章推送失败」，点开是列表。
- 每人每天新增待办上限 20 条，超出的排队到次日（避免收件箱变垃圾场）。
- 待办 7 天未处理 → 通知其上级/主编（不是继续骚扰本人）。

| 知识资产（看板/列表/目录） | ♻️ 复用 + 🔧 | `/api/kb/entries`、`/api/kb/tree`、`/api/kb/libraries`；需新增「按五步分组」的聚合字段与停留时长 |

| Zendesk 冲突处理 | ♻️ 复用 | `/api/sync/drift*` |
| 推送状态与重试 | ♻️ 复用 | `/api/sync/tasks*`（前端不再单设「同步中心」页，融进待办与详情） |

## 11. 验收清单（AI 生成原型后逐条自检）

### 11.1 结构类
- [ ] 侧栏只有 4 个一级菜单，无二级菜单
- [ ] 每个页面都能在 3 次点击内到达任意功能
- [ ] 五步进度条出现在：待办卡、看板卡、列表行、详情页、通知
- [ ] 全局 `+ 新建知识` 与 `Cmd+K` 在所有页面可用

### 11.2 交互类
- [ ] 全站搜不到 disabled 状态的主按钮
- [ ] 全站主按钮文案都是动词短语，无「提交/确认/保存」裸词
- [ ] 只有 4 处弹二次确认（下架、回滚、覆盖 Zendesk、停用成员）
- [ ] 非危险动作后都有撤销条
- [ ] 每个页面都画了正常/空/加载/出错 4 态
- [ ] 每个空态都有一句解释 + 一个主按钮

### 11.3 文案类
- [ ] 全站不出现术语黑名单（状态机/门禁/drift/锁/队列/API/schema/locale）
- [ ] 所有错误提示都是「发生了什么 + 你能做什么」
- [ ] 所有 AI 产出内容都有 ✨ 标记 + 采纳/我改改

### 11.4 流程类
- [ ] 新用户从登录到发布第一篇，全程不需要看文档
- [ ] 不存在任何绕过「审」这一步的路径（含批量导入、AI 采纳、Zendesk 拉回）
- [ ] 英文未校对时，「上线」入口不出现，只出现「还差什么」
- [ ] 任何时刻用户都能看到条目「在第几步、等谁、等了多久」

### 11.5 埋点（验证傻瓜化是否奏效）

| 指标 | 目标 | 说明 |
|---|---|---|
| 首次发布耗时 | <15 分钟 | 新用户从登录到第一篇上线 |
| 待办处理率 | >80% | 当天生成的待办当天处理掉的比例 |
| 向导完成率 | >70% | 进入 W1 到点「送去审核」 |
| AI 建议采纳率 | >40% | 反映建议质量 |
| AI 预填修改率 | <30% | 改得越少说明 AI 填得越准 |
| 帮助气泡打开率 | <15% | 打开得多 = 界面不够自明 |
| 「稍后」使用率 | <25% | 高说明派活不准 |

## 12. 非目标（明确不做，防止 AI 发挥过度）

| 不做 | 原因 |
|---|---|

| 深色模式 | 本期不做 |

## 13. 与旧版（v1.0）的主要差异

| 维度 | 旧版 | 新版 |
|---|---|---|
| 菜单 | 5 组 10 项，含二级 | **4 项，无二级** |
| 心智模型 | 8 个条目状态 + 7 个英文状态 + 7 个同步状态，共 22 个概念 | **5 个字 + 2 张贴纸** |
| 首页 | 我的工作台（4 个分组页签） | **今日待办**（系统派活，做完即空） |
| 新建 | 一次性大表单（11 个字段） | **4 步向导**，AI 预填，用户只填 1 个问题 |
| 字段 | 条目类型/场景一级/场景二级/标签 4 个分类字段 | 合并为 **「客户会怎么问」** 1 个 |
| 发布 | 门禁三查 + 禁用按钮 + tooltip | **上线向导** + 「还差 N 件事」可跳转清单 |
| AI 能力 | 分散在挖掘/缺口/反馈 3 个页面 | **合流为「AI 建议」1 页 3 类卡** |
| 同步中心 | 独立页面（任务队列 + drift + 映射表） | **拆解融入待办与详情**，用户不需要理解队列 |
| 角色 | 4 角色 × 10 权限矩阵 | **3 角色 + 单人模式**，无矩阵界面 |
| 确认弹窗 | 8 处二次确认 | **4 处**，其余撤销条 |
| 移动端 | 无 | **待办 + 审核两页** |
| 文案 | 大量技术术语（门禁/drift/状态机） | **零术语**，术语对照表强制 |
